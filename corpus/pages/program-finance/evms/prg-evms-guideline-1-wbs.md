## Purpose

Sets out what the guide requires when a contractor defines the work breakdown structure for a program, and what that structure contains.

## The rule

| Field | Value |
|---|---|
| Instrument | DoD EVMS Interpretation Guide, not a codified instrument [@CL-PRG-0151] |
| Codified citation | Not established. |
| RFO citation | Not established. |
| Edition date | Not established. |
| Text status | Not established. |
| Applies to | Programs for which the contractor must define the authorized work elements [@CL-PRG-0152] |

The guideline asks the contractor to define the authorized work elements for the program and treats a product-oriented structure, tailored for effective internal management control, as the common way to do it [@CL-PRG-0152]. The structure is a product-oriented, hierarchical breakdown of the program requirements [@CL-PRG-0153]. It includes all program elements, such as hardware, software, services, data or facilities, and it is decomposed to lower levels for planning, budgeting, scheduling, cost accounting, work authorization, progress measurement and management control [@CL-PRG-0560].

The work breakdown structure must also include all subcontracted work scope [@CL-PRG-0154]. In all cases, the contractor must extend the contract work breakdown structure to a level needed for effective internal management control, and this should not be an arbitrary level established across the program [@CL-PRG-0155]. A single product-oriented work breakdown structure is used for a given contract and extends to the level necessary for management action, comprising all contract work scope, including subcontracted and intercompany scope, to levels needed for effective internal management control [@CL-PRG-0157].

## How it works

A single product-oriented work breakdown structure is used for a given contract and extends to the level necessary for management action, comprising all contract work scope, including subcontracted and intercompany scope, to levels needed for effective internal management control [@CL-PRG-0157]. Using a product-oriented work breakdown structure facilitates data collection and traceability and provides a control framework for integrated program management, work authorization, tracking, and reporting purposes [@CL-PRG-0561]. In all cases, the contractor must extend the contract work breakdown structure to a level needed for effective internal management control, and this should not be an arbitrary level established across the program [@CL-PRG-0155].

## Worked example

Synthetic example. The numbers are made up.

A program breaks its scope into 3 product levels and ends with 12 elements at the level where managers authorize work, each carrying hardware, software and data, plus 4 subcontracted elements. The answer is that the structure can be used, because every piece of contract scope, subcontracted work included, appears in it and the depth follows management need.

## Never confuse

The work breakdown structure is a product-oriented, hierarchical breakdown of the program requirements [@CL-PRG-0153], while the program organizational structure, including the major subcontractors, is responsible for accomplishing the authorized work and defines the organizational elements where work will be planned and controlled, and integrating the program work breakdown structure and organizational structure identifies management control points where responsibility is assigned to specific work scope [@CL-PRG-0159; @CL-PRG-0166]. For management control purposes, there may be one or more responsible organizations supporting a single work breakdown structure element or multiple control accounts within one organizational breakdown structure element driven by scope and exit criteria (i.e., completion of the effort) [@CL-PRG-0170; @CL-PRG-0072]. Cost collection requirements, such as Cost and Software Data Reporting (CSDR), may require a different reporting structure other than the work breakdown structure used in the Earned Value Management System (EVMS) for program management [@CL-PRG-0156].

## Company calibration

Whether the company's programs extend the work breakdown structure to the depth their earned value requirement needs, and whether that structure is the one the validated system uses [@CL-PRG-0155; @Q-037]
