## Purpose

Shows what the guide expects when the scheduling, budgeting, work authorization and cost accumulation processes have to work as one framework for program management.

## The rule

| Field | Value |
|---|---|
| Instrument | DoD EVMS Interpretation Guide, not a codified instrument [@CL-PRG-0173] |
| Codified citation | Not established. |
| RFO citation | Not established. |
| Edition date | Not established. |
| Text status | Not established. |
| Applies to | Programs whose management processes must be integrated with each other [@CL-PRG-0174] |

The guideline asks the contractor to provide for the integration of the scheduling, budgeting, work authorization and cost accumulation processes with each other and, as appropriate, with the work and organizational structures [@CL-PRG-0174]. The guide says integrating planning, scheduling, budgeting, work authorization and cost accumulation management processes provides the capability to establish the performance measurement baseline, identify work progress and collect actual costs [@CL-PRG-0175].

Integration runs through coding structures that use unique identifiers and common data elements, or a simple mapping method [@CL-PRG-0176]. The earned value system must also integrate subcontractor data [@CL-PRG-0177]. Those subsystems are joined by one common and unique coding structure across all levels of the work structure and the organizational structure [@CL-PRG-0178].

## How it works

The guideline names the processes that have to be integrated with each other: scheduling, budgeting, work authorization and cost accumulation [@CL-PRG-0174]. Unique identifiers and common data elements, or a simple mapping method, integrate the processes [@CL-PRG-0176]. The unique coding allows data from one system to relate to and be consistent with the data of the other systems [@CL-PRG-0562]. The integration provides the capability to establish the baseline, identify work progress and collect actual costs [@CL-PRG-0175]. Subcontractor data sits inside that boundary as well [@CL-PRG-0177].

## Worked example

Synthetic example. The numbers are made up.

A company runs 4 separate systems for planning, scheduling, budgeting and cost collection, and one shared charge number ties them together. A cost posted against that charge number shows the same work element and the same organization in every system. The answer is that the processes are integrated through the shared code, so progress and actual cost can be compared without rebuilding the data by hand.

## Never confuse

Integrating the processes is not the same as replacing the systems with one product, because the guideline accepts shared codes or a simple mapping between separate systems [@CL-PRG-0176]. The boundary is also wider than the work structure alone, since the organizational structure and subcontractor data are inside it [@CL-PRG-0178; @CL-PRG-0177]. Integration is also not limited to the top of the structures, because the common coding structure covers all levels of the contract work breakdown structure and the organizational structure [@CL-PRG-0178].

## Company calibration

Whether the coding structure that links planning, scheduling, budgeting, work authorization and cost accumulation is the same one used to reconcile program forecasts to accounting and reporting [@CL-PRG-0176; @Q-010]
