## Purpose

Shows how the guide expects baseline changes to be controlled so that performance data stays accurate and reliable.

The objective of the four Revisions and Data Maintenance guidelines, guidelines 24 through 27, is to establish the requirements for a formal change control process that preserves the integrity of the baseline and the earned value data [@CL-PRG-0645]. Because the baseline is the agreed-upon plan between contractor and government, any changes to it are formally controlled and properly documented using a systematic approach [@CL-PRG-0646].

The baseline must reflect all authorized work scope, so authorized contractual changes go into budgets, schedules, work authorizations and other program documents in a timely manner before that work starts [@CL-PRG-0647]; see [the customer-directed changes guideline](prg-evms-guideline-24-customer-directed-changes.md). Retroactive changes to performance data are controlled and limited to only certain circumstances [@CL-PRG-0648]; see [the retroactive changes guideline](prg-evms-guideline-26-retroactive-changes.md). Authorized baseline revisions are documented, managed, tracked and reported to the program manager and the government in a timely manner [@CL-PRG-0649].

## How it works

This page is the overview of guidelines 24 through 27: a formal change control process protects the baseline [@CL-PRG-0645], and every authorized revision is documented and reported [@CL-PRG-0649]. The guideline pages hold the rules for each kind of change.

## Worked example

Synthetic example. The numbers are made up.

The government adds scope worth 600,000 to a contract. The company puts the new scope into budgets, schedules and work authorizations before the work starts. It logs the change, tracks it and reports it to the program manager and the customer. The answer: the baseline is revised before the work, and the change is on record.

## Never confuse

A revision that brings in authorized scope is not the same as a retroactive change to performance data [@CL-PRG-0647; @CL-PRG-0648]. For the retroactive case, see [the retroactive changes guideline](prg-evms-guideline-26-retroactive-changes.md).
