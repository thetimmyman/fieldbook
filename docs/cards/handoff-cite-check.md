# handoff-cite-check

- **Runs where:** home, CI Linux
- **Schema impact:** none
- **Review:** auto

## Outcome

`fieldbook cite-check <file|-> [--json]` reads an answer and reports, for each citation, one of the nine statuses in [Citation checks](../reference/citation-check.md#status-and-exit), flags uncited sentences, accepts the abstention phrase, and exits 1 when any citation does not resolve or nothing verifies. `assist::cite_check(view, answer, context)` is the same engine for `ask --resume`, the Bridge and the `mcp` tool; the plain command has no context and never gives `outside context`. The lead's 20 seed cases in `tests/golden/handoff/` pass in Rust and are the vectors that `assistant-page` holds the JavaScript port to.

## Why

- The statuses, their precedence and the exit rules are in [AD-18](../decisions/0001-foundation.md#ad-18-security-and-confidentiality-guardrails) (cite-check statuses) and the codes FB0701 to FB0707 are in [07: Handoff](../reference/corpus-format.md#07-handoff). The reader is the tolerant mode of the one lexer ([Syntax at a glance](../reference/corpus-format.md#syntax-at-a-glance)). The words come from `strings`: `cite_statuses`, `refusal`, `abstention`.
- `outside context` is a result and not a diagnostic: it has no code, it is never counted as verified, and it does not by itself make the command exit 1. A reference that is outside both the Corpus and the context is `broken`, because the first status that applies wins. Only a check that is given a context can say it: the Assistant page, `ask --resume` and the Bridge. This is the decision of AD-18 and of [HANDOFF.md](../design/HANDOFF.md) §9 Cite-check.
- Control HG-05 in [controls.md](../controls.md) (the statuses, the exit code, the count line and the refusal line) and HG-06 (an AI note never supports a claim; a note is `weak`). "Resolves" means the applicable reference, locator and direct quotation checks passed; this does not judge a paraphrase or the answer's correctness.
- One engine, two readers. `assist.js` mirrors this function and the Rust code is the reference; shared goldens hold them together, and `cite_check`, the sentence splitter and the printer are pure so the harness can run the same cases.
- Types are defined once. `CiteStatus` and `CiteVerdict` live in `assist`; `ports/chat.rs` re-exports them for the Bridge's `AnswerCard`.
- Design: the [MAP.md](../design/MAP.md) rows for the Ask drawer (VerdictChips, CiteCheckChip) and `#assistant` (CheckedAnswer, VerdictChips) take their statuses from this engine, and CommandChip gains the `cite-check` verb. [HANDOFF.md](../design/HANDOFF.md) §9 Cite-check and §7 Status display rules. Token groups: none; this card builds no page.

## Steps

1. `assist/cite_check.rs`: `CiteStatus { Broken, BrokenLocator, OutsideContext, Superseded, Weak, UncheckedLocator, UncheckedQuote, QuoteMismatch, Verified }` (serde snake_case: `broken`, `broken_locator`, `outside_context`, `superseded`, `weak`, `unchecked_locator`, `unchecked_quote`, `quote_mismatch`, `verified`), `CiteVerdict { reference, status, source_exists, locator: FactVerdict, quote: FactVerdict }`, where FactVerdict is NotApplicable, Verified, Unchecked or Mismatch, `CiteLine { verdict, code, excerpt, non_canonical }` and `CiteReport { lines, neutral, uncited, abstentions, unresolved, total }`. `CiteReport::nothing_verifies(&self) -> bool` exposes the single derived predicate of step 3 from the engine's immutable sentence/citation classification; every caller uses that method. Retain the private facts needed to distinguish an answer made only of abstentions; citation counts alone are insufficient. Do not expose an independent mutable public boolean. Text, JSON and exit decisions share this predicate; the separate JSON report keeps its existing `verdict` shape. `cite_check(view, answer, context: Option<&ContextIds>) -> CiteReport` reads the answer with `cite::lexer` in `Mode::Tolerant` and takes, for each citation, the first status that applies: `broken` (the id is unreadable or is not in the view), `broken_locator` (`quote::locator_resolves(extraction, locator)` returns `Err` for the version's extraction; `check_facts` decides it over the facts of step 1a), `outside_context` (only when `context` is `Some`, the id exists and is not in it), `superseded` (a superseded version or claim), `weak` (Tier D, an AI note, or a claim that is unchecked, unresolved or contradicted) then `unchecked_locator` for unavailable locator facts, `unchecked_quote` for missing quotation text, `quote_mismatch` for a checked quotation mismatch, and `verified` only when every applicable fact was checked and matched. A question or conflict reference is neutral and appears only in `neutral`. A recognisable form that is not canonical sets `non_canonical`. `code` is the primary code of the precedence verdict: FB0701 for `broken`, FB0702 for `broken_locator`, FB0703 for `superseded` and FB0704 for `weak`, and none for the others. `non_canonical` is independent of that verdict: a recognisable noncanonical form sets it true and it carries the FB0706 warning on its own, so one citation may hold a primary `code` and `non_canonical = true` at the same time, and the shared text printer and the browser display show both diagnostics rather than one replacing the other. `unresolved` counts each citation once when its id is broken or either applicable locator or quote fact is Unchecked or Mismatch, including under a higher-precedence display status; a noncanonical form does not add to it twice or change the exit code; `total` counts the citations that are not neutral. The answer-only `[@<area>-note-<nnn>]` form is read by the same tolerant lexer: an absent id is `broken`; a visible id outside supplied `ContextIds` is `outside_context`; a visible in-context id (or one checked without a context) is `weak`, without Corpus citation resolution; the strict reader still rejects the form with FB0300.
1a. `assist::cite_facts(view) -> Vec<CiteFact>` with `CiteFact { id, kind, superseded, weak, locators: LocatorFacts, evidence: Option<EvidenceRef> }`, sorted by id, no text: `kind` is the unit kind and includes `question` and `conflict` for the ids that the check treats as neutral; `superseded` and `weak` are the two predicates of step 1 (Tier D, an AI note, or a claim that is unchecked, unresolved or contradicted, for `weak`); `locators` is `LocatorFacts { available: bool, pages: u32, labels: Vec<String>, tables: Vec<TableFact> }` with `TableFact { sheet: Option<String>, rows: u32, columns: Option<u32> }`; for a source version they hold what `quote::locator_resolves` reads (all empty for any other kind): `available` is false when extraction metadata is absent; no bounds check then claims a known invalid locator. With metadata present, `pages` is `page_count` and `labels` the sorted keys of `[locators]`. `tables` is empty unless the extraction method is `csv-rows` (one entry with `sheet` `None`, `rows` = `row_count` and `columns` `None`) or `xlsx-sheets` (one entry for each `[sheets."NAME"]`, sorted by name, with its `rows` and `columns`); `extract-csv-rows` and `extract-xlsx-sheets` fill it. With tables empty, a sheet or rec locator is Unchecked, never Verified; structural check may defer it but answer verification cannot claim it was checked. `cite_check(view, answer, context)` calls `check_facts(&cite_facts(view), &ViewEvidence::new(view), answer, context)`. Use the complete-locator text from the provider as one bounded page when calling `quote::find` (`within = 1..=1`); absent coverage remains Unchecked. Implement the pure `EvidenceText` provider and `EvidenceRef` mapping in [Facts and evidence](../reference/citation-check.md#facts-and-evidence); `CiteFact` still contains no source text. Resolve a claim's source reference before looking up text; never search unrelated text for a quote. `check_facts` tests `p. N` (both ends of a `pp.` range) against `pages`, a label against `labels` and, when `tables` is not empty, `rec N` against `rows` (`rec NAME!N` against the entry named `NAME`, the name read with its three escapes) and `sheet NAME!range` against that entry (its last row at most `rows + 1`, its last column at most `columns`). It is the function that `assist.js` ports, so the facts the Assistant page receives in `assist-data.js` and the facts the engine uses are one list, and the locator test of the port is written once. Tests: `cite_facts_cover_every_id_the_engine_can_resolve`, `cite_facts_hold_no_unit_text`, `check_facts_gives_the_same_report_as_cite_check` and `cite_facts_cover_rec_and_sheet_locators` (in `tests/cite_check.rs`, over hand-built facts: for a table of 3 rows `rec 3` resolves and `rec 4` is `broken_locator`; for a `Rates` sheet of 120 rows and 6 columns `sheet Rates!A1:F121` resolves and `sheet Rates!A1:G2` is `broken_locator`; with tables empty rec 99999 is unchecked_locator).
2. `assist/sentences.rs`: `split(answer) -> Vec<Sentence>`, pure. A sentence ends at `.`, `!` or `?` followed by white space or the end, or at a blank line or a list marker at the start of a line. A full stop inside a citation bracket, after `p`, `pp`, `sec` or `no`, or between digits is not an end [J]. Headings and empty lines are not sentences. A sentence with no citation and not an abstention is `uncited` (FB0705). A sentence that contains the abstention phrase of `strings`, in any case, with or without the final full stop, is an abstention and is allowed.
3. The verdict: `nothing_verifies` is true when the answer has no `verified` citation and is not made only of abstentions; it raises FB0707 and the refusal line. The exit code is 1 when `unresolved` is above 0 or `nothing_verifies`, else 0. An `outside_context`, `superseded`, `weak` or uncited finding does not by itself change the exit code.
4. `assist/render.rs`: `CiteReport::to_text()`, the one printer, used by the command and by `ask`. One line per citation, in reading order, with the status word from `strings::cite_statuses`, the reference as written, the primary code if any, `non-canonical` when the flag is set (with its FB0706 warning shown even when a primary code is present, so both appear on that line), and for a verified citation the line `Citation resolves at this locator.` and the excerpt from `EvidenceText` cut at 200 Unicode scalar characters. Then one line per uncited sentence (`uncited: <first 80 characters>`), then `N of M citations do not resolve` when `unresolved` is above 0, then `Do not use this answer.` when nothing verifies. Text only: the answer is printed as text and never run, opened or turned into a command.
5. A quotation of six words or more directly before a citation is checked with the shared matcher. A checked mismatch sets quote = Mismatch and, unless a higher-precedence status applies, status = QuoteMismatch; it counts unresolved and exits 1. Missing locator or quotation facts set that fact to Unchecked and prevent Verified; cite-check reports unresolved and exits 1. Source existence alone never verifies a row, cell, page or quotation. FactVerdict fields keep these facts distinct even when a higher-precedence status applies. The fact detail carries the reason; FB0702 keeps its invalid-locator meaning and FB0705 remains uncited-sentence only. A new fact status need not invent a check code.
6. `cite_check.rs` in the binary: `cite-check <file|->` reads the file or standard input as UTF-8 (at most 1 MiB; an empty or larger input is exit 2), loads the Corpus, builds the `LabelledView` from the `Allowed` token that `egress::check` mints for the `handoff` destination (a denial is exit 2 with its code; the command only reads and sends nothing), and calls the engine with `None`. `--json` prints the report of step 7 in place of the text. The command writes nothing and has no journal event.
7. `CiteCheckReport` in `report.rs`: `{ "report_version": 1, "verb": "cite-check", "citations": [ { reference, status, source_exists, locator, quote, code?, excerpt?, non_canonical } ], "neutral": [reference], "uncited": [text], "abstentions": N, "unresolved": N, "total": M, "verdict": "ok" | "unresolved" | "refused" }`, where `refused` means nothing verifies. Follow Adding a JSON report: add `tests/golden/json/cite-check.json` and the row in `json_reports.rs`. Add the `cite-check` row to the `ENTRIES` table in `tests/deterministic_verbs.rs`, like the rows already there. Remove `cite-check` from `PENDING` in `tests/chips.rs`. Run `cargo xtask docs` and commit `cli.md`. Register its case in `tests/support/chip_cases.rs` (a fixture reply file on a fresh Home copy, the verdict's exit code).
8. Two synthetic answers for the acceptance run, marked synthetic: `answer-mixed.txt` holds one citation of a claim of `corpus-mini` with a locator that resolves (read the id and the locator from the fixture) and one citation of `CL-CMP-9999`; `answer-abstains.txt` holds only the abstention phrase.
9. Tests in `tests/golden_handoff.rs` (each file of `tests/golden/handoff/` is included with `include_str!`; the loader refuses an unknown key): `seed_cases_pass` (all 20, reporting every failing id), `every_code_from_fb0701_to_fb0707_has_a_seed_case`. In `tests/cite_check.rs`: `precedence_runs_broken_locator_outside_superseded_weak_verified`, `cite_check_and_check_share_one_locator_test` (a `p.` beyond `page_count` of a `corpus-mini` version is `broken_locator` in `cite_check` and FB0304 in `match_claim`, and the last page resolves in both), `a_reference_outside_the_corpus_and_the_context_is_broken`, `without_a_context_outside_context_is_never_given`, `outside_context_is_not_unresolved_and_not_verified`, `question_and_conflict_references_are_neutral`, `uncited_sentences_are_flagged`, `the_abstention_phrase_is_allowed_in_any_case_with_or_without_the_full_stop`, `tolerant_forms_are_flagged_non_canonical` (a missing `@`, a missing comma, Unicode dashes, `p.14`, `§15.404-1`; one case is a broken noncanonical citation that holds `code = "FB0701"` and `non_canonical = true`, and the text printer and the JSON report both show the FB0701 diagnostic and the FB0706 warning), `an_ai_note_is_weak`, `one_verified_citation_lifts_the_refusal`, `an_answer_of_only_abstentions_exits_0`, `nothing_verifies_is_fb0707_and_exit_1`, `sentence_splitting_keeps_locators_whole`, `cite_check_never_panics_on_random_and_mutated_answers` (the file includes the generator with `#[path = "../../../tests/support/rng.rs"] mod rng;`, builds 200 byte strings of length 0 to 192 from `Rng::new(1)`, and takes `answer-mixed.txt` and `answer-abstains.txt` with each byte flipped once and deleted once, through `String::from_utf8_lossy` into `split` and `cite_check` on `corpus-mini`, with `None` and with a context; the result is a report, never a panic). ## Negative control

On the branch, swap `broken_locator` and `outside_context` in the precedence of step 1: `precedence_runs_broken_locator_outside_superseded_weak_verified` and a seed case must fail. Restore it. Make the plain command pass an empty context instead of `None`: `without_a_context_outside_context_is_never_given` must fail. Restore it. Make `nothing_verifies` ignore abstentions: `an_answer_of_only_abstentions_exits_0` must fail. Restore it. Build the view when the state is Closed: `a_closed_policy_is_fb0413_and_prints_no_report` must fail. Restore it. Index the first byte of the answer in `split` without a length check: `cite_check_never_panics_on_random_and_mutated_answers` must fail. Restore it. Make `check_facts` accept a page one past `pages`: `cite_check_and_check_share_one_locator_test` must fail. Restore it. Make `check_facts` ignore `tables`: `cite_facts_cover_rec_and_sheet_locators` must fail.

Treat absent facts as valid or leave a quote mismatch Verified: the matching vector must fail in Rust and the browser. Restore each.

Treat an answer-only note reference as a Corpus citation or as verified: the note vector must fail in Rust and the browser. Restore it.

Return a match from metadata alone, or use truncated text as a complete locator: the missing-text and truncated-coverage vectors must fail. Hide unresolved quote facts behind a higher-precedence status: that vector must fail. Restore each.

## Rollback

Revert the merge commit. The command, `assist::cite_check` and the printer go, `cli.md` regenerates, and the seed files stay. A card that calls `cite_check` (`model-handoff-ask`, `chat-bridge`, `mcp-server`) fails to build until it is reverted too, so revert in reverse order.

## BLOCKED

Fewer than 20 seed cases are in the tree, a seed expects a status that AD-18 does not give, the corpus-mini fixture lacks a unit a seed needs (a superseded version, a Tier-D source, an unchecked claim: the lead adds it first), or `quote::locator_resolves` cannot say whether a locator resolves for some kind of source. Write the seed or the unit and stop.
