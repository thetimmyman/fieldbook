# r2-company-ids

- **Runs where:** home, CI Linux, CI Windows
- **Schema impact:** none
- **Review:** owner

## Outcome

A company store has ids that no public id can equal, a writer that is part of every id, a guard against two stores issuing the same id, and a search that reads it. `ids::next_company` allocates `SO-000042`, `CL-XES-000012`, `QO-000003`, `XO-000002` and `CM-000012` for a family and a writer from that family's rows only. `fieldbook init --overlay [--writer N]` writes `store.toml` (`store_uid` and `writer`) and marks the store folder not content-indexed; `restore --to` stamps `restored_from` into the restored `store.toml`, `init --overlay --adopt` clears it, and until it does no id is allocated (FB0836). The writer reaches `journal.open`, the proposals and the allocator. `check` raises FB0416 for a company shape in a public file, FB0417 for a public shape defined in a company register, and FB0420 for a store folder without the not-indexed mark. `fieldbook search` builds one in-memory index over every store the actor may read, with `--store`, the labels beside each result and the text of a company document searchable by window. `build --overlay` writes the overlay site and its index on demand into `state\site\overlay\`, inside its own budget, and not for a store whose row names `readers`. `ask-promote` gets its `gap_question` arm for the company store. The citation lexer reads a company key, and a new golden file pins it. A text window says in its title when its table was saved from a workbook, and every company-store fixture, `laptop-mini` among them, takes its date from one file, `tests/fixtures/COMPANY_TODAY`.

## Why

- The company store and the edition merge in one index, so one id must never name two documents. The decision is by shape, made once ([ADR 0004, section 10](../../decisions/0004-company-boundary.md#10-identity)): public ids keep four digits, company ids have six to ten, and the writer digits come first, so two writers cannot hand out the same number. The failure it prevents: a citation `[@S-0042-v1]` that is valid in two stores and quotes the wrong document.
- One const table, not a service. A shape rule needs no allocator, and a new family is a row ([Adding an id family](../README.md#adding-an-id-family)). Allocation reads only the rows of one family and one writer, so a restored store keeps counting from its own last number.
- The writer lives in `store.toml` with the data, so a restore keeps it, and `later-second-device` can hand out a second index without a format change. A restore keeps it too far: restoring onto a new laptop while the old one still runs would give two stores with the same writer, and both would issue `SO-000043`. Ids are never reused or renamed, so that cannot be repaired afterwards. So `restore --to` stamps `restored_from`, and the allocator refuses (FB0836) until `init --overlay --adopt` says the old machine is retired or gives this store a new writer. The failure it prevents is two stores that disagree about what `SO-000043` is.
- The index is one index over all stores, with one idf, because two indexes merged afterwards would rank the same term differently in each ([search.md](../../reference/search.md#the-company-index)). Search is never cut: every label a store holds is searchable here by a person who may read that store, and what leaves is cut by the view of each destination, not by the index. A store whose row names `readers` is not opened for a person outside that group, so nothing from it enters the index (ITS6).
- Existence is metadata. This card prints a label beside a result on the owner's screen, which is not egress, and puts no label or title in an error.
- The overlay site and its index are a second copy of company text. So they are built on demand into `state\site\overlay\`, never inside the store, never for a `readers` store, never copied by backup, and `clean --site` removes them. A copy that sits beside the store on every build would outlive a purge and travel with every backup.
- Design: the company search loader follows the Search and Skeleton rows of [MAP.md](../../design/MAP.md#routes-and-components), and index loading in [HANDOFF.md §10](../../design/HANDOFF.md#10-search) and [§11](../../design/HANDOFF.md#11-edge-cases). It reuses the existing Skeleton and search tokens; no new page layout is built here. The record-type page `r/<type>.html` belongs to `later-record-views`; until then record search rows have no link.
- A figure read from a CSV that was saved from a workbook can be wrong where nobody looks: the file holds what the screen showed, with no formula behind it, and a manual-calculation setting or a stale cached cell can have left a number on display that the workbook would not recompute (R-13). The text of such a version says so in its title, and a search result and the export of `handoff-context` carry that title, so no reader meets the figure without the warning. A workbook that is read directly has the same risk and says so in the `flags` of its extraction, and its title carries those sentences in the same way. `extract-csv-rows` owns the key and its sentence and `extract-xlsx-sheets` the flags and theirs; this card only reads them, through `window_label`. The failure it prevents: a quoted price is trusted as if a formula stood behind it.
- Every `check` over a company-store fixture needs a date, and a store root cannot hold an extra file (FB0121), so the date sits beside the fixtures in `COMPANY_TODAY` and one test fails when a fixture is not clean at it. The failure it prevents: a fixture that is green on the day it is written and red when a `review_by` passes, with the cause far from the date.

3. The store file, `init --overlay` and the guard. `store_toml.rs` (`StoreToml`, `parse`, `render`) and `World::fresh_uid` are built by `r2-state-and-journal` (its step 3b), and this card writes the file through them. `fieldbook init --overlay [--writer N]` (the verb `r2-overlay` made) writes `store.toml` with `StoreToml::render` first, then the folders and registers it already writes; `--writer` outside 0 to 9999 is a usage error (exit 2) before any file is written; a folder that already holds files is still refused. `init --overlay --adopt (--retired | --writer N)` is the one verb that opens an existing store: it refuses a store whose `store.toml` has no `restored_from`, removes `restored_from`, keeps the writer for `--retired` or sets the new one for `--writer N` (so ids already issued by the old writer are never reissued: the new writer's rows start at 000001 in its own series), and appends one `store.adopted` event with the unchanged `store_uid`, `mode = retired` or `writer` for the selected option, and the resulting writer, journal first.
