# ai-drill

- **Runs where:** home, CI Linux
- **Schema impact:** none
- **Review:** auto

## Outcome

`cargo xtask ai-drill` is one scripted run of the built `fieldbook` binary on a copy of the fixture Corpus, in temporary state folders, with no real network. It prints one line per step: `PASS`, `FAIL` with the reason, or `NOT BUILT` with the card that owns the step. It exits 1 on any `FAIL`, and a step whose card has not merged is listed and never counted as passed. The steps that this card can run are written here: the Handoff round trip, a refused label, a journal that refuses appends, the deterministic verbs after the AI steps, the search for a synthetic key and prompt, a folder through `add --propose`, an accept without a terminal, an accept at a terminal, and a clean `audit verify` at the end. CI runs it, and its report is a file.

## Why

- The Day-30 claim is one claim: the AI work and the intake work behave as the [gate](../../decisions/0001-foundation.md#gates) says, end to end, and every accepted proposal is in the journal. One drill that a person can run and read is cheaper to keep honest than a list of separate tests, and the unit tests of each card stay where they are.
- A step is never passed because its card is missing. The plan of steps is data in this card, and a step with no function prints `NOT BUILT` and the owning card, so a Day-30 gate that cut the endpoint adapter or `mcp-server` (the cut order in [Cut line and floor](../../decisions/0001-foundation.md#cut-line-and-floor)) says so in its record instead of looking complete.
- The steps run the real binary and read the real journal. The drill proves what the journal holds after a run; it does not trust the output text alone. The accept step uses a pseudo-terminal, so the terminal check of `queue accept` is exercised and never bypassed.
- Each later card adds its step as one new file and one registration line, so cards in flight do not edit the same file. This card owns the plan, the runner and the helpers. The recipe is [Adding a drill step or a settings key](../README.md#adding-a-drill-step-or-a-settings-key), and its drift check `ai_drill_covers_registry` keeps the rule that a `Built` model or decide row, and the verbs `mcp` and `chat`, have a step.
- No page, template or string shown in a browser is built here, so there is no Design bullet.

## Scope

- Files: `xtask/src/main.rs`, `xtask/src/ai_drill/{mod.rs,plan.rs,env.rs,handoff.rs,refusals.rs,deterministic.rs,secrets.rs,intake.rs,verify.rs}`, `justfile`. The tests are in `mod tests` of `xtask/src/ai_drill/mod.rs`.
- Registration lines: the `ai-drill` job and its entry in the `needs` list of `ci-ok` in `.github/workflows/ci.yml`; the row `ai-drill` in the table of AD-08 in `docs/decisions/0001-foundation.md`.
- Docs to update: none by hand. `cargo xtask --help` lists the new command. No `CHANGELOG.md` line: the owner sees nothing new.

## Out of scope

- The steps of the cards that have not merged: `scripted-endpoint`, `fallback-to-handoff` and `loopback-endpoint` (`model-adapter-openai`), `mcp-session` (`mcp-server`), `decide-run` (`decide-port`) and `bridge-requests` (`chat-bridge`). Each adds one file under `xtask/src/ai_drill/` and one line in the function table of `mod.rs`, and edits nothing else here. Each of those cards lists `ai-drill` in its Cards merged and adds its step in its own pull request, without a condition.
- The gate record and the release run (`release-0-2-0`, a PLAN item). It reads this drill's report. The release workflow is not changed here.
- Any change to the program. If a step fails because the program is wrong, the fix is in the card that owns the behaviour. The drill adds no flag or environment variable to the program.

## Preconditions

- Cards merged: `model-handoff-ask`, `review-queue` and `policy-load` (the `--policy` flag and the Floor and Closed states that the steps run under), `model-gate` (the fixture `state-ai-gate/` and `tests/fixtures/policy/gate.toml` of step 5), `ai-config-and-keys` (`ai status --json` of step 6), `audit-journal` (`audit verify` of steps 3 and 8), `ai-kernel` (`ADAPTERS`, which `ai_drill_covers_registry` reads), `check-ci-and-docs` (the job `changes` that step 9 uses) and `calc-day1` (the seeded generator `tests/support/rng.rs` that step 6 includes).
- Merge order: this card goes in before the cards that add a step, and the plan puts it there. `model-adapter-openai`, `mcp-server`, `decide-port` and `chat-bridge` each require it as a merged card, so none of them can merge first and none has a conditional step.

## Steps

1. `ai_drill/plan.rs`, the plan. `EXPECTED` is a list of `Expected { id, card, covers }` in the order of the gate, with these ids and owners: `handoff-round-trip` (`model-handoff-ask`), `scripted-endpoint`, `fallback-to-handoff` and `loopback-endpoint` (`model-adapter-openai`), `refused-label` and `journal-refuses-appends` (`model-handoff-ask`), `deterministic-verbs` (`model-gate`), `mcp-session` (`mcp-server`), `no-secret-in-state` (`ai-config-and-keys`), `propose-folder`, `agent-cannot-accept` and `accept-is-journaled` (`review-queue`), `decide-run` (`decide-port`), `bridge-requests` (`chat-bridge`) and `audit-verify-clean` (`audit-journal`). `covers` names what a step proves: `model/handoff@1` for the first, `model/openai-compatible@1` for `scripted-endpoint`, `decide/rules-model@1` for `decide-run`, and the verbs `mcp` and `chat` for their steps. A step is built when `mod.rs` holds a function for its id; `FUNCTIONS` is the table later cards add a line to.
2. `ai_drill/mod.rs` and `env.rs`, the runner. `Drill` owns a temporary folder with a copy of `corpus-mini`, makes a state folder per step from a named fixture and, when the step names one, a policy file from `tests/fixtures/policy/` that it passes as `--policy` (the drill builds the AI binary with the feature `test-hooks`, because a release binary has no such flag; a step that names none runs under the Floor), builds `fieldbook` once with `cargo build --locked -p fieldbook --features test-hooks` through `proc::run_visible`, and starts it with `--state` through `std::process::Command` in `env.rs`, because the helpers of `proc.rs` take neither an environment nor standard input. This keeps the rule that only `xtask` starts a process. Helpers: `run(args, stdin)` returns the exit code, standard output and standard error; `run_tty(args, input)` runs the command under `script -qec` from util-linux so that it has a terminal, and fails the step naming `script` when it is missing; `events(state)` reads `audit/journal.jsonl` and returns the lines of a kind; `tree_hash(dir)` hashes a folder in path order. The output is `PASS <n> <id>`, `FAIL <n> <id>: <reason>` or `NOT BUILT <n> <id> (<card>)`, then `ai-drill: P passed, F failed, N not built`. A function that panics is a `FAIL`. A function whose id is not in `EXPECTED` is an error before any step runs. `--report FILE` writes the same lines and a last line, `gate: complete` when nothing failed and nothing is not built, else `gate: incomplete`. The report holds no time and no path, so two runs of the same tree give the same bytes.
3. `handoff.rs`, `handoff-round-trip`, on a copy of `tests/fixtures/state-ask/`. Run `ask "synthetic" --scope area:cmp --note` (`cmp` is an area of `corpus-mini`, the one `new claim --area cmp` uses); the pack is `handoff/H-0001.txt` and its first line is `Labels: owner-supplied`. Resume with `ask --resume H-0001 --from reply-good.txt --note`. The journal must hold `ai.pack` then `ai.paste` for it and no `ai.begin` or `ai.call`, and the report must show every citation resolving. `queue show P-0001` on the note it filed must exit 0 with no FB0917, which shows that the file `ask --note` writes is the file `review-queue` reads. Copy the state, change one hex digit of `output_sha256` in the copy's proposal, and `queue show` must print FB0917 and exit 1, so the check is seen to bite. Last, `audit verify` exits 0.
4. `refusals.rs`, `refused-label` and `journal-refuses-appends`. For the first: a state whose `[model.handoff]` table has `allow = []`, so that no route covers the owner's question; `ask "synthetic"` must exit 2 with FB0901, `handoff/` must stay empty, and the journal must hold one `refuse` event with the code, the request's `labels` and reason `label`, with `dest` absent, and no `ai.pack`. Over Handoff this is the whole of the AI-drill case "a request with a label outside the destination's allowed set sends nothing"; the endpoint variant is `model-adapter-openai`'s. For the second: a copy of `tests/fixtures/state-known-bad/FB0903/`, whose journal has a wrong last hash: `ask "synthetic"` must exit 3 with FB0903 and write no pack, and `search synthetic` and `check` on the same copy must still run, because reads do not need the journal.
5. `deterministic.rs`, `deterministic-verbs`. On a copy of `tests/fixtures/state-ai-gate/` (the settings of `model-gate`, which name an endpoint and an `order`, with `tests/fixtures/policy/gate.toml` as the policy), run `check --strict --today <TODAY>` (the date in the `TODAY` file of the fixture copy, which `Drill` reads once), `search synthetic`, and `build` twice into two folders. The two output trees must have the same `tree_hash`, and the journal must hold no `ai.*` event from these runs. The in-process proof with `PanicHttp` is `tests/deterministic_verbs.rs` of `model-gate`; this step is the same claim on the built binary, after the AI steps have run in the neighbouring states.
6. `secrets.rs`, `no-secret-in-state`. The settings name an endpoint `fake` with `key_env = "FIELDBOOK_DRILL_KEY"`. The step gives each `fieldbook` process it starts that variable, with `Command::env`, as a synthetic string made of `drill-key-` and 16 hex digits, and uses a question made of `drill-prompt-` and 16 hex digits. The digits come from `Rng` (`tests/support/rng.rs`, included in `xtask/src/ai_drill/mod.rs` with `#[path = "../../../tests/support/rng.rs"] mod rng;` and written nowhere else, `one_rng_exists`) with a fixed seed, so two runs use the same strings and a leak of either is found by searching for the whole string. It runs `ai status --json`, `ai test`, the question through `ask`, a refused `ask` (step 4's state) and `ask --via fake`, which fails as an adapter that is not built or not configured, and keeps every output. The key must appear in no journal line, no file under `ai/` or `handoff/`, no output and no error string. The prompt may appear in `handoff/` (it is content) and must appear in no journal line, no `ai status` output and no error string. This is the drill form of NS-07.
7. `intake.rs`, three steps on one copy of `corpus-mini` and one state folder whose `settings.toml` has `role = "lead"`. `propose-folder`: an inbox with `a-regulation.txt` (the line `Synthetic Regulation Text, part one. Made up for tests.`), `b-copy.txt` (the same bytes), `c-page.html` (a small HTML page with a title) and `d-tool.ps1`; `add <inbox> --propose --confirm-public` must print, in this order and by fields not by spacing, `proposed P-0001 new_source a-regulation.txt`, `waiting P-0001 b-copy.txt`, `proposed P-0002 new_source c-page.html`, `refused FB0821 d-tool.ps1` and `done: 2 proposed, 1 waiting, 1 refused`, exit 1; `tree_hash` of `corpus/` must be the same before and after; the journal must hold two `queue.propose` events and one `refuse`. `agent-cannot-accept`: `queue accept P-0001` with standard input from `/dev/null` must print FB0822 on standard error and exit 1 with `corpus/` unchanged, and the same under a terminal with `role = "agent"` must print FB0822 and exit 1 with `corpus/` unchanged (a terminal joins the two streams). `accept-is-journaled`: with `role = "lead"` and under a terminal, `queue accept P-0001` with the input `y` must exit 0 and print `accepted`. The journal must then hold exactly one `write.begin` and one `write.end` for `queue accept` and one `queue.accept`, in that order; the Corpus must hold the new original, its text and one new row; `check --today <D>` must report only FB0205 for the new row, where `<D>` is the UTC date that `Drill` read when it started, because the accept stamped that date into the row (the README date rule: a sequence that follows a stamping verb passes the date of the run, and the report holds no date); and `queue list` must no longer show `P-0001`.
8. `verify.rs`, `audit-verify-clean`, always last: `audit verify` must exit 0 on every state folder that the earlier steps made and that is meant to be clean, which is all of them except the FB0903 copy.
9. `xtask/src/main.rs`: the `ai-drill [--report FILE]` command. `justfile`: a `ai-drill` recipe that runs it. `.github/workflows/ci.yml`: a job `ai-drill` on `ubuntu-24.04`, with `timeout-minutes: 20`, the read-only token and the same pinned actions as the `rust` job. It is gated by `changes` as the recipe "Adding a CI job" in [docs/cards/README.md](../README.md#adding-a-ci-job) says: `needs: [changes]`, and `if: needs.changes.outputs.code == 'true'` on every step after checkout, with no job-level `if` and no path list. It runs `cargo xtask ai-drill --report target/ai-drill/report.txt` and uploads the report as the artifact `ai-drill-report`. Add `ai-drill` to the one-line `needs` of `ci-ok` (the test `ci_ok_needs_every_job` fails without it) and add this row to the table of [AD-08](../../decisions/0001-foundation.md#ad-08-ci-design), above the `ci-ok` row: "`ai-drill` | Runs `cargo xtask ai-drill` on `ubuntu-24.04`: the Day-30 gate drill on the built binary, and uploads its report. Needs `changes`; its steps run when `changes.code` is true (built by `ai-drill`)".
10. Tests in `mod tests` of `ai_drill/mod.rs` (`xtask` is a binary crate, so a file in `xtask/tests/` could not call the runner or the plan). `run_drill(expected: &[Expected], functions: &[(&str, StepFn)], report: Option<&Path>) -> i32` is what `main.rs` calls with `EXPECTED` and `FUNCTIONS`, so a test passes a table of fake steps of its own: `unbuilt_step_prints_not_built_and_is_not_counted_as_passed`, `failing_step_exits_1`, `panicking_step_is_a_fail`, `function_without_a_plan_entry_is_an_error`, `report_is_the_same_bytes_twice`, `gate_is_incomplete_while_any_step_is_not_built`, `plan_ids_are_unique`, and `ai_drill_covers_registry`: every `Built` row of `ADAPTERS` whose port is Model or Decide, and the verbs `mcp` and `chat` when the clap definition has them, must be named by the `covers` of a step that has a function, and a temporary extra `Built` row with no step must make the test fail. The registry holds no MCP row, so the check reads the verbs from the clap definition.

11. Call only ModelPort; Guarded and the selected ModelAdapter own preparation, authorization and delivery. This caller never implements prepare or attempt.

12. Terminal presence, a writable role setting and Git author text are accidental-use checks and attribution, not proof of a human identity. The agent must not run acceptance, label changes or certification; consequential decisions use the owner review flow outside these writable settings. The scripted PTY drill tests mechanics and grants no authority to approve real work. Add a PTY-path test showing both redirected refusal and the scripted terminal mechanics. The drill report describes these as scripted mechanics.

## Acceptance

```sh
cargo nextest run --locked -p xtask ai_drill::
cargo xtask ai-drill --report "$(mktemp -d)/report.txt"; echo "exit $?"
cargo xtask --help | grep -c ai-drill
just check
```

Expected: the tests pass; the drill prints `PASS` for the nine steps of this card, `NOT BUILT` with a card name for each step of a card that has not merged, a final `ai-drill: 9 passed, 0 failed, N not built` where N is the number of such steps, and `exit 0`; `grep -c` prints `1`; `just check` exits 0. A tree on which every card has merged prints `gate: complete` and `0 not built`. Remove the temporary folder afterwards.

## Negative control

On the branch, make `ask` write its pack before it appends `ai.pack` when the journal refuses: the step `journal-refuses-appends` must print `FAIL` and the command must exit 1. Restore it. Let `ask` build a pack for a request whose labels no route covers: `refused-label` must fail. Restore it. Remove the `ai.paste` append: `handoff-round-trip` must fail. Restore it. Let `queue accept` go on without a terminal: `agent-cannot-accept` must fail. Restore it. Make `add --propose` write a row to `sources.csv`: `propose-folder` must fail on the `tree_hash` of `corpus/`. Restore it. Add a `Built` model row to a temporary copy of the registry with no step: `ai_drill_covers_registry` must fail. Next, register a function for the id `mcp-session` while `fieldbook` has no `mcp` verb: the step must fail rather than pass. Last, open a scratch pull request that changes only a file under `docs/`: the `ai-drill` job finishes with success and its steps show as skipped; a pull request that changes a file under `crates/fieldbook/src/adapters/` runs them.

## Rollback

Revert the merge commit. The command, the just recipe and the CI job go, `ci-ok` stops needing the job and the AD-08 row goes. Revert the cards that added a step first (`model-adapter-openai`, `mcp-server`, `decide-port`, `chat-bridge`), because each one has a file under `xtask/src/ai_drill/` and a line in `mod.rs`. The program is untouched, so no behaviour changes, but the Day-30 gate has no drill and `release-0-2-0` cannot pass until the card is restored.

## BLOCKED

The accept step needs a pseudo-terminal, and the CI image or the contributor's machine may not have `script`. If a terminal cannot be allocated, set the item to Blocked with `BLOCKED: no pseudo-terminal for the accept step`, and stop. Do not make `queue accept` skip its terminal check for the drill, and do not add a flag or an environment variable to the program that does.
