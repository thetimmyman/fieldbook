# extract-xlsx-sheets

- **Runs where:** home, CI Linux
- **Schema impact:** none
- **Review:** owner

## Outcome

A workbook can be extracted, cited and checked without saving it as CSV first. `cargo xtask extract <version-id>` on a version whose original is a `.xlsx` or `.xlsm` file writes `sources/text/<version-id>/` with, for each worksheet in tab order, one text file per window of 50 data rows, each starting with the header line of that sheet (its row 1), and an `extraction.toml` with `method = "xlsx-sheets"`, `unit = "window"`, `window_rows`, `row_count`, `values = "cached"`, one `[sheets."NAME"]` table for each sheet and, where the workbook calls for it, `flags`. A claim cited at `sheet Rates!D214` or `sheet Rates!A2:F9` is checked against the cells it names, and a claim cited at `rec Rates!213` against data row 213 of that sheet: `check` raises FB0311 when the sheet, the row or the range does not exist and FB0308 when the claim's quote is not in the cells named. The text holds the value that the workbook stored in each cell and never a formula. The source page and the title of a text window say when a figure may be stale (calculation was manual when the workbook was saved), when a figure is the result of a formula, and when a sheet is hidden. Nothing in the workbook runs, is followed or is opened beyond its cell values. The method is the `xlsx-sheets@1` extractor, registered with the other four, and the company device calls the same extractor (`r2-pull-and-sync`, `r2-org-intake`). A `.xls`, `.xlsb` or password-protected workbook is refused with a message that says to save a copy as `.xlsx`.

## Why

- The method, the windows, the locators, the keys and the flags are in [Extraction](../../reference/corpus-format.md#extraction) and the [Check catalogue](../../reference/corpus-format.md#check-catalogue). The place of the method in the company design is [ADR 0004, section 9](../../decisions/0004-company-boundary.md#9-provenance-extraction-and-records), and the owner's answer that this card carries out is row D-24 of [ADR 0001](../../decisions/0001-foundation.md): read the cell values of a workbook directly, right after CSV, and do not wait for a workbook to fail the CSV route first.
- A company workbook cited through a CSV is a file the owner made, not the file the company holds. The hash, the page and the figure then rest on a step ("recalculate, then save as CSV UTF-8") that every person must remember for every file and that nobody can repeat from the original. Reading the `.xlsx` keeps the original the company's own file. The CSV route stays for a system that only exports CSV (`extract-csv-rows`).
- Values stored are not values shown, and neither is a formula. A cell holds the value the workbook last stored next to its formula. With manual calculation on, that value can disagree with the cells it depends on, and nothing on screen says so (R-13). The extractor reads what the file stores, which is the only thing it can know, and states what it could tell about that value in `flags`: `formulas` (a figure may be a formula's saved result), `calc-manual` (calculation was manual when the workbook was saved), `uncached-formulas` (a formula had no saved result and its cell is empty) and `external-links` (cells may hold results from other files, which were not followed). The failure they prevent: a price taken from a stale cell is quoted as if it were current.
- The text holds the stored value and not the display. A number format shows `41.2` as `41.20` and `0.05` as `5%` on one machine, and a reader cannot recover the stored value from the display. A quote is copied from the extracted text, as Extraction already says, so `41.2` is what matches.
- A sheet is a table, with the arithmetic of `csv-rows`: sheet row 1 is the header, data row N is sheet row N + 1, its window within the sheet is `ceil(N / window_rows)` and its line is `((N - 1) mod window_rows) + 2`. Blank rows are kept so that the arithmetic holds, a window never mixes two sheets, and nothing is stored per row. A workbook whose table does not start at `A1` is cited with the `sheet` locator, which names cells and not rows.
- A figure in a workbook is cited at its cell, so the `sheet` locator names cells (`D214`, `A2:F9`), and `rec Rates!213` names the whole row for a claim about a line. The sheet name is part of both because a workbook has several tables.
- Nothing can run. The extractor takes bytes and returns text: it opens no file, no socket and no process, reads no formula text, and never semantically reads a macro project, embedded object or drawing, or follows a link target. Semantic extraction reads only the workbook, strings, styles and worksheets; bounded size-accounting inflation separately measures every ZIP entry without interpreting excluded payloads. A formula is never evaluated, and a link to another file is never followed (it is only named in `flags`).
- The reader is `calamine` 0.36.1 (pure Rust, MIT). It streams cells, gives the stored value and says whether a cell has a formula, and it takes `zip` 8.6 with `deflate`, which is the version `rust_xlsxwriter` already brings, so the graph keeps one `zip` (the metadata test). It does not expose the calculation mode or the external-link parts, so `zip` is also a direct crate of `fieldbook-core`. Alternatives: `umya-spreadsheet` (reads and writes, much heavier), and a reader written over `zip` (shared strings, styles for dates and shared formulas are easy to get wrong). Pins and reasons are rows of [dependencies.md](../../reference/dependencies.md).
- This card has `Review: owner` because it adds a parser of untrusted files to the program that runs on the company device, two direct crates (`calamine` and `zip`) and about nine transitive crates. It takes the silent build to 14 direct runtime crates (still 14 at R2) and the AI build to 17 from `v0.2.0` (still 17 at R2; `embed-resource` is build-only), past the review trigger of 15, and it takes the AI build's transitive count to about 96 against a cap of 100. The owner reads the counts it measures (step 1).
- A zip is an attack surface that a CSV is not: a few kilobytes can inflate to gigabytes. The card therefore bounds the original (32 MiB), the bytes the parts inflate to (256 MiB, counted by inflating each part once into nothing before `calamine` reads it), the cells (5,000,000), the data rows (100,000) and the windows (9,999), and a file over a bound is `TooLarge`, never cut. The original is still kept and cited by hash.
- Extraction output carries the labels of its original (the union rule of [ADR 0004](../../decisions/0004-company-boundary.md#2-labels)). The extractor reads bytes and returns text, sends nothing and takes no token.
- The Later row that held the workbook reader is renamed `later-docx-import` and now holds Word only, because this card builds the workbook half.
- Design: the [MAP.md](../../design/MAP.md#routes-and-components) row "Source drawer", for the label of a window in LocatorView. The label text is a request to the interface lane (`docs/design` is theirs); this card sets the string in `extraction.rs` and changes no template or token.

## Out of scope

- Formula text. It is never read or shown; a formula is neither evaluated nor checked.
- The review queue. An extraction is written when a proposal is accepted, so `queue show` cannot print the flags of a workbook before that; the source page and the title of the text show them after it.
- The number format. A cell shows what is stored, not what is displayed; no currency, percent or accounting format is interpreted. A duration (a time-delta format) is written as the number stored, in days.
- Merged cells, hidden rows and columns, comments, charts, images, pivot caches, named ranges, Excel tables, data validation and hyperlinks. A merged range has its value in its top-left cell and the rest empty, as the file stores it. `fullCalcOnLoad` is not read: a workbook that asks to be recalculated on opening either stores results (they are what the file says) or does not (`uncached-formulas`).
- `.ods`, `.xltx` and `.xltm`. `accepts` is false for them, so they stay `needs-extraction`. `.xls`, `.xlsb` and password-protected files are routed here only to be refused with a message.
- A table that does not start at `A1`: the first sheet row is the header, whatever it holds.
- Loading typed records from a workbook (`r2-records` reads CSV only), search units for the windows of a company source (`r2-company-ids`) and the call of this extractor from `sync` and company intake (`r2-pull-and-sync`, `r2-org-intake`).
- Word files (`later-docx-import`), PDF and OCR (`later-pdf-native-ocr`), and a dataset tier for ledger-scale tables (`later-dataset-tier`).
- A change to quote normalisation, to the register reader, or to any extraction already committed. A page extraction and a `csv-rows` extraction stay byte-identical.

The rows of `dependencies.md` (pins, reasons, the budget and the planned replacement) are in the repository already; this step makes the manifests equal them. Run `just lock`, then follow [Review evidence](../../reference/dependencies.md#review-evidence) with committed-lock builds, both cargo-deny shapes and exact-source MAX/JEV review. The two `zip` checks must still pass: `two_zip_versions_are_rejected` (xtask) and the metadata test. Measure the transitive count of each profile with the command of "Counting crates" in `dependencies.md` (without and with `--features net` once that feature exists), compare it with the estimate (about nine more crates in each profile: `atoi_simd`, `debug_unsafe`, `rustversion`, `byteorder`, `codepage`, `encoding_rs`, `fast-float2`, `log` and `quick-xml`, some of which may be in the graph already), and add one row to Measurements. If a count is over its cap, the card is BLOCKED (below); if one is within 10 of its cap, the pull request says so, as the policy asks. The Budget cell of `dependencies.md` already names the counts that include this card (14 silent, 17 for the AI build from `v0.2.0`); if the documented budget does not describe the actual activation stage, reconcile that stage explicitly in review without raising a cap to fit the result (a budget is raised by an edit of the cell with a reason, not by a gate). Tests: none of its own; the checks are the test.
2. Package facts, `extraction/xlsx_sheets/facts.rs`: `scan(bytes: &[u8], ext: &str, limits: &Limits) -> Result<Facts, ExtractError>` with `Facts { calc_manual: bool, external_links: bool }` and `Limits { bytes, unpacked, cells, data_rows, windows, columns, cell_text_bytes, output_bytes }`, whose `Limits::DEFAULT` is `MAX_BYTES = 32 MiB`, `MAX_UNPACKED = 256 MiB`, `MAX_CELLS = 5_000_000`, `MAX_DATA_ROWS = 100_000` and `MAX_WINDOWS = 9_999`, `MAX_COLUMNS = 1_024`, `MAX_CELL_TEXT_BYTES = 1 MiB` and `MAX_OUTPUT_BYTES = 32 MiB`. The order of refusals is fixed: more than `bytes` is `TooLarge`; ext `xls`, or a head of `D0 CF 11 E0 A1 B1 1A E1` (the container of an old or a password-protected workbook) is `NotWorkbook(OldFormat)`; ext `xlsb` is `NotWorkbook(Binary)`; a head that is not `PK\x03\x04` or `PK\x05\x06`, a zip that `zip` cannot open, and a zip with no `xl/workbook.xml` are `NotWorkbook(Unreadable)`. `WorkbookRefusal` is the enum `{ OldFormat, Binary, Unreadable }` and its sentence is one const table: `OldFormat` "an old .xls workbook, or one that has a password; in Excel, remove the password and save a copy as .xlsx (or as CSV UTF-8)", `Binary` "a binary .xlsb workbook; in Excel, save a copy as .xlsx (or as CSV UTF-8)", `Unreadable` "not a workbook this method can read; in Excel, save a copy as .xlsx (or as CSV UTF-8)". Then each entry is inflated once into nothing with a running total of real bytes (the declared size is not trusted); a total over `unpacked` is `TooLarge`. `external_links` is true when an entry name starts with `xl/externalLinks/` (compared without case). `calc_manual` is true when the first element of `xl/workbook.xml` with the local name `calcPr` has the attribute `calcMode` equal to `manual`: `calc_mode(xml: &str) -> bool` is a scan, not an XML crate. It skips comments, CDATA, processing instructions and a doctype, takes the tag name to the first space, `/` or `>`, drops a prefix up to the last `:`, and reads attributes with single or double quotes, so a `>` inside a value does not end the tag. Before Calamine construction, this same semantic boundary also opens the exact shared-string part Calamine will consume for the bounded preflight below. No unrelated part is opened by this module. Tests, in `mod tests` of `facts.rs`: `an_xls_extension_is_old_format`, `a_compound_file_head_is_old_format_whatever_the_extension`, `an_xlsb_extension_is_binary`, `text_named_xlsx_is_unreadable`, `a_zip_without_a_workbook_part_is_unreadable`, `more_than_32_mib_is_too_large`, `a_zip_that_inflates_past_the_limit_is_too_large` (the test sets `unpacked` to 1 MiB and builds a part of 2 MiB of zeros), `a_lying_size_in_the_directory_is_not_trusted` (the builder writes a part whose declared size is 10 and whose data inflates to 2 MiB; with `unpacked` at 1 MiB it is `TooLarge`), `external_link_parts_are_named`, `calc_manual_is_read`, `calc_auto_is_not_manual`, `a_missing_calcpr_is_auto`, `a_prefixed_calcpr_is_read`, `calcpr_in_a_comment_or_cdata_is_ignored`, `a_gt_inside_an_attribute_value_does_not_end_the_tag`, `scan_never_panics_on_random_and_mutated_bytes` (the file includes the generator with `#[cfg(test)]` on the line above `#[path = "../../../../../tests/support/rng.rs"] mod rng;`, so that the normal build does not compile it, and writes it nowhere else (`one_rng_exists`); the test takes 200 byte strings of length 0 to 512 from `Rng::new(1)` and 200 strings of 0 to 256 bytes from the same generator as `calc_mode` input, and each goes through `scan` or `calc_mode`: a value or a typed error and never a panic).
3. Cell text, `extraction/xlsx_sheets/cells.rs`: `cell_text(&DataRef, is_1904: bool) -> String`, the one place that writes a cell. An empty cell and an empty string are `""`. A string is written as stored with each tab, CR, LF or CRLF written as one space. `Int` is its decimal digits. A `Float` that is finite, whole and below 1e15 in magnitude is written as an integer (`-0` is `0`); any other finite float is the shortest decimal that reads back to the same number (Rust `Display`, never an exponent); a float that is not finite is `#NUM!`. A boolean is `TRUE` or `FALSE`. An error is its Excel text (`#DIV/0!`, `#N/A`, `#NAME?`, `#NULL!`, `#NUM!`, `#REF!`, `#VALUE!`, `#DATA!`). A date-time that `calamine` marks as a date or time is written as an ISO text by `date_text(serial: f64, is_1904: bool) -> Option<String>`: a serial below 1 is a time of day `HH:MM:SS`; in the 1900 system a serial from 1 to 59 is the day after 1899-12-31, serial 60 is the text `1900-02-29` (the day Excel counts and the calendar does not have), and a serial from 61 is `1899-12-30` plus the serial; in the 1904 system a serial is `1904-01-01` plus the serial; the time part is the fraction rounded to a whole second (a result of 86400 seconds carries into the next day) and is written as `YYYY-MM-DDTHH:MM:SS` when it is not midnight and as `YYYY-MM-DD` when it is; a negative serial, or one after 9999-12-31, returns `None` and the number is written as a number. A duration (`calamine` marks a time-delta format) and an ISO text that the file itself stores are written as stored. The civil date comes from the days-from-civil algorithm with no date crate. Tests, in `mod tests` of `cells.rs`: `a_string_is_written_as_stored`, `tab_cr_lf_and_crlf_in_a_cell_become_one_space`, `an_empty_string_is_an_empty_cell`, `a_stored_41_2_is_written_41_2`, `a_whole_float_has_no_decimal_point`, `negative_zero_is_zero`, `a_large_float_has_no_exponent`, `a_float_that_is_not_finite_is_num`, `booleans_are_upper_case`, `every_error_has_its_excel_text`, `serial_45123_is_2023_07_16`, `serial_61_is_1900_03_01`, `serial_60_is_the_fictional_1900_02_29`, `serial_59_is_1900_02_28`, `a_serial_below_1_is_a_time`, `a_1904_serial_adds_the_1904_epoch`, `the_time_part_rounds_to_a_second_and_carries`, `midnight_has_no_time_part`, `a_negative_serial_is_a_number`, `a_duration_is_the_number_stored`, `date_text_never_panics_on_random_serials` (the same generator: 200 values from `Rng::new(1)` taken as `f64` bit patterns, which include NaN and infinities).
4. The extractor, `extraction/xlsx_sheets.rs`: `XlsxSheets::new(window_rows)` with `WINDOW_ROWS = 50` as the default (the const of `csv_rows`), `XlsxSheets::with_limits(window_rows, Limits)` for tests, an `Extractor` with `id()` `xlsx-sheets@1` that accepts the extensions `xlsx`, `xlsm`, `xls` and `xlsb` in any case. `extract(bytes, ext)` runs `scan` and its bounded shared-string preflight before opening the bytes with `calamine::Xlsx::new(Cursor::new(bytes))` (any `calamine` error is `NotWorkbook(Unreadable)`, and `XlsxError::Password` is `NotWorkbook(OldFormat)`), and reads only the sheets whose type is a worksheet, in tab order (`sheets_metadata`); a workbook with none is `ExtractError::Missing("worksheet")`. For each sheet it streams the cells with `worksheet_cells_reader` and `next_cell_with_formula_metadata`, ignoring an empty cell, and groups them by row: a cell with a formula makes the flag `formulas`, and a formula cell with no stored value is written as an empty cell and makes the flag `uncached-formulas`. A row's text is its cells from column A to its last non-empty cell, separated by one tab (the cells before it are empty, so a column keeps its place), and a row with no cell is an empty line. Sheet row 1 is the header and is not a data row; the data rows are sheet rows 2 to the last one that holds a cell, so `rows` is that number minus 1, or 0. The `columns` of a sheet is the largest number of cells in a row. Each sheet starts at a new window; its windows are `p000i.txt` numbered on from the last window of the sheet before: the header line, then up to `window_rows` data row lines, each ending in a line feed. A sheet with `rows = 0` has one window that holds the header (an empty line when row 1 has no cell). The returned `Extraction` has `table: Some(TableMeta { window_rows, row_count, values_only: false, values: Values::Cached, sheets, flags })`, where `row_count` is the sum of `rows` over the sheets, `sheets` is a `Vec<SheetMeta { name, first, last, rows, columns, hidden }>` in tab order (`hidden` is true for a hidden and for a very hidden sheet) and `flags` is the set of `WorkbookFlag` in the order of `WORKBOOK_FLAGS`. `TableMeta` is the type of `extract-csv-rows`, which derives `Default` (`Values::AsWritten`, empty `sheets`, empty `flags`) and builds every `TableMeta` with `..TableMeta::default()`, so `csv_rows.rs` and its tests are not edited here and its output does not change. `WorkbookFlag` is the enum `{ CalcManual, ExternalLinks, Formulas, UncachedFormulas }` and `WORKBOOK_FLAGS` the const table of `(flag, word, note)` in this order: `formulas` "formula cells show the result last saved", `calc-manual` "calculation was manual when saved; formula results may be stale", `uncached-formulas` "some formula cells had no saved result and are empty", `external-links` "cells may hold results from other files; the links were not followed". The flags `calc-manual` and `uncached-formulas` are set only when the workbook has a formula, since neither means anything without one; `calc_manual` and `external_links` of `Facts` set `calc-manual` and `external-links`. A workbook with a `ExternalLinks` part and no formula still gets `external-links`. The limits are counted as the cells are read: more than `cells` cells, more than `data_rows` data rows in all, or more than `windows` windows is `ExtractError::TooLarge`. Merged cells are not read, hyperlinks and formula text are not read, and a sheet name is kept as it is stored. The module holds the named consts and the table; no number appears elsewhere. `ExtractError` gains the variant `NotWorkbook(WorkbookRefusal)` and names the extractor as the others do. Tests, in `tests/xlsx_sheets.rs` (the file includes the builder with `#[path = "support/xlsx_build.rs"] mod xlsx_build;`, which writes a workbook's parts by hand and zips them, and writes it nowhere else (`one_xlsx_builder_exists`)): `a_sheet_of_120_rows_makes_windows_of_50_50_20`, `every_window_starts_with_the_sheets_header`, `sheets_are_read_in_tab_order_and_never_share_a_window`, `row_count_is_the_sum_over_the_sheets`, `columns_is_the_widest_row`, `a_header_only_sheet_has_one_window_and_no_rows`, `an_empty_sheet_has_one_window_with_an_empty_header`, `blank_rows_are_kept_so_the_row_arithmetic_holds`, `trailing_empty_cells_are_trimmed_and_leading_ones_are_kept`, `a_hidden_sheet_is_read_and_marked`, `a_very_hidden_sheet_is_marked_hidden`, `a_chart_sheet_is_skipped`, `a_workbook_with_no_worksheet_is_missing`, `a_merged_range_has_its_value_in_the_top_left_cell`, `a_formula_gives_its_saved_result_and_never_its_text`, `a_formula_without_a_saved_result_is_empty_and_flagged`, `formulas_set_the_formulas_flag`, `manual_calculation_with_formulas_sets_calc_manual`, `manual_calculation_without_formulas_sets_no_flag`, `a_workbook_without_formulas_has_no_flags`, `external_link_parts_set_external_links_and_are_not_followed`, `a_macro_project_is_never_opened` (a `vbaProject.bin` whose bytes are not a valid file does not change the result), `dates_are_written_as_iso_text` (a 1900 and a 1904 workbook), `shared_strings_and_inline_strings_both_read`, `an_xlsm_is_read_like_an_xlsx`, `an_xls_is_refused_with_its_message`, `an_xlsb_is_refused_with_its_message`, `a_password_protected_workbook_is_refused`, `more_than_100000_rows_is_too_large`, `more_than_5000000_cells_is_too_large`, `more_than_9999_windows_is_too_large`, `a_sparse_cell_far_down_is_too_large_and_not_a_million_blank_lines`, `same_input_same_output`, `random_and_mutated_bytes_never_panic` (the file includes the generator with `#[path = "../../../tests/support/rng.rs"] mod rng;` and writes it nowhere else (`one_rng_exists`); the test takes 200 byte strings of length 0 to 512 from `Rng::new(1)`, takes `original.xlsx` of `tests/fixtures/extract/xlsx-sheets/` cut at 512 bytes, and takes the builder's sample workbook with each byte of `xl/workbook.xml`, `xl/styles.xml`, `xl/sharedStrings.xml` and `xl/worksheets/sheet1.xml` once flipped and once deleted, each written into the zip uncompressed so that the mutation reaches the parser;
