# stage-command

- **Runs where:** home, CI Linux
- **Schema impact:** none
- **Review:** auto

## Outcome

`cargo xtask stage <dir> [--state DIR] [--recursive] [--propose [--confirm-public]]` extracts the text of every PDF in the inbox with `pdftotext -layout` and writes it to `staging/<sha256>/` in the state folder: one text file for each page and an `extraction.toml` that holds the original's hash and the hash of each page. With `--propose` it then runs `fieldbook add <dir> --propose` (with `--confirm-public` when `stage` was given it), which finds the staged text, so the proposal carries quotes from the PDF's own pages. The program never starts a process and does not know that poppler exists; it only reads the staging folder.

## Why

- The shipped program starts no process, so it cannot run poppler. At home the owner wants PDFs in the queue with real page text, and `xtask` is the only crate that may start a process ([AD-05](../../decisions/0001-foundation.md#ad-05-crate-layout-and-enforcement) is the layout rule). The staging folder is the whole interface between the two: one writer here, one reader in `staged@1`, and no shared state.
- The layout is the one `extract` writes for a version under `sources/text/<version-id>/`, so `queue accept` can move the pages from `staging/` into the Corpus unchanged and the hashes still match ([Extraction](../../reference/corpus-format.md#extraction)). Both commands call one writer, so there is no second copy of the key order.
- Staging is derived state, not content: it is untracked, holds text that is already in the original, and is removed when the proposal is accepted. A folder is written whole or not at all (written beside, then renamed), so `staged@1` never reads a half-written folder. A folder that exists and still verifies is kept, so running the command twice does the same work once.
- This is the second card to cut if Day 30 is at risk. Without it a PDF is proposed with no extraction (FB0825) and the owner can still paste the text with `add FILE --text TEXTFILE` on the laptop; nothing built earlier depends on `stage`.
- No page, template or string shown in a browser is built here, so there is no Design bullet. `stage` is a developer command and has no chip.

## Scope

- Files: `xtask/src/{main.rs,extract.rs,stage.rs}` (the tests are in `mod tests` of `stage.rs` and `extract.rs`), `tests/fixtures/state-intake/` (read; rewritten only if the rebuild differs).
- Registration lines: `AGENTS.md` (the Commands line for `cargo xtask stage`).
- Docs to update: `AGENTS.md` (Commands: `cargo xtask stage <dir> [--propose [--confirm-public]]`, at home, needs `pdftotext`). `cargo xtask extract` is unchanged for its users. No `CHANGELOG.md` line: the shipped program does not change.

## Out of scope

- The reader of the staging folder (`staged@1`, `pipeline-ports`), the proposal files and `add --propose` (`review-queue`), and OCR. A page with no text is listed as thin, never repaired.
- Text a person pastes for a file the tools cannot read (`supplied@1`, `r2-org-intake`), and any other format than PDF. HTML and plain text are extracted by the program itself, which stages their output when it proposes them.
- A marking scan of the extracted text. `add --propose` scans and refuses a marked file (FB0400); the staged text stays in the untracked state folder like the inbox file itself.
- Removing old staging folders. `queue accept` removes the folder of an accepted file; a folder for a file that was never proposed stays until the owner deletes it.

## Preconditions

- Cards merged: `extract-and-locators` (`Extractor`, `PdftotextLayout`, the writer of a version's text folder and the fixtures), `extract-csv-rows` and `extract-xlsx-sheets` (all three cards edit `xtask/src/extract.rs`, so this card splits `write_extraction_dir` out of the file as `extract-xlsx-sheets` leaves it, with the `csv` arm and the `xlsx`, `xlsm`, `xls` and `xlsb` arms in `select`), `review-queue` (`add --propose`), `pipeline-ports` (`staged@1`, the reader that checks a staging folder) and `ai-kernel` (the path edge from `xtask` to `fieldbook` that the checks of `staged@1` need).

## Steps

1. `extract.rs`: split the function that writes a version's text folder into `write_extraction_dir(dir: &Path, original_sha256: &str, tool: &str, tool_version: &str, extraction: &Extraction) -> io::Result<()>`. It writes `pNNNN.txt` files (LF, one final newline) and `extraction.toml` in the key order of the reference (`tool`, `tool_version`, `method`, `page_count`, `thin_pages`, `original_sha256`, `[pages]`, `[locators]`). `extract` calls it and its output must not change by one byte: the tests of `extract.rs` (`cargo nextest run --locked -p xtask extract::`) pass untouched. Make `PdftotextLayout` and the pin check `pub(crate)` if they are not. The two strings are the tool name and version that `extract` already records; `extract` passes both, and the fixture writer uses fixed synthetic values.
2. `stage.rs`, arguments. `dir` must be the state folder's `inbox/` or a folder inside it, else exit 2 naming the inbox path. The state folder is `--state` or `FIELDBOOK_STATE`, the rule the program uses. `--recursive` walks subfolders. Files are taken in the byte order of their names, the order of `add-folder-mode`, so the report is stable. A symbolic link or a folder where a file is expected is skipped with the reason.
3. `stage(args, extractor: &dyn Extractor, runner: &dyn Runner) -> StageReport` is the core of the command, so a test can pass a scripted extractor and a scripted runner. `stage.rs` defines `pub trait Runner { fn run(&self, program: &str, args: &[&str], dir: &Path) -> Result<RunOutput, String>; }`, `pub struct RunOutput { pub code: Option<i32>, pub stdout: String, pub stderr: String }` and `struct Process;`, which implements `Runner` through `proc::output` of `xtask`; a `None` code (the process was ended by a signal) is exit 3. `stage` uses the runner for `pdftotext -v` and for the `add` command of step 6. These types are local to `stage.rs`; the `Runner` of `r2-migrate` is its own. For each file: a name that does not end in `.pdf` (any case) prints `skipped  <name>  (the program extracts this type)`. For a PDF, read the bytes, hash them, and look at `staging/<sha256>/`. Before any work, remove every folder in `staging/` whose name is `.tmp-` or `.old-` followed by 64 lowercase hex digits: the command makes only those, and one found now is the leftover of a run that was killed. If `staging/<sha256>/` exists and passes the checks of `staged@1` (the original's hash, each page hash, the page count), print `kept` and go on. Otherwise call the extractor, which is `PdftotextLayout`, write the folder to `staging/.tmp-<sha256>/` with `write_extraction_dir`, and read it back through `staged@1`. If a final folder exists and failed its checks, rename it to `staging/.old-<sha256>/` now (a rename onto a folder that is not empty fails on every system, which is why it is moved aside), rename the temporary folder to `staging/<sha256>/`, and remove the old one; if that rename fails, rename the old folder back. A failure at any point removes the temporary folder and leaves the final folder as it was found, damaged or absent.
4. Tool checks, as `extract` does them. A missing `pdftotext` exits 3 with its name; a `tool_version` that differs from the `[poppler]` pin of `.config/tools.toml` is a warning, as in `extract`: one line on standard error names both versions, the run goes on, and `extraction.toml` records the version that was used as `tool_version`. A PDF that `pdftotext` rejects (encrypted, damaged, zero pages) prints `failed    <name>  pdftotext exit N` and the run goes on; the final exit code is then 1. An image-only PDF is staged with every page thin and its line says so.
5. The report. One line for each file: `staged    <first 12 hex>  <name>  12 pages, 1 thin`, `kept      <first 12 hex>  <name>`, `skipped   <name>  (...)` or `failed    <name>  <reason>`, then `done: 2 staged, 1 kept, 1 skipped` with zero counts left out. Exit 0 when nothing failed, 1 when a file failed, 2 for a usage error and 3 for a missing tool or an I/O error. The command writes nothing under `corpus/` and appends no journal event: staging is derived text, and the proposal that uses it is journaled by `add --propose` (`queue.propose` records the extraction adapter and hashes).
6. `--propose [--confirm-public]`. After staging, even when a file failed, run `cargo run -q --locked -p fieldbook -- --state <state> add <dir> --propose` (with `--recursive` and `--confirm-public` when given) through the runner of step 3, passing its output through. `--confirm-public` is only passed on: it is the act of `add` that gives `public`, so without it `add` refuses each Corpus file (FB0410) and `stage` shows those lines, and `--confirm-public` without `--propose` is a usage error (exit 2). A PDF that failed to stage is proposed with no extraction, and `add --propose` prints FB0825 for it. The exit code is the larger of the two. `stage` never runs `queue accept`, and it does not read the proposal files. `add` finds the Corpus by walking up from the working directory (`check-command`), so the runner starts it in the folder that `xtask` was started in, which is the repository, and the person runs `queue show` from there too.
7. `main.rs` registers the subcommand. Tests in `mod tests` of `stage.rs` (`xtask` is a binary crate, so a file in `xtask/tests/` could not call `stage`), with a scripted extractor and a `ScriptedRunner { replies: Vec<RunOutput> }` (it returns its replies in order and records each program, its arguments and its working directory), so they run in CI without poppler: `stages_pdfs_in_byte_order`, `non_pdf_is_skipped_with_a_reason`, `folder_outside_the_inbox_is_a_usage_error`, `recursive_walks_subfolders`, `existing_valid_staging_is_kept`, `damaged_staging_is_written_again`, `a_failed_replacement_leaves_the_damaged_folder_as_it_was` (a local writer fault fires after a page write following successful extraction while a damaged final folder exists: the folder is back under its name, byte for byte, and no `.tmp-` or `.old-` folder remains), `leftover_temporary_folders_are_removed_first` (a `.tmp-` and an `.old-` folder with 64-hex names are removed; a folder called `.tmp-notes` and a file called `.old-` and 64 hex digits are left alone), `propose_keeps_the_working_directory` (the scripted runner records the working directory it was given for `add`: the one `xtask` was started in, and not the inbox), `same_input_same_staging_bytes`, `staging_is_written_whole_or_not_at_all` (an extractor that fails after the second page leaves no folder), `staging_is_read_back_by_staged_1`, `extraction_toml_keys_are_in_the_documented_order`, `thin_pages_are_listed`, `pdftotext_missing_exits_3`, `tool_version_off_the_pin_is_a_warning` (the scripted runner reports a `pdftotext` version that differs from the pin: the exit code is 0, standard error holds one line that names both versions, and `extraction.toml` holds the version the runner reported), `failed_pdf_does_not_stop_the_folder`, `propose_runs_add_after_staging_with_the_same_dir`, `propose_exit_is_the_larger`, `stage_passes_confirm_public_to_add` (the recorded `add` call holds `--propose --confirm-public` when the flag is given and no `--confirm-public` when it is not), `confirm_public_without_propose_is_a_usage_error` (exit 2, nothing staged and no call) and `state_intake_matches_the_writer` (it takes the inbox file of `tests/fixtures/state-intake/` and constants for the page texts and for the header values `tool`, `tool_version` and `method`, builds a scripted `Extraction`, writes `staging/<sha256>/` with `write_extraction_dir` (the `tool` and `tool_version` constants are its two string arguments) in a temporary folder and compares it byte for byte with the fixture's staging folder; on a difference it leaves the rebuilt folder in `target/state-rebuilt/state-intake` and fails with a diff). Marked `#[ignore]` like the other poppler tests, and run at home: `real_pdf_stages_two_pages`, `blank_page_is_thin` (both on the fixtures of `extract-and-locators`) and `stage_then_propose_gives_a_proposal_with_page_quotes`, which builds the program, stages the two-page fixture, runs `add --propose --confirm-public` and checks `queue show --json`: the extraction has adapter `staged@1`, method `pdftotext-layout` and two pages. The ordinary `queue show` first line reads `2 pages, 0 thin`; there is no extraction line.

8. Use a small local `xtask` test seam, not a shared file-operations abstraction: inject a page-write failure after successful extraction, and separately a one-shot temporary-to-final rename failure after the damaged directory moved aside. Assert each fault was reached, restoration preserves every original byte and temporary directories disappear. Also test an initially absent destination. Direct final-directory writes and missing rollback must fail these respective tests.

## Acceptance

```sh
cargo nextest run --locked -p xtask stage:: extract::
cargo nextest run --locked -p xtask stage:: --run-ignored only
cargo build -q --locked -p fieldbook && B="$PWD/target/debug/fieldbook" && T="$(mktemp -d)" && S="$T/state" && mkdir -p "$S/inbox" && cp xtask/tests/fixtures/synthetic-two-pages.pdf "$S/inbox/two-pages.pdf" && printf 'role = "lead"\n' > "$S/settings.toml"
cargo xtask stage "$S/inbox" --state "$S" --propose --confirm-public; echo "exit $?"
cargo xtask stage "$S/inbox" --state "$S"; echo "exit $?"
ls "$S/staging"/*/
"$B" --state "$S" queue show P-0001
"$B" --state "$S" queue show P-0001 --json | grep -o -e 'staged@1' -e 'pdftotext-layout' | sort -u
just check
```

Expected: the tests pass, the ignored ones at home where `pdftotext` is installed; the first `stage` prints `staged` for `two-pages.pdf` with `2 pages, 0 thin`, then the lines of `add --propose` (`proposed  P-0001  new_source  two-pages.pdf` and `done: 1 proposed`), and `exit 0`; the second prints `kept` and `exit 0`; `ls` shows `extraction.toml`, `p0001.txt` and `p0002.txt`; `queue show` prints `2 pages, 0 thin` in its first line; the `--json` line prints `pdftotext-layout` and then `staged@1`; `just check` exits 0. Remove the temporary folder afterwards.

## Negative control

In the temporary folder, change one byte of `p0001.txt` under `staging/` and run `cargo xtask stage "$S/inbox" --state "$S"` again: it must print `staged`, not `kept`, and the byte must be back. On the branch, write the final folder directly with no rename: `staging_is_written_whole_or_not_at_all` must fail. Restore it. Skip the read-back through `staged@1`: `staging_is_read_back_by_staged_1` must fail. Restore it. Make the pin check an error again, so that a `pdftotext` version off the pin exits 3: `tool_version_off_the_pin_is_a_warning` must fail. Restore it. Write `[pages]` before `page_count`: `extraction_toml_keys_are_in_the_documented_order` and the goldens of `extract` must fail. Restore it. Then run `add --propose` before staging: `propose_runs_add_after_staging_with_the_same_dir` must fail. Restore it. Rename the staged folder onto the damaged one without moving that one aside: `damaged_staging_is_written_again` must fail. Restore it. Skip the move back after a failed rename: `a_failed_replacement_leaves_the_damaged_folder_as_it_was` must fail. Restore it. Skip the removal of leftovers: `leftover_temporary_folders_are_removed_first` must fail. Restore it. Then change one character of a page text that `state_intake_matches_the_writer` holds: it must fail and leave the rebuilt folder in `target/state-rebuilt/state-intake`. Restore it. Leave `--confirm-public` out of the `add` call: `stage_passes_confirm_public_to_add` must fail. Restore it. Let `--confirm-public` pass without `--propose`: `confirm_public_without_propose_is_a_usage_error` must fail. Restore it. Last, start `add` in the inbox folder instead of the caller's folder: `propose_keeps_the_working_directory` must fail.

## Rollback

Revert the merge commit. `xtask stage` goes and `extract` is split back into one function with identical output. Staging folders already written stay in the state folder as untracked files, and `add --propose` reads them as before, because it never depended on this command. Nothing in the Corpus or an edition changes.

## BLOCKED

`xtask` cannot call the checks of `staged@1`, because the adapter is not reachable through the path edge to `fieldbook` that `ai-kernel` gave `xtask`. Set the item to Blocked with `BLOCKED: xtask cannot reach staged@1`, and stop. Do not write a second reader of the staging format in `xtask`.
