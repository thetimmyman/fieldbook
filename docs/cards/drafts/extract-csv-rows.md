# extract-csv-rows

- **Runs where:** home, CI Linux
- **Schema impact:** none
- **Review:** auto

## Outcome

A table saved as CSV can be extracted, cited and checked. `cargo xtask extract <version-id>` on a version whose original is a CSV file writes `sources/text/<version-id>/` with one text file per window of 50 data rows, each starting with the header line, and an `extraction.toml` with `method = "csv-rows"`, `unit = "window"`, `window_rows`, `row_count` and `values = "as-written"`. A claim cited at `rec N` resolves to data row N: `check` raises FB0311 when the table has no such row and FB0308 when the claim's quote is not in that row's text. The method is the `csv-rows@1` extractor, registered with the other three, and the company device calls the same extractor (`r2-pull-and-sync`, `r2-org-intake`). A table that came from a workbook saved as CSV can say so with `values_only = true`: this card owns the key and its one sentence, and `r2-pull-and-sync` writes it.

## Why

- The method, the windows, the `rec` arithmetic, the keys of `extraction.toml` and FB0311 are in [Extraction](../../reference/corpus-format.md#extraction) and the [Check catalogue](../../reference/corpus-format.md#check-catalogue). The place of the method in the company design is [ADR 0004, section 9](../../decisions/0004-company-boundary.md#9-provenance-extraction-and-records).
- Today a `rec` or `sheet` locator is accepted and never read. A claim that says "unit price 41.20 at rec 213" is then checked by nobody, and a price list or a transaction export is exactly the kind of source a bid rests on. This card makes the quote meet the row it names.
- A spreadsheet's CSV is not a register. `schema::table::read` is strict on purpose (it refuses a ragged row and a line break in a cell), so this card has its own lenient reader and does not touch the register reader.
- The windows are arithmetic and not an index: the window of row N is `ceil(N / window_rows)` and its line is `((N - 1) mod window_rows) + 2`, so nothing is stored per row, and each window file is hashed with the rest of the extraction.
- A table is cut or refused, never quietly truncated: over 100,000 data rows, over 32 MiB, or over 9,999 windows is `TooLarge`. The original is still kept and cited by hash, and the Later row `later-dataset-tier` names the trigger.
- Only values reach the text. CSV holds no formula and no macro, so this method reads nothing that can run. A workbook that a system exports as a workbook is read by `xlsx-sheets` (`extract-xlsx-sheets`); this method serves the systems that export CSV only.
- Values on display are not values stored. A workbook saved as CSV carries what the screen showed: with manual calculation on, or a stale cached cell, a figure can disagree with its formula and nothing in the file says so (R-13). The extractor reads bytes and cannot know, so a caller that does know sets `values_only`, and the key travels with the extraction to every place that shows the text. The failure it prevents: a quoted price is trusted as if a formula stood behind it.
- Extraction output carries the labels of its original (the union rule of [ADR 0004](../../decisions/0004-company-boundary.md#2-labels)). The extractor reads bytes and returns text, sends nothing and takes no token.
- Design: the [MAP.md](../../design/MAP.md#routes-and-components) row "Source drawer", for the label of a window in LocatorView. The label text is a request to the interface lane (`docs/design` is theirs); this card sets the string in `source.rs` and changes no template or token.

## Out of scope

- Workbooks (`xlsx-sheets`, card `extract-xlsx-sheets`) and cached values (`values = "cached"` belongs to that method and is refused for `csv-rows`).
- A delimiter other than a comma, and the encodings other than UTF-8 and UTF-16 with a byte-order mark. The message is "save as CSV UTF-8".
- A dataset tier for ledger-scale tables (`later-dataset-tier`).
- Search units for the windows of a company source version (the search reference, "Text windows") and the call of this extractor from `sync` and company intake (`r2-pull-and-sync`, `r2-org-intake`).
- A change to quote normalisation, to the register reader, or to any extraction already committed. A page extraction stays byte-identical.

## Steps

1. Decoding, `extraction/csv_rows.rs`: `decode(bytes) -> Result<String, ExtractError>`. UTF-8 with or without a byte-order mark, and UTF-16 (either order) only with a byte-order mark, are text. Anything else is `ExtractError::NotText`: bytes that are not valid UTF-8 and carry no UTF-16 mark, a NUL byte in UTF-8 text, an unpaired surrogate. Tests: `utf8_is_read`, `utf8_bom_is_stripped`, `utf16_le_with_bom_is_read`, `utf16_be_with_bom_is_read`, `utf16_without_bom_is_not_text`, `windows_1252_bytes_are_not_text`, `a_nul_byte_is_not_text`, `an_unpaired_surrogate_is_not_text`.
2. Parsing, the same file: `parse(text) -> Result<Vec<Vec<String>>, ExtractError>`, comma-separated. A row ends at CRLF, LF or CR; a final line break ends the last row and starts none; a blank line is a row of one empty cell. A cell in double quotes may hold a comma, a quote written twice, and a line break; a double quote inside an unquoted cell, or text after a closing quote, is kept as written. Rows may have different cell counts and are not padded. A quote that is never closed is `ExtractError::Missing("closing quote")`: the rest of the file is never swallowed into one cell. Tests: `crlf_lf_and_cr_end_rows`, `quoted_cell_may_hold_a_comma_and_a_line_break`, `a_doubled_quote_is_one_quote`, `a_stray_quote_in_an_unquoted_cell_is_kept`, `text_after_a_closing_quote_is_kept`, `ragged_rows_are_kept`, `a_final_line_break_adds_no_row`, `a_blank_line_is_a_row`, `an_open_quote_is_missing`.
3. Windows, the same file: `CsvRows::new(window_rows)` with `WINDOW_ROWS = 50` as the default, an `Extractor` with `id()` `csv-rows@1` that accepts the extension `csv` in any case. Row text is its cells in file order separated by one tab, with each tab, CR, LF or CRLF inside a cell written as one space; the header is row 1 and is not a data row. Window i (from 1) is the file `p000i.txt`: the header line, then up to `window_rows` data row lines, each ending in a line feed. A header-only table has `row_count = 0` and one window that holds the header. An empty input has no header and is `ExtractError::Missing("header row")`. The returned `Extraction` gains `table: Option<TableMeta { window_rows, row_count, values_only }>`, which is `None` for every other method (`values_only` is false as the extractor returns it, because the extractor reads bytes and knows nothing of where they came from). `TableMeta` derives `Debug, Clone, PartialEq, Default`, and `Values` (step 4) derives `Default` with `AsWritten` as the default. Every construction of a `TableMeta` outside `extraction.rs`, in `csv_rows.rs` and in tests, ends in `..TableMeta::default()` or reads single fields, so a card that adds a field edits `extraction.rs` only. Limits, as consts: `MAX_DATA_ROWS = 100_000`, `MAX_BYTES = 32 MiB` and `MAX_WINDOWS = 9_999` (the four-digit file stem), each `ExtractError::TooLarge`. Tests: `a_table_of_120_rows_makes_windows_of_50_50_20`, `every_window_starts_with_the_header`, `row_count_excludes_the_header`, `a_header_only_table_has_one_window_and_no_rows`, `tab_and_line_break_in_a_cell_become_one_space`, `crlf_in_a_cell_is_one_space`, `an_empty_input_has_no_header`, `more_than_100000_rows_is_too_large`, `more_than_32_mib_is_too_large`, `more_than_9999_windows_is_too_large`, `same_input_same_output`, `utf16_and_utf8_give_the_same_text_files`, `table_meta_default_is_empty` (every field of `TableMeta::default()` is 0, false or empty, and `Values::default()` is `Values::AsWritten`), `random_and_mutated_bytes_never_panic` (the file includes the generator with `#[cfg(test)] #[path = "../../../../tests/support/rng.rs"] mod rng;` and writes it nowhere else (`one_rng_exists`); the test takes 1 MB from `Rng::new(1).bytes(1 << 20)` and builds 200 byte strings of length 0 to 512 from the same generator, and takes `original.csv` and `original-utf16.csv` of `tests/fixtures/extract/csv-rows/`, each cut at 512 bytes, with each of its bytes once flipped and once deleted; each goes through `decode`, `parse` and `CsvRows::extract`, and the result is a value or a typed error and never a panic; 200 strings of 0 to 16 bytes from the generator also go to `resolve` of step 6 as a key, with the same rule).
4. Keys, `extraction.rs` and `extraction/methods.rs`: `ExtractionToml` gains `unit` (`Unit::{Page, Window}`, `Page` when the key is absent), `window_rows`, `row_count`, `values` (`Values::{AsWritten, Cached}`) and `values_only` (a boolean; absent means false). `values_only` is written as `values_only = true` and never as `false`, so each meaning has one spelling, and the writer takes it from `TableMeta.values_only`, which a caller sets (`r2-pull-and-sync` sets it for a stream saved from a workbook). `values_only_note(&ExtractionToml) -> Option<&'static str>` returns `Some("values only (saved from a workbook)")` when the key is true and `None` otherwise: it is the one place that holds the sentence, and the source page, the review queue and the title of a text window call it. The writer leaves all five out for a page extraction, so no committed extraction changes by a byte. Append the row `csv-rows` to `METHODS` (types `csv`, locator `rec`, keys `unit`, `window_rows`, `row_count`, `values`, `values_only`, extractor `csv-rows@1`, fixture `tests/fixtures/extract/csv-rows/`) and one line to `tests/golden/extract/methods.txt` in the form that file uses. Tests: `window_keys_round_trip`, `unit_defaults_to_page`, `values_only_round_trips`, `values_only_is_written_only_when_true`, `values_only_note_has_one_sentence` (it returns the sentence above for a table that says `values_only = true` and `None` otherwise), `a_page_extraction_is_written_without_the_new_keys` (the `corpus-mini` extraction is unchanged), `random_and_mutated_extraction_toml_never_panics` (the same generator; the test takes `tests/fixtures/extract/csv-rows/expected/extraction.toml` with each of its bytes once flipped and once deleted, and each goes through `ExtractionToml::parse`: a value or a typed error, never a panic), and the two existing drift tests `methods_only_grow` and `methods_match_extractors` must pass with the new row.
5. Integrity, `check/extraction.rs`: for `unit = "window"` the pass requires, as FB0212, that the method is `csv-rows`, `window_rows` is at least 1, `row_count` is set, `values` is `as-written`, `page_count` equals `max(1, ceil(row_count / window_rows))`, `thin_pages` is empty, and each file holds the header line plus the right number of row lines (window i has `min(window_rows, row_count - (i - 1) * window_rows)`; a text file ends in one line feed). `values_only` is accepted only as `true` and only with `unit = "window"`: `values_only = false`, or the key on a page extraction or on a method other than `csv-rows`, is FB0212. The hashes, `original_sha256` and the file list are checked as for any extraction. Tests: `a_matching_window_extraction_passes`, `a_wrong_page_count_for_window_rows_is_fb0212`, `a_window_with_a_missing_row_line_is_fb0212`, `a_window_with_an_extra_row_line_is_fb0212`, `thin_pages_must_be_empty_for_windows`, `window_unit_with_another_method_is_fb0212`, `values_cached_on_csv_rows_is_fb0212`, `a_missing_row_count_is_fb0212`, `values_only_true_on_a_window_extraction_passes`, `values_only_false_is_fb0212`, `values_only_on_a_page_extraction_is_fb0212`.
6. Resolution, `extraction/csv_rows.rs`: `resolve(&ExtractionToml, key: &str) -> Result<RecAt, RecError>` with `RecAt { n, window, line }`. The key is `[1-9][0-9]*`, one spelling for each row; `0`, a sign, a leading zero, a range, a decimal or any other text is `RecError::NotARow`; `n > row_count` is `RecError::Beyond { n, row_count }`. `quote::locator_resolves` gets the `rec` arm: for a `record_key` locator on a version whose method is `csv-rows` it calls `resolve` and returns FB0311 on `Err`, so `check`, `new claim` and `cite_check` read one rule. A valid table locator returns `Ok(None)`; no document-range match is attempted. `check/quotes.rs` takes the `RecAt` from `resolve` and looks for the claim's nonempty quote in the one line `line` of window file `window`, after the normalisation of Extraction, and raises FB0308 when it is not there. Every other combination is as before: a `rec` or `sheet` locator on a version with another method, or with no extraction, is accepted and not read. `new claim` reaches `resolve` through `check::quotes::match_claim` of `quote-match-and-anchors`, so `new.rs` is not edited. `assist::cite_facts` fills `tables` for a `csv-rows` version with one `TableFact { sheet: None, rows: row_count, columns: None }`, so `cite_check` and the Assistant page call a `rec` beyond `row_count` `broken_locator`. Tests, in `check::quotes::`: `rec_resolves_to_its_window_and_line` (rows 1, 50, 51, 100, 101 and the last, for `window_rows` 50 and for 7), `rec_zero_is_fb0311`, `rec_beyond_row_count_is_fb0311`, `rec_with_a_non_number_is_fb0311`, `rec_with_a_sign_a_leading_zero_or_a_range_is_fb0311`, `quote_in_the_row_matches`, `quote_from_another_row_is_fb0308`, `quote_across_two_cells_matches_with_a_space`, `quote_in_the_header_is_not_a_row`, `rec_on_a_plain_text_version_is_not_read`, `sheet_on_csv_rows_is_not_read`. In `crates/fieldbook/tests/new.rs`: `new_claim_at_rec_matches_the_row` and `new_claim_refuses_a_rec_beyond_row_count` (exit 1, nothing written). In `crates/fieldbook-core/tests/csv_rows.rs`: `cite_check_rec_beyond_row_count_is_broken_locator` (a copy of `corpus-mini` whose one source version carries the extraction of `tests/fixtures/extract/csv-rows/expected/`: `cite_facts` gives one `TableFact` with `rows` 120, and `cite_check` of an answer that cites that version at `rec 120` is not `broken_locator` and at `rec 121` is). A `check --strict` that follows `new claim` in these tests passes `--today` the date the verb stamped, which is the date of the scripted clock (the README date rule for a sequence that follows a stamping verb).
7. Extraction run, `xtask/src/extract.rs`: add the `csv` arm to `extraction::select`, which returns `CsvRows` with the default window, and append `csv` to `SELECT_TYPES` and to `TEXT_TYPES` of `add.rs` (the test `text_types_equal_the_extractor_list` of `extract-and-locators` must pass with both lists equal). `extract` writes the files, `[pages]`, `page_count`, the table keys and `original_sha256`, with the `tool` and `tool_version` that the other core extractors write. A rerun on the same original with an existing `csv-rows` extraction keeps its `window_rows`. A refused original (`NotText`, `Missing`, `TooLarge`) writes nothing, prints `csv-rows@1: <reason>` (for `NotText`, "not text; save as CSV UTF-8") and exits 1. Tests, in `mod tests` of `xtask/src/extract.rs`: `csv_is_cut_into_windows` (the fixture's expected files, byte for byte), `a_utf16_csv_gives_the_same_text`, `rerun_keeps_window_rows`, `a_csv_that_is_not_text_writes_nothing_and_exits_1`, `a_table_over_the_limit_writes_nothing`. They build a temporary corpus from `corpus-mini` plus the fixture original, a version row for it (with its `sha256`) and one claim at `rec`, so the same tree also runs `check --strict --today <D>` in `csv_extraction_passes_check`, where `<D>` is the content of the `TODAY` file that the copy of `corpus-mini` holds (the README date rule for a fixture copy; the tests write the version row and the claim themselves and run no stamping verb).
8. Source page, `crates/fieldbook-render/src/source.rs`: the LocatorView label of a text file is `p. The cited row's line gets the same `<mark>` as a cited passage. When `values_only_note` is `Some`, the label reads `rows A to B; values only (saved from a workbook)` (the sentence of the note joined by a semicolon), so a reader of the source page sees it beside the text. No template, style rule or token changes. Tests in `tests/source.rs`: `window_extraction_is_labelled_by_rows`, `a_values_only_window_label_carries_the_note` and `a_window_label_without_the_key_has_no_note`.

- Drop the `n > row_count` test: `rec_beyond_row_count_is_fb0311` must fail.
