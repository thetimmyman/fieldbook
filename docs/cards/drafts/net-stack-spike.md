# net-stack-spike

- **Runs where:** home, CI Linux, CI Windows
- **Schema impact:** none
- **Review:** owner

## Outcome

`UreqHttp` in `crates/fieldbook/src/io/net.rs` implements `HttpPost` over `ureq`, `rustls` and the pure-Rust `rustls-graviola` provider, behind the Cargo feature `net`, with server certificates checked against the operating system's store. That store is the company's: it holds the roots IT installs, including the root of a TLS-inspecting gateway, so a later connector to a company data source (`later-company-source-read`) and the model endpoint use one transport and one trust decision, and the answer here covers both. The card ends with a measured answer for Linux and for Windows: go, go with schannel on Windows, or no-go. `deny.toml` holds the wrapped-crate rules, `dependencies.md` has the three rows out of "proposed" and the first AI-profile rows in Measurements, `os_random` gives the Bridge its token bytes from the operating system without a crate of its own (or with one row, if step 14 chooses the crate), and the silent build's graph is shown to hold none of the three crates. A no-go is a finished card: it records what failed and keeps `ask` over Handoff.

## Why

- A model endpoint needs TLS, and so will a connector that reads a company data source (`later-company-source-read`); the only stack that adds no C to the build graph is rustls with the graviola provider and the platform verifier ([AD-01](../../decisions/0001-foundation.md#ad-01-architecture), [AD-18](../../decisions/0001-foundation.md#ad-18-security-and-confidentiality-guardrails)). It is the first network dependency the project takes, so the owner approves it at the release [gate](../../decisions/0001-foundation.md#gates) and no adapter uses it before this card has merged. `deny.toml` is edited only here.
- Four things are claimed and not yet shown: graviola builds and completes a handshake on Windows (MSVC), the CPU features it needs are common on the runners and on the laptop, `ureq` reads the proxy variables as the design says, and the executable stays under 50 MB (NFR-F-10). The transitive counts (silent 63, AI 87 on the two graph targets, 106 for `--target all`) were measured on a probe and are repeated here; a tree that has `extract-xlsx-sheets` adds about nine crates to each count (72 and 96). This card measures them and reports the result either way. A claim marked [S] is one of these: the spike has not shown it, and the text beside it says what to do if it does not hold (a count marked [S] is replaced by the measured one in the result).
- The test certificates are made at run time in a temporary folder and never committed. The secret scanner has no allowlist, and a private key in the repository would be a finding. The CA is added to a runner's store only when `CI` is set, so no developer machine is changed. The test CA stands in for a company root: the program trusts it only because the operating system's store does, no setting or file of the program names a root, and a company that installs its root in the store (or whose gateway re-signs traffic with that root) needs nothing from Fieldbook.
- The Day-30 cut order puts this card last, together with `model-adapter-openai`. Cutting both leaves `net = []` and Handoff only; nothing built earlier depends on them.
- No page, template or string shown in a browser is built here, so there is no Design bullet.

## Steps

1. Pins. In the root `Cargo.toml` add to `[workspace.dependencies]`: `ureq` (`default-features = false`, features `rustls-no-provider` and `platform-verifier`), `rustls` (`default-features = false`, features `std`, `tls12`, `custom-provider`) and `rustls-graviola`, each at the caret form of the pin in `dependencies.md`. In `crates/fieldbook/Cargo.toml` declare the three with `optional = true` and `workspace = true`, and change `net = []` to `net = ["dep:ureq", "dep:rustls", "dep:rustls-graviola"]`. Do not add `net` or `bridge` to `default`; whatever `default` holds is left as it is. Run `just lock` once. The lock decides the real pins; if it picks a release other than the table's, the table and the manifest follow the lock. `rustls-platform-verifier` is not named anywhere: it comes through `ureq`.
2. `deny.toml`. Replace the network block of the bans with these entries: `tokio`, `reqwest`, `hyper`, `curl` and `native-tls` banned; `ureq` with `wrappers = ["fieldbook"]`; `rustls` with `wrappers = ["ureq", "rustls-graviola", "rustls-platform-verifier", "fieldbook"]`; `ring`, `aws-lc-rs`, `aws-lc-sys` and `openssl` banned by name. `cc` keeps `wrappers = ["embed-resource"]`, and `cmake`, `bindgen`, `pkg-config`, `openssl-sys` and `libsqlite3-sys` stay. Rewrite the comment above the block as the one-line reason in `dependencies.md`. Read the `rustls` wrapper list from `cargo tree -p fieldbook --features net -i rustls --edges normal --target all` instead of trusting the list above: the direct parents it shows must be those four names. Run `cargo deny --locked check bans licenses sources` with default features and with `--all-features`.
3. `xtask/src/graph.rs`. `BANNED` loses `ureq` and `rustls` and gains `ring`, `aws-lc-rs`, `aws-lc-sys` and `openssl`. A table `WRAPPED` holds the two wrapped crates and their allowed parents, and a new rule reports any parent of a wrapped crate that is not in its list, with a sentence naming the parent. Unit tests on synthetic metadata: `wrapped_crate_under_an_allowed_parent_is_accepted`, `ureq_under_fieldbook_core_is_rejected`, `rustls_under_an_unlisted_crate_is_rejected`, `ring_is_rejected_by_name`. The test that runs the rules over this workspace runs twice: with default features it also asserts that `ureq`, `rustls`, `rustls-graviola` and `rustls-platform-verifier` are absent from the graph, and with `--features fieldbook/net` it asserts that the rules pass. This is the metadata test per profile that NS-01 names.
4. `io/net.rs`, `UreqHttp`, under `#[cfg(feature = "net")]`. `UreqHttp::new(proxy: ProxyMode)` with `ProxyMode::{Env, None}` builds one agent: rustls with the graviola provider, the platform verifier as the only source of roots, no bundled roots, zero redirects, 4xx and 5xx statuses returned as replies and not raised as errors. There is no setting, argument or code path that turns certificate checks off. `post` takes the timeout from the request, refuses before any connection a URL whose scheme is not `https` unless it is `http` to `127.0.0.1`, `[::1]` or `localhost`, reads at most `max_reply_bytes` plus one byte (the extra byte gives `HttpError::TooLarge`), and reads `Retry-After` as whole seconds when it is a number. Every `ureq` error is mapped to an `HttpError` variant by matching its kind, never by formatting it, so that no header value and no URL query reaches an error string. A certificate that is untrusted, expired or for another host is `HttpError::Tls`. For HTTPS, `ProxyMode::Env` uses the proxy variables `ureq` reads and `ProxyMode::None` disables them, with certificate verification preserved. Permitted loopback HTTP always connects directly, bypassing every proxy regardless of ProxyMode or NO_PROXY; its plaintext body and auth header must never travel to a proxy.
5. `cpu_ok()` gets its body. A pure function `required_features_present(has: &dyn Fn(&str) -> bool) -> bool` checks the list that the pinned graviola documents (starting from AES, SSSE3, AVX, AVX2, ADX, BMI2 and PCLMULQDQ on x86-64, and the aarch64 equivalents) [S: read the list from the pinned release and copy it into a comment]. `cpu_ok()` calls it with `is_x86_feature_detected!` or `is_aarch64_feature_detected!`, and returns false on any other architecture. Without the `net` feature it still returns true.
6. Tests without a server, in `tests/net_http.rs` (`#![cfg(feature = "net")]`): `http_to_a_remote_host_is_refused_before_connecting` (the host is `example.invalid`, so a connection attempt would fail with a different variant), `connection_refused_is_connect_and_shows_no_header_value` (port 1 on `127.0.0.1`; a `Secret` header holds a synthetic string and the `Debug` and `Display` text of the error must not contain it), `required_features_present_fails_when_any_one_is_missing` (table-driven, one flag false in turn) and `cpu_ok_is_true_on_this_machine` (ignored on a machine without the features, with the reason printed).
7. `xtask/src/net_spike/plain.rs`: a loopback server on `127.0.0.1` and a port the operating system picks, one thread per connection, with fixed routes: `/ok` (200 and a short JSON body), `/status/429` (with `Retry-After: 7`), `/status/503`, `/redirect` (302 to `/target`), `/big` (a 2 MiB body) and `/slow` (waits 3 s). It logs each request line and the header names, never the values. Tests in `tests/net_http.rs`, marked `#[ignore = "needs the endpoint of cargo xtask net-spike"]` and reading the address through `support/endpoint.rs`, which the test file declares with `#[path = "support/endpoint.rs"] mod endpoint;` as `policy-load` declares its `support/policy.rs`, so that `support/mod.rs` is not edited (the one function that reads the environment, with `#[expect(clippy::disallowed_methods, reason = "a test reads the endpoint that xtask started")]`): `post_returns_status_and_body`, `retry_after_is_read`, `status_429_and_503_are_replies`, `redirect_is_returned_and_not_followed`, `reply_over_the_cap_is_too_large` and `slow_reply_times_out_at_the_request_timeout`. After the run, `xtask` checks that the log holds no request for `/target`.
8. `xtask/src/net_spike/tls.rs`, `cargo xtask net-spike`. In a temporary folder it makes a test CA, a leaf for `localhost` signed by it, and a second self-signed leaf, with the `openssl` program (on `PATH`, or Git's under the Program Files folder on Windows), using ECDSA P-256 [S: the curve graviola verifies; use RSA 2048 if it does not, and say so]. It starts the POST-capable loopback TLS fixture managed by `xtask` twice on loopback ports it picked, one with each leaf. It runs `cargo nextest run --locked -p fieldbook --features net --run-ignored all --test net_http --test net_tls` with the addresses in the environment, and removes the folder and the servers on exit and on failure. Trust: on Linux the CA is given to the test as `SSL_CERT_FILE`, which the platform verifier reads on Linux [S]; if it does not, the job installs the CA with `update-ca-certificates`. On Windows the job runs `certutil -addstore -f Root` and removes the CA by thumbprint afterwards. `xtask` refuses both installs unless `CI` is set. The posts have an empty body, so the server has nothing unread when it closes. The helpers `make_certs` and `start_s_server` are `pub(crate)`, because `model-adapter-openai` starts the same self-signed server for its drill step.
9. `tests/net_tls.rs`, all `#[ignore]`, run by step 8 and declaring `endpoint` as step 7 does: `trusted_chain_completes_a_handshake` (`https://localhost:<port>/`, status 200), `self_signed_leaf_is_refused_as_tls`, `leaf_for_another_host_is_refused_as_tls` (the trusted leaf reached as `https://127.0.0.1:<port>/`) and `without_the_ca_the_trusted_chain_is_refused` (the same URL in a fresh child after the test CA has been removed from every trust source and its absence verified, so the chain is genuinely untrusted). Test HTTPS proxy behavior separately with local proxy/TLS fixtures and certificate verification, recording the variables ureq honors. `loopback_http_bypasses_every_proxy` tests 127.0.0.1, [::1] and localhost with an environment proxy listener configured and bypass variables absent: for Env and None the endpoint receives the POST and the proxy receives no connection. Use bounded local observers and restore the test environment afterwards.
10. `ci.yml`: a job `net` on `ubuntu-24.04` and `windows-2025`, with `timeout-minutes: 30`, the read-only token and the same pinned actions. It is gated by `changes` as the recipe "Adding a CI job" in [docs/cards/README.md](../README.md#adding-a-ci-job) says: `needs: [changes]`, and `if: needs.changes.outputs.code == 'true'` on every step after checkout. It has no job-level `if` and no path list, so it always finishes with success and `ci-ok` can read it. A change to `deny.toml`, `Cargo.lock` or a manifest is a code change for `changes`, so the job runs on every pull request that touches code and on every push to `main` that does, and its steps are skipped on a docs-only change. It runs `cargo xtask net-spike`, then in `bash` prints the measurements of step 11, and on Windows the DLL names from `dumpbin /imports` of the silent and of the AI executable (`dumpbin` is found with `vswhere`). Add `net` to the one-line `needs` of `ci-ok` (the test `ci_ok_needs_every_job` fails without it) and add this row to the table of [AD-08](../../decisions/0001-foundation.md#ad-08-ci-design), above the `ci-ok` row: "`net` | Builds the AI profile (`--features net`) on `ubuntu-24.04` and `windows-2025` and runs `cargo xtask net-spike`: the TLS cases against a local `openssl s_server`, the crate counts, the executable sizes and, on Windows, the import list. Needs `changes`; its steps run when `changes.code` is true (built by `net-stack-spike`)".
11. Measure, on Linux (home and CI) and on Windows (CI), and record in the work item. Counts: the command of "Counting crates" in `dependencies.md` without and with `--features net`; direct runtime crates per profile (the AI build adds exactly three direct crates to the silent build: `ureq`, `rustls` and `rustls-graviola`); `cargo xtask deps --check`. Size: `cargo build --locked --profile dist -p fieldbook` with and without `--features net`, the byte size of each executable. Add the rows to Measurements (one for each profile, the next row number, with the size in Notes), move the three rows out of "proposed" and fill their licence and minimum Rust version from the lock, set the Cap row to what was measured, and copy the observed proxy variable names, the stores the verifier read on each system and the Windows import list into `network-silence.md` section 5, which IT-30 reads for the endpoint and for a company data source. The cap of 100 applies to the `cargo xtask deps --check` figure on the two graph targets; the `--target all` figure is reported in Measurements and is not capped. If the AI count is above 100, say so in the pull request and in the Cap row; the owner decides at review.
12. The result. Go: nothing more. Go with schannel on Windows: if the handshake fails on Windows for graviola's own reason (not the store, the test or the runner), declare `ureq` for `cfg(windows)` with its `native-tls` feature instead, which uses schannel, let `native-tls` have `wrappers = ["ureq"]` in `deny.toml`; also remove its unconditional `xtask/src/graph.rs::BANNED` entry and add the matching permitted-parent rule, allowing it only through the Windows transport, move the graviola crates and the CPU check to `cfg(not(windows))`, repeat steps 8 to 11 on Windows, and say why in `dependencies.md` and NS-01 (about 66 transitive crates [S]). No-go: if neither stack works, remove the crates from the manifests and the lock, leave `net = []`, move the rows to the rejected-crates table with the failure, and keep `deny.toml` as it was; the endpoint adapter and the Bridge wait, and Handoff, the gate and `mcp` are unaffected. Each result is a finished card with the owner's review.
13. Controls. NS-01 names the wrappers as `deny.toml` has them and cites the metadata test per profile. NS-06 says that section 5 of `network-silence.md` lists the permitted imports.
14. The random source. The Bridge token needs 16 secret bytes from the operating system, and `chat-bridge` adds no crate and reads no device by hand for them. `io/net.rs` gets `pub fn os_random(buf: &mut [u8]) -> Result<(), RandomError>` under `cfg(feature = "net")`, where `RandomError` is a unit struct that holds no text. Choose its source in this order and write the choice and the reason in the work item and in the result of step 12: (a) a function of the standard library that fills bytes from the operating system, if the pinned toolchain has a stable one; (b) the `secure_random` of the pinned TLS provider (`rustls::crypto::SecureRandom::fill`), where the provider is in the graph and reads the system source on that operating system [S: read the provider's source for Linux and for Windows]; (c) the `getrandom` crate, whose row this card adds to `dependencies.md` in the same pull request (it would be a fourth direct crate that the AI build adds, beyond the three of step 1, and it counts toward the budget in `dependencies.md`). `std::hash::RandomState` is not a source: its keys are per process and are not a secret. The Windows build must have a source too; if (a) and (b) give none there, (c) is the answer for both systems. In `tests/net_http.rs`, with no server and not ignored, so that both runners run it: `os_random_fills_16_bytes_and_two_calls_differ` (two buffers of 16 zero bytes; after two calls neither is all zero and they differ). In a no-go result (step 12) keep `os_random` only if source (a) or (c) works without the TLS crates; otherwise the Bridge waits with the endpoint adapter, as the result says.

15. Serialize trust-store phases. First run untrusted-chain cases with the CA absent. Then install the unique test CA and run trusted/host-mismatch cases. Remove it by thumbprint on Windows or its unique file plus update-ca-certificates on Linux, verify its absence, start a fresh process, and run without_the_ca_the_trusted_chain_is_refused. Changing SSL_CERT_FILE alone is insufficient after a system-store install. A cleanup guard runs removal and verification on success and failure; cleanup failure fails the job. No other test mutates this trust store concurrently. The scripted xtask tests assert install/run/remove/verify/run order and cleanup on every failure.

16. The shared loopback TLS fixture observes a POST and returns HTTP 200 in the trusted case; certificate-refusal cases retain isolated trust setup and cleanup. The endpoint adapter reuses this helper. A GET-only server must fail the trusted POST test. A go result retains the measured transport and its checks. For no-go, remove the prototype, dependency-consuming tests and job wiring; restore applicable dependency and graph rules, `ci-ok` and the network decision text. Record measured rejection in the existing rejected-crate table and the owner’s tracker. Keep `os_random` only with the independent source condition in step 14. The no-go acceptance path checks the silent build and Handoff and keeps endpoint and Bridge deferrals; network-success assertions apply only to go. Both paths end with `just check`.

17. If the schannel fallback is selected, test the actual metadata graph with a permitted Windows transport and a forbidden parent. Both deny.toml and graph.rs enforce the same dependency path; removing the graph parent restriction must fail the forbidden-parent fixture.

## Acceptance

For a go result:

```sh
cargo build --locked -p fieldbook --features net
cargo nextest run --locked -p fieldbook --features net --test net_http
cargo nextest run --locked -p xtask graph::
cargo xtask net-spike
cargo deny --locked check bans licenses sources
cargo deny --locked --all-features check bans licenses sources
cargo tree --locked -p fieldbook -i ureq; echo "exit $?"
cargo xtask deps --check
just check
```

Expected: the build and the tests pass; `net-spike` prints `net-spike: ok` and lists the tests it ran, including the four TLS cases; both `cargo deny` runs pass; the `cargo tree` line prints that `ureq` matches no package and `exit 101`, which shows that the silent build's graph does not hold it; `deps --check` and `just check` exit 0. The pull request's `net` job is green on both runners, its log shows the counts and sizes of step 11, and the AI executable is under 50 000 000 bytes. `net-spike` removes its temporary folder, with the test CA and its key, on exit.

For a no-go result, after the cleanup above, run instead:

```sh
cargo build --locked -p fieldbook
cargo nextest run --locked -p fieldbook --test ask --test contract_handoff --test ns07_ask --test adapters
cargo nextest run --locked -p xtask graph::
cargo xtask deps --check
cargo deny --locked --all-features check bans licenses sources
cargo xtask cards --check
just check
```

Expected for no-go: silent and Handoff tests pass; removed network tests/jobs are not referenced by `ci-ok`; dependency and graph checks match the restored build. The rejected-crate table retains measured failure evidence. No network-success assertion applies.

## Negative control

On a scratch branch add `ureq` to `crates/fieldbook-core/Cargo.toml`: `cargo deny check bans` and the graph test must both fail, naming the parent. Revert. Set the agent's redirect limit to 5: `redirect_is_returned_and_not_followed` must fail, and `xtask` must report a request for `/target`. Revert. Make `required_features_present` ignore the last flag: its table test must fail. Revert. Change the actual active trust sources as steps 9 and 15 specify, verify absence and use a fresh child. Deliberately retain the generated test CA in `UreqHttp` after removing it from the test trust source: `without_the_ca_the_trusted_chain_is_refused` must fail. Revert. Last, make `os_random` return without touching its buffer: `os_random_fills_16_bytes_and_two_calls_differ` must fail.

Leave the CA installed before the final negative phase: `without_the_ca_the_trusted_chain_is_refused` must fail. Restore it.

Remove the direct-loopback HTTP bypass: `loopback_http_bypasses_every_proxy` must fail because the proxy sees a connection or the endpoint receives nothing. Restore it; keep HTTPS certificate tests enabled.

## Rollback

Revert the merge commit. `net` goes back to `net = []`, `UreqHttp`, `os_random` and `cpu_ok`'s body leave, `deny.toml` bans `ureq` and `rustls` again, the rows go back to "proposed", and `Cargo.lock` loses the crates. The silent build never changes, because the feature is off by default. Revert `model-adapter-openai` and `chat-bridge` first if they have merged. Cutting the card at Day 30 moves it to P5 unchanged.

## BLOCKED

`just lock` cannot resolve the three crates at the cooldown, `cargo deny check licenses` names a licence outside the allowlist (the one to watch is `webpki-roots`, which `ureq` may pull in through its TLS features), the tree shows a parent of `rustls` that the wrapper list does not name, or a runner has no `openssl` or cannot add the test CA to its store, or none of the three sources of step 14 gives secure random bytes on one of the two systems (a crate other than `getrandom` needs its own review). Set the item to Blocked with `BLOCKED: <which of these>` and stop. Do not allow a licence, add a wrapper or turn certificate checks off to get past it, and do not read the system random device by hand. A failure of graviola on Windows is a result, not a block: use the schannel branch of step 12.
