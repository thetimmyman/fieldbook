# model-adapter-openai

- **Runs where:** home, CI Linux
- **Schema impact:** none
- **Review:** owner

## Outcome

`openai-compatible@1`, the second Model adapter, sends one request to an endpoint that speaks the chat-completions shape, over `UreqHttp`, through the gate that `model-gate` wrote. The company's policy holds a `[[destination]]` row for the endpoint (kind `model`, its `url`, the labels it allows); the owner adds a `[model.endpoint.<name>]` table to the settings, narrows the row with `allow` if wanted, names a key variable, lists the endpoint in `[model] order`, and runs `fieldbook ai test <name>` or `fieldbook ask "..." --via <name>`. The wire format is fixed and golden-tested, the statuses map to FB0905 to FB0914 as the table says, a 5xx or a rate limit is retried after 1 s then 4 s, a redirect is never followed, and a failure of availability falls back to a Handoff pack when `handoff` is in `order` and its row covers the request. A loopback fake endpoint in `xtask` lets the AI drill run the adapter end to end, and ten known-bad cases show each code.

## Why

- This is the one adapter that sends text off the machine, so it is built last and only after the spike has shown the stack works ([AD-01](../../decisions/0001-foundation.md#ad-01-architecture), [AD-18](../../decisions/0001-foundation.md#ad-18-security-and-confidentiality-guardrails)). The owner reviews it at the release [gate](../../decisions/0001-foundation.md#gates): it changes what data can leave, and the IT documents must say so in the same pull request.
- The gate has already done the work that keeps this adapter small: the policy check, the marking scan, the budget, audit before the send, validation after. The adapter only turns one request into one attempt and one reply or one coded failure, and it never sees the journal, the clock or the label rules. A test adapter whose `attempt` panics proves the order, and this card runs suite M on the real adapter as well.
- The wire format follows the widely used chat-completions interface. It is not verified here against any named vendor; five optional settings (`chat_path`, `query`, `max_tokens_field`, `response_format`, `send_temperature`) cover the usual gateways without new code, and the owner's own check is step 12. A local model server on loopback is the same adapter with a loopback `base_url`; documenting that as a supported setup is not done here (`later-local-model`).
- Redirects are never followed, because a redirect could carry the key to another host. A key reaches the adapter as a `Key` that cannot be printed, and only `io/net.rs` reads its text. The key is never in the URL: a `query` that names a key-like parameter is refused when the settings load.
- Controls: HG-09, HG-10 and AL-04 (proved on this adapter), NS-07 (the key and the prompt are searched for after every failure path), and NS-06, whose capture runs at the signed release.
- No page, template or string shown in a browser is built here, so there is no Design bullet.

## Steps

1. `settings.rs`. Add to the key table of `[model.endpoint.<name>]`: `chat_path` (default `/chat/completions`, must start with `/`), `query` (default empty; `name=value` pairs joined by `&`, characters `[A-Za-z0-9._~=&-]` only, and no parameter whose name, without case, is `key`, `api_key`, `apikey`, `token`, `access_token`, `secret`, `password`, `sig` or `signature`, with the help line "put the key in an environment variable and name it with `key_env`"), `max_tokens_field` (`max_tokens` or `max_completion_tokens`, default the first), `response_format` (`json_schema`, `json_object` or `none`, default `json_schema`) and `send_temperature` (a boolean, default true). `auth` keeps its two words. These are FB0900 when wrong. Add FB0913: a `base_url` is accepted when its scheme is `https`, or `http` and its host is exactly `127.0.0.1`, `[::1]` or `localhost`; a name that merely starts with one of them (`localhost.example`) is FB0913, and so is any other `http`. A `base_url` with a query or a fragment is FB0900. A `base_url` that differs from the `url` of the endpoint's row in the policy is FB0918 when the request is checked, before any connection; that match is `egress::check`'s and is not made here. Tests in `tests/settings_endpoint.rs`: `https_endpoint_loads`, `loopback_http_loads_for_three_hosts`, `remote_http_is_fb0913`, `lookalike_loopback_name_is_fb0913`, `query_with_a_key_name_is_refused_with_the_help_line`, `base_url_with_a_query_is_fb0900`, `unknown_variation_value_is_fb0900` and `defaults_apply`.
2. `io/net.rs` and `lib.rs`. Add `Offline`, an `HttpPost` whose `post` returns `HttpError::Other`; it is never reached, because the gate refuses an adapter that needs the network before `attempt` when `avail.net_built` is false (FB0912). The router calls `io::net::transport(proxy)`; only that factory names and constructs `UreqHttp::new(proxy)` under `net`, or `Offline` otherwise. It passes the returned transport and KeySource to the adapter factories. The layer scans stay unchanged. The adapter therefore compiles in both builds; only the client does not.
3. `adapters/openai.rs`, the request. `OpenAiCompatible::new(endpoint, http, keys)` implements `ModelAdapter` with `id() = "openai-compatible@1"` and `caps() = Caps { network: true, structured: true, embeddings: false, streaming: false, max_prompt_chars: 200_000 }` [J]. `prepare` builds the URL as `base_url` without a trailing `/`, then `chat_path`, then `?` and the `query` when there is one. `prepare` writes the body once; `attempt` consumes those exact prepared bytes without serializing again. The body is written by a struct with `Serialize` whose fields are in this order: `model` (from the route), `messages` (a system message with `req.system()`, then a user message with `req.prompt()`), `temperature` (0, omitted when `send_temperature` is false), the output-limit field named by `max_tokens_field` (the request's `max_out_tokens`), `stream` (false) and `response_format`. With a schema and `json_schema` it is `{"type":"json_schema","json_schema":{"name":"reply","strict":true,"schema":<emitted schema>}}`; with `json_object` it is `{"type":"json_object"}` and the schema is appended to the system message as a fixed sentence and the schema text; with `none` only the sentence is appended. The same request gives the same bytes. Headers: `content-type` and `accept` as `application/json`, and, when the endpoint names a `key_env`, one `Header::Secret` built from the `Key` that `keys` returns: `authorization` with the value `Bearer <key>` for `auth = "bearer"`, or `api-key` for `auth = "api-key"`. The adapter never calls `reveal`. A request has `timeout_s` from the route and `max_reply_bytes` of 1 MiB [J].
4. `adapters/openai.rs`, the reply. A 2xx reply must be JSON with `choices[0].message.content` as a string; `usage.prompt_tokens` and `usage.completion_tokens` are read when present. `finish_reason` `stop` is `Finish::Stop`, `length` is `Finish::Length` (the gate reports FB0909 with outcome `truncated`), and `content_filter` is `AttemptError::Permanent(Rejected(200))`. A 2xx body that is not that shape is `Rejected(200)`, and no part of it is kept in the error. The statuses: a connect failure is `Transient::Connect`; a timeout is `Transient::Timeout`; 429 is `Transient::RateLimited` carrying `Retry-After` when it is a number; 500 and above is `Transient::Server(status)`; 401 and 403 are `Permanent::Auth`; 400, 404, 422 and 413 are `Permanent::Rejected(status)`; 300 to 399 is `Permanent::Redirect`; `HttpError::Tls` is `Permanent::Tls`; `HttpError::TooLarge` is `Permanent::TooLarge`. With the gate's mapping these are FB0905, FB0906, FB0907 (for 413), FB0908, FB0909, FB0910 and FB0919. Add the registry row (port Model, not the default, `Built`, `Ai`, crate `fieldbook`, needs `Net`, `sees` labelled, `calls_model` true, the keys of step 1 with `model.proxy`, fixtures `tests/fixtures/ports/model/openai-compatible@1/`, suite M), the factory row and `pub mod openai;`. Run `cargo xtask docs` and commit `ports.md` and `errors.md`.
5. Tests in `tests/openai.rs`, on `ScriptedHttp` and `ScriptedPace`. The request: `request_bytes_match_the_golden_plain`, `request_bytes_match_the_golden_with_a_schema`, `request_bytes_match_the_golden_for_json_object`, `same_request_same_bytes`, `bearer_and_api_key_headers_carry_the_key_as_a_secret_header`, `no_key_env_sends_no_auth_header`, `path_and_query_are_joined`, `max_tokens_field_variants`, `temperature_can_be_left_out`. The reply: `reply_text_and_tokens_are_read`, `length_is_truncated`, `content_filter_is_rejected`, `body_of_the_wrong_shape_is_rejected_and_not_echoed`, `status_table` (one row for each status of step 4 and its code). The gate with this adapter: `retry_sleeps_are_1000_then_4000_and_the_third_try_wins` (503, 503, 200: `attempts = 3`), `retry_after_7_sleeps_7000` and `retry_after_over_30_is_30`, `exhausted_retries_are_fb0908_with_a_fallback_pack`, `redirect_is_refused_after_one_request` (a scripted 302 gives FB0906, and the double recorded exactly one request), `auth_is_not_retried`, `a_label_outside_the_row_sends_nothing` (HG-09: a request labelled `owner-supplied` against a row that allows `public` only; the double counts zero sends and a `refuse` event exists with the code, `labels` and `dest`), `a_base_url_that_is_not_the_rows_url_sends_nothing` (FB0918: the double counts zero sends), `marking_in_the_prompt_sends_nothing` (HG-10), `journal_refusing_begin_sends_nothing` (AL-04), `key_unset_is_fb0914_before_any_send`, `random_and_mutated_bytes_never_panic` (200 byte strings of length 0 to 512 from `Rng::new(1)` of `tests/support/rng.rs`, included in `tests/openai.rs` with `#[path = "../../../tests/support/rng.rs"] mod rng;` and written nowhere else (`one_rng_exists`), and the canned 200 reply of `requests.toml` with each of its bytes once flipped and once deleted, each served as the reply: the result is a reply or a coded failure, never a panic, and no byte of the body is in an error string), and `ai_test_over_a_scripted_endpoint` (the verb prints counts and not the reply).
6. `tests/contract_openai.rs`: `contract_model_openai_compatible_1` calls `suite_m` with a factory for the adapter over `ScriptedHttp`, and adds this adapter's cases from `tests/fixtures/ports/model/openai-compatible@1/` (`requests.toml`, the expected `ai.begin` and `ai.call` field values, the canned replies). `tests/ns07_openai.rs` extends NS-07: a synthetic key (`FBTEST-` and 40 characters of `[A-Za-z0-9]` drawn from `Rng::new(7)`, included with the same `#[path]` line) and a synthetic prompt go through every failure of step 5. Credentials must be absent from saved records and diagnostics; request captures retain header names, never secret values. Prompt/reply content is absent from journal, errors, Debug and status, but allowed in authorized transport bodies and labelled retained calls under retention and State admission. Test permitted and refused retention. Reuse `reveal_is_called_only_in_io_net` from ai-config-and-keys, scanning `.reveal(` call sites with its existing definition-module and io/net* exceptions; do not scan the identifier itself. The five keys of step 1 are read by `Settings::parse`, which `ai-config-and-keys` tests: add to `random_and_mutated_bytes_never_panic` of `tests/settings_no_panic.rs` a second input, a settings text that the test builds with an endpoint `work` that sets `chat_path`, `query`, `max_tokens_field`, `response_format` and `send_temperature`, flipped and deleted byte by byte in the same way.
7. The known-bad harness. In `known_bad.rs` a per-code file may name `http = "http.toml"` (defined once in [Known-bad files](../../reference/corpus-format.md#known-bad-files)), a file inside the case's fixture tree. A case with that key runs the verb in process, with a router built on `ScriptedHttp`, `ScriptedKeys` and the `Avail` the file gives, instead of the built binary. `http.toml` holds `net` (default true), `cpu` (default true), `keys` (the variable names that are set, default the endpoint's own) and `[[reply]]` rows, each with `status`, an optional `body` and `retry_after`, or an `error` of `connect`, `timeout`, `tls` or `too_large`. Each tree holds a `state/` with the settings, a one-file `corpus/`, and `http.toml`. It logs the request line, the header names and the body length, never a header value or the body, and `requests()` returns the log. In `mod tests` of `fake_endpoint.rs` (`xtask` is a binary crate, so a file in `xtask/tests/` could not call the server): `answers_in_order`, `logs_names_and_never_values`, `exhausted_script_is_a_500`, `delay_is_honoured`, `binds_loopback_only`. ## Negative control

Make the adapter map a 302 to `Rejected`: `status_table` must fail. Restore it. Let the double answer a 302 with a second scripted reply and have the adapter follow it: `redirect_is_refused_after_one_request` must fail. Restore it. Add a `key=` parameter to the `query` of a settings file: the load must fail with FB0900 and the help line. Put the key variable's value into one error string: `ns07_openai` must name the slice it found. Make `Guarded` skip `egress::check` for this adapter in a scratch change: `a_label_outside_the_row_sends_nothing` and `a_base_url_that_is_not_the_rows_url_sends_nothing` must fail. In the drill, trust the self-signed leaf by pointing the CA variable at its certificate: `loopback-endpoint` must fail, because it expects FB0910. Restore it. Last, let the reply reader index `choices[0]` without checking that the array has an element: `random_and_mutated_bytes_never_panic` must fail. Restore it.

Remove the `openai-compatible@1` row from `ADAPTERS`: `adapters_match_registry_docs_and_fixtures` must fail. Restore it.

## Rollback

Revert the merge commit. The adapter, its registry row and factory, the five settings keys and the FB0913 rule, `Offline`, the fake endpoint and the three drill steps go, and `ports.md` and `errors.md` regenerate. An existing `settings.toml` with an `openai-compatible` endpoint then fails with FB0900 until the endpoint table is removed; the file is the owner's and is not rewritten. `ask` over Handoff, the gate and `mcp` are unaffected. If the Day-30 gate drops this card, `net-stack-spike` goes with it (the cut order), and the gate record says the endpoint adapter is not built.

## BLOCKED

The gate cannot pass the key to this adapter without handing it the journal or the clock, or the known-bad harness cannot run a verb in process with a scripted transport. Set the item to Blocked with `BLOCKED: <which of these>` and stop. Do not give the adapter a second key reader, do not read the environment in `openai.rs`, and do not add a flag or a variable to the program that changes the transport.
