# r2-records

- **Runs where:** home, CI Linux, CI Windows
- **Schema impact:** none
- **Review:** owner

## Outcome

The company store holds typed records. `types.toml` defines the record types, `records\<type>.csv` holds one row for each record version under a 15-column envelope, `check` validates them (FB0200 to FB0207 on record files, FB0240, FB0241, FB0380, FB0381 and FB0311 on a `source_ref` or a `field` locator, and FB0504 on a `calc_run` cell), and `search` finds each version as a unit under its labels. A stream with `load` in `systems.toml` becomes records: `sync` reads the file, plans each row as `New`, `Unchanged`, `Historical` or `New version`, and proposes one `new_record_batch` for the whole file. A person accepts the batch. The accept writes the original, its extraction, the records file and, last, the source row, and a crash is finished by accepting again. A record version and its `handling` cell are immutable: a label added later is a line of the label ledger, and the labels of a version include its persisted inputs through effective_item. The store's `Register` port has two methods, `read` and `plan_append`, and its default adapter is `csv-folder@1`. `rests_on` walks the inputs of a computed version, and `check` and `status` warn when one rests on a superseded or withdrawn input (FB0382). The failures it prevents are in Why.

## Why

- A figure that cannot be traced is the failure this module exists to prevent: a rate in a bid that nobody can lead back to a quote. Every figure type carries an origin label (`quoted`, `computed` or `judgment`), and `check` finds one that names nothing (FB0380, FB0381). A quoted figure leads to validated per-field evidence in stored text, a table cell or a record field ([ADR 0004, section 9](../../decisions/0004-company-boundary.md#9-provenance-extraction-and-records)).
- A record version is immutable and a change is a new version. The failure it prevents: a price built on a rate that a later edit changed in place. The port has no method that rewrites a row (`there_is_no_way_to_rewrite_a_row`). A hand edit of a value is found by `check` only where it breaks a rule of this card; comparing each record with its source row is `records verify` (`later-records-verify`).
- A record version's labels cannot be edited in place. The failure it prevents: a price whose figures are cited by id and whose label was lowered by editing a cell, with nothing to show who did it. A label added later is a line of `labels.csv` ([the ledger](../../reference/company-store.md)), and `labels::effective_item` gives the set that search, the views and the checks use.
- A computed figure rests on other versions. When a quote it was built on is superseded or withdrawn, the price built on it looks current and is not. The failure it prevents: a bid priced from a rate that the vendor has since withdrawn. `rests_on` is one function that `check` and `status` share, so the warning (FB0382) cannot differ between them.
- A computed figure names the run that produced it, and a page or a claim cites one figure of a record. The failure they prevent: a price on a page that nobody can lead back to the cell it prints and to the calculation that made it. The `calc_run` cell holds the function and a hash of the run, and the `field` locator names the cell. This card parses, checks and resolves both and computes nothing (the producers are `later-pricing` and `later-rate-book`).
- A lock on a closed period will exist, and a write that ignores it would be found only after the period was closed. `plan_append` takes a scoped `Locks` argument, so the one place a lock is consulted is already the one place records are written. The common lock and approval types are fixture contracts here; their module workflows come later.
- A record type is data. A new type is one block in `types.toml`, with no Rust, no lexer rule and no search change, so a new ledger never waits for a build.
- The whole batch or nothing. The failure it prevents: a ledger loaded halfway, which looks complete and is not.
- `Unchanged` reuses values but writes observation membership. A monthly export lists every commitment again, and without the rule each load would double the file.
- `Historical` is a rule because someone drops last quarter's vintage into a share after this quarter's has loaded, and without it the differing rows of the old file would become the current versions.
- `plan_append` writes nothing. It returns a PlannedBatch of files, so the queue's single commit, journal pair and crash rule cover records as they cover sources, and a server store later is one adapter and no second writer.
- A single record by hand is a one-row file in a stream, so there is one door and one audit trail. A cell value is never printed in a problem line, so a company figure does not reach a ticket or a log from a pasted error.

## Out of scope

- A `new record` verb and per-row edits of a batch at accept (`later-batch-edit`). A person edits the source file and `sync --full` plans it again.
- `records verify`, the re-derivation of a record from its original (`later-records-verify`).
- The record-type page (`r/<type>.html`) and the `record` and `text` result filters. They belong to the interface lane; the data is in `search --json`.
- A verb that changes the columns of a type that holds records. The hand step is in [Adding a record type](../README.md#adding-a-record-type).
- Producers of computed figures: pricing, the rate book and the estimate (`later-pricing`, `later-rate-book`). This card checks the origin label of a computed version and builds none.
- The record types for an approval, a lock and a hold. Their shared shape and scoped Locks reader are built here from Financial work; the module workflows wait for their own cards.
- Writing a record to a CSV file or a workbook, and the record-type page. This card builds the function that neutralises a leading `=`, `+`, `-` or `@` for them (`cells::for_export`); the exporter and the page call it in their own cards.
- Correlation of records across systems (`later-entity-resolution`). `origin_key` is the first entity key.
- A server store or a shared store (`later-shared-store`). It is one more `Register` adapter by the adapter recipe.
- A file over the limits of `csv-rows@1` (100,000 data rows, 32 MiB). It is skipped with the extractor's message; ledger-scale tables are `later-dataset-tier`. A workbook as the file of a `load` stream: the load reads CSV only, and a workbook is read as a source by `xlsx-sheets` (`extract-xlsx-sheets`), so its cells are cited with `sheet` and `rec NAME!N` locators and are not loaded as records. Typed pointers also resolve workbook cells and record fields; workbook loading as a stream remains later work.
- Currency conversion and every other calculation on a figure. They belong to `fieldbook-calc`.

Mapped columns must exist with the reference kinds Financial work requires; missing or malformed declarations are FB0240, while a row missing its declared scope is FB0241. Each type revision is immutable; `revision` defaults to 1, `(name, revision)` is unique, and revisions preserve prior column meanings. A column's `kind` is one of eleven words: `text`, `int`, `date`, `pdate`, `decimal`, `bool`, `list`, `enum`, `money`, `ref` and `calc_run`. `show` is an optional array, the columns that a record view prints in order; `Type::shown()` returns it, or the `title` column and then the `key` columns when it is absent, and nothing reads it until `later-record-views` (the key is checked and not read). Every failure is FB0240 and names the key path and never a value. `Type::cells()` lists the cell names of a type's columns in order, a `money` column as `<name>` and `<name>_ccy`.
