# handoff-context

- **Runs where:** home, CI Linux
- **Schema impact:** none
- **Review:** auto

## Outcome

`fieldbook context "<question>" [--scope area:<code>|page:<id>] [--budget N] [--include tier-d,superseded,contradicted] [--json]` prints a plain-text context pack made from the `LabelledView` for the `handoff` destination (the records whose every label the `handoff` row of the policy allows: `public` and `owner-supplied` under the floor), and appends one `ai.pack` event, with the destination, the labels of the pack and the policy hash, before it prints. The same builder gives the Assistant page and the Bridge their context items, each with its origin and its reason, so the command, the page and the chat agree. The same inputs give the same bytes.

## Why

- The verb is in [AD-17](../../decisions/0001-foundation.md#ad-17-authoring-experience) (Day 30). The selection, the closure, the exclusions and the budget are the Handoff design of [AD-18](../../decisions/0001-foundation.md#ad-18-security-and-confidentiality-guardrails) and the rules on conflicts in [Dates, supersession, handling and labels](../../reference/corpus-format.md#dates-supersession-handling-and-labels). `ASSISTANT.md` is the first block, as AD-18 says.
- Controls: HG-01 (a record whose labels the destination does not allow never reaches a pack, and the pack says how many it left out), HG-02 (top 8 hits and their closure, 12,000 characters, whole blocks, the "Left out (budget)" list, the exclusions, a claim and its conflict kept or dropped together), HG-03 (the question scan, FB0700: a marking whose label the request does not cover) and AL-04 (a pack leaves an `ai.pack` event), all in [controls.md](../../controls.md). The Assistant page keeps the same scan in the browser, held to this card's goldens.
- One builder, three callers. `assist::context_pack` is the reference that [HANDOFF.md](../../design/HANDOFF.md) §9 names. The command prints it, `chat-bridge` calls it and `assist::apply_edits` for `POST /api/context`, and `assistant-page` ports both to `assist.js` and runs the goldens written here in Edge. The pin, remove and add rules live here and not in the page or the Bridge, so a pack built by hand in the browser and one built by the Bridge cannot differ.
- Each item carries `why`, so the screen can say "matches withholding and FFP" or "cited by both pinned items" without guessing. A reason for leaving an item out ("Tier D", "superseded", "contradicted", "over budget", "you removed it") is not stored: the page reads it from the unit's flags in `assist-data.js` and from `included`.
- The decision that a context holds only what its destination allows, whichever adapter is selected, is in [ADR 0004, section 5](../../decisions/0004-company-boundary.md#5-egress) and in AD-18 (Handoff design). The view is built for one destination from an `Allowed` token over everything the row allows, and the audit event is written from a second token over the labels that the pack holds, so no code here branches on an adapter: the `context` verb asks for `handoff`, and the Bridge and `ask` ask for the destination that their route planned. A record outside the set is left out whole, never redacted, and the pack's last line says so (it counts them for the `handoff` destination and says only that some were omitted for a model or the Bridge), so a pack never reads as complete when records were dropped.
- Design: the [MAP.md](../../design/MAP.md) rows `#assistant` (ContextPanel, ContextItem, ContextMeter), the Ask drawer (ContextBar and the context sheet) and CommandChip for the `context` verb. [HANDOFF.md](../../design/HANDOFF.md) §9 Context panel and Context pack (Selection, Left out by default, Format). Token groups: none; this card builds no page.

## Steps

1. `assist/context.rs`, pure data with `serde` derives and no `serde_json`: `Scope { All, Area(String), Page(String) }`, `Include { tier_d, superseded, contradicted }` (three `bool`s, `Default` all false; `handoff-new-note` adds `notes`), `Origin { Auto, Suggested, Pinned, Added }`, `Why { Hit, Closure, Scope, Named }`, `ContextItem { unit, origin, why, via, included, stale }` (`via` is the id of the item that brought a `Closure` item), `NamedPack { name, ids, view_fingerprint }` and `ContextIds`, a sorted set of ids with `from_pack(&ContextPack)` (the included items) and `from_ids`. `ContextPack` from `page-context-packs` gains `question`, `scope`, `items`, `chars`, `budget`, `request_budget`, `labels` (the union of the labels of the included items and of the question) and `view_fingerprint`; the pack already holds `left_out_line`, the last line of its text, which it took from `view.left_out_line(&dest)` when `page-context-packs` built it. `page_pack` fills them with an empty question and `Scope::Page`, and its `to_text()` bytes do not change. `Scope::parse(&str) -> Result<Scope, UsageError>` reads `area:<code>` or `page:<id>` (step 6 checks the code or the id against the view) and `Include::parse(&str) -> Result<Include, UsageError>` reads the comma list; both are pure, accept any text, and return a value or a typed error.
2. `assist::context_pack(view, question, scope, budget, include: &Include) -> ContextPack`, in this order. (a) The hits: `search::query` on the question over `assist::index_of(view)` (from `page-context-packs`: the index is built from the pages and source versions that `view` kept, so nothing the view dropped is ranked), top 8, and for `Scope::Area(code)` only units of that area; for `Scope::Page(id)` the page's own unit comes first (`why = Scope`), then its cited claims (`Closure`, `via` the page), then the hits with the page's own units left out. (b) The closure of AD-18 for each hit: the claims it cites, those claims' source versions and linked terms, and each selected claim's conflict row and every claim in that row's `claim_ids`, shown as contradicted; `via` is the first selected item that brought it. (c) The exclusions of HG-02: Tier-D sources, superseded versions and claims, and contradicted claims are `included = false` unless `include` names the class or the question names the unit's id (`why = Named`), except a conflict dependency of a selected claim; quarantined versions are never listed. (d) A claim and its conflict dependencies are one unit of selection: kept or dropped together. Add whole units in selection order until `budget` characters would be passed; the rest are `included = false` and are listed under the `left_out_budget` line of the text.
3. `assist::apply_edits(view, pack, edits, budget) -> ContextPack` with `Edits { pinned, removed, added, suggested }` (lists of ids): `removed` sets `included = false` and keeps the item listed; `pinned` sets `origin = Pinned` and moves the item first; `added` and `suggested` append an item with that origin and `why = Named`, and an added claim brings its conflict row and opponents as `Closure` items; an id the view does not hold is listed `stale = true, included = false`. After edits, reserve rules, question, history, pins and required closure. If mandatory content exceeds the limit, set request_budget.sendable=false and keep it visible. Trim only optional dependency groups in reverse rank order; rebuild text and scalar counts. A unit that is not in the view is not in it whatever its labels, so no id can bring one in.
4. `assist/view.rs`: `view_fingerprint(&LabelledView) -> String` (the SHA-256 in hex of the lines `<id> TAB <SHA-256 of its text> TAB <effective labels joined by |> ` of every unit of the view in id order); `resolve_pack(view, &NamedPack) -> Vec<ContextItem>` (origin `Pinned`, `why = Named`; an id the view lacks is `stale`, and when the stored fingerprint differs every available item is `stale` but may remain `included`; an id absent from the current view stays `stale = true, included = false`. An unavailable pin makes the pack unsendable until removed; a fingerprint change never restores permission); `export_units(view) -> Vec<UnitRecord>` with `UnitRecord { id, kind, title, area, as_of, tier, superseded, contradicted, block, closure, conflicts }`, sorted by id, where `block` is the text the pack uses for that unit. It is the one function that says which units an assistant may see, and `assistant-page` writes `assist-data.js` from it.
5. `ContextPack::to_text(&self)` for a pack with a question: `ASSISTANT.md` verbatim, a blank line, the line `Labels: ...` (the pack's `labels`, sorted and joined by a comma and a space; the owner's question is `owner-supplied` and `public` drops beside it) followed by the banner line of each label that has one in the policy, a blank line, `Question: <question>`, a blank line, then the blocks, then the `left_out_budget` list when it is not empty, and last the stored `left_out_line`: for the `handoff` destination of the `context` verb it is `Left out (policy): N records`, with N counted by the view, and for a `model` or `bridge` destination it is the fixed line `Some records were omitted.` that `page-context-packs` defines. With an empty question the bytes are those of `page-context-packs` for the same destination (`Labels: public` and the same last line). LF only, one final newline, no time stamp.
6. `context.rs` in the binary: `fieldbook context "<question>"` with the flags above. `--scope area:<code>` and `page:<id>` are checked against the view (else exit 2); `--budget` defaults to `[assistant] pack_budget_chars` and must be a positive integer; `--include` takes `tier-d`, `superseded` and `contradicted` (another word is exit 2; `handoff-new-note` adds `notes`). An empty question is a usage error. In this order and no other. (a) Label the question with `labels::for_text` (`owner-supplied` unless a marking or a policy rule gives it more) and keep `found`, the markings in it (`labels::markings_in`); a marking whose label the `handoff` row does not allow, or that no rule maps (`marked`), is FB0700. (b) Take the view token, `egress::check(&effective, &Dest::Handoff, None, None, now, shipped)`, using the current policy snapshot's time and export age. It selects the complete narrowed permission set without constructing data labels; an empty set selects no units. A denial keeps its own code. The question's labels are checked with the finished pack. (c) Build the view with `LabelledView::new(&model, &view_token, &ReadableStores::corpus())` and the pack from the view. If request_budget.sendable is false, print the over-budget or unavailable-pin reason, exit 2 and write no pack. (d) Take the audit token over what the pack holds, `egress::check(&effective, &Dest::Handoff, Some(&pack.labels), Some(&delivery), now, shipped)`, where `pack.labels` is the union of the labels of the included items and of the question. Every denial, at (a), (b) or (d), appends one `refuse` event (the code, `dest` and the labels where they are known) and nothing else, prints the code and exits 2. Then append `ai.pack` with `prompt_sha256` (the SHA-256 of the text to be printed), `context_ids` (the included ids), and `dest`, `labels` and `policy` taken from the audit token and never from the view token, and if the journal cannot append, print nothing and exit 3 with FB0903; then log the question (step 9); then print the text on standard output (with `--json`, the report of step 7 in its place) and one line on standard error, `context: N items, W characters, M left out`. Exit 0. The command writes the journal events and the question log and nothing else, and runs with the plain `Ctx` of a deterministic verb.
7. `ContextReport` in `report.rs`: `{ "report_version": 1, "verb": "context", "pack": ContextPack, "pack_text": string }`, with `ContextPack` as `{ request_budget: RequestBudget, question, scope, items: [ { unit, origin, why, via?, included, stale } ], chars, budget, labels, left_out_line, view_fingerprint }`. Add `tests/golden/json/context.json` and the row in `json_reports.rs`. Add `context` to `cli.md` through `cargo xtask docs`. Remove `context` from `PENDING` in `tests/chips.rs`. Register its case in `tests/support/chip_cases.rs` (a fresh Home `corpus-mini` copy, default Handoff, exit 0 with the pack).
8. Goldens for the page: `tests/golden/context/cases.json`, in the format of [Context](../../../tests/golden/README.md#context) (`kind` `context`, `version` 1): six cases on `corpus-mini`, each `{ id, question, scope, budget, include, edits, items, text }` with the expected result of steps 2, 3 and 5: a plain question; an area scope; a page scope; a claim in a conflict; a budget that drops a claim with its conflict; a pin, a removal and an unknown id. `assistant-page` reads the same file in Edge.
9. Call `asked::log_question(world, journal, settings, policy, Via::Context, labels, inputs, query, hits, Cited::NotChecked)` once, after `ai.pack` is appended and before the pack is printed; `labels` is the `labels` of the `ai.pack` event, the labels of the question and of the included items; inputs are the included items' trusted store-qualified references, excluding omitted items. A log that cannot be written prints its warning line and changes neither the output nor the exit code. A refused question (step 6) is not logged.
10. Tests in `crates/fieldbook-core/tests/context.rs` and `context_edits.rs`, on `corpus-mini` plus an in-memory page, source version and claim whose `handling` is `["np-0007"]` and which carry a synthetic marker, with `tests/fixtures/policy/context.toml` (a `handoff` row that allows `public` and `owner-supplied`, and a copy that also lists `np-0007`): `a_record_outside_the_allowed_set_never_reaches_a_pack_or_the_export` (carries `// control: HG-01` directly above it, as `controls_have_tests` reads it; the pack ends `Left out (policy): 3 records`), `pack_never_ranks_a_unit_outside_the_view` (the question is the exact title of the in-memory page whose `handling` is `["np-0007"]`, which the view leaves out under `tests/fixtures/policy/context.toml`: no block names that page, and the last line counts it), `a_record_inside_the_allowed_set_is_present_with_its_banner`, `the_labels_line_is_the_union_of_the_items_and_the_question`, `the_pack_ends_with_the_left_out_line`, `top_8_hits_then_closure_in_order`, `budget_drops_whole_blocks_and_lists_them`, `a_selected_claim_brings_its_conflict_and_opponent`, `over_budget_drops_claim_with_its_conflict`, `tier_d_superseded_and_contradicted_are_left_out_unless_named`, `quarantined_is_never_listed`, `why_and_via_are_set_for_each_item`, `area_scope_keeps_hits_in_the_area`, `page_scope_puts_the_page_first`, `same_inputs_same_bytes`, `a_removed_item_is_listed_and_not_included`, `a_pinned_item_goes_first_and_keeps_its_origin`, `an_added_claim_brings_its_conflict`, `an_unknown_id_is_stale_and_not_included`, `view_fingerprint_changes_with_a_unit_text`, `view_fingerprint_changes_with_effective_labels`, `resolve_pack_never_reincludes_an_unavailable_pin`, `resolve_pack_marks_every_item_stale_when_the_fingerprint_differs`, `goldens_match`, `context_arguments_never_panic_on_random_and_mutated_bytes` (the file includes the generator with `#[path = "../../../tests/support/rng.rs"] mod rng;`, builds 200 byte strings of length 0 to 96 from `Rng::new(1)`, and takes `area:cmp`, `page:P-0001` and `tier-d,superseded,contradicted` with each byte flipped once and deleted once, through `String::from_utf8_lossy` into `Scope::parse` and `Include::parse`; 12. Define `RequestBudget { limit, rules, question, history, context, total, sendable, over_by }`, measured in Unicode scalar values of the exact serialized request, including separators and repair text. ContextPack exposes this budget. Pins and their required closure are never excluded to make it fit: if mandatory material exceeds limit, sendable is false and no pack/send is produced. Optional hits are removed in reverse rank order as whole dependency groups. Invalid or inaccessible pins remain explicit stale/unavailable entries and also prevent send; they cannot silently disappear. Tests `pins_over_budget_disable_send`, `pin_closure_is_not_cut`, `unicode_budget_counts_scalars`, `whole_request_budget_includes_question_and_rules`, `optional_hits_trim_before_pins` share vectors with the browser.

13. Before the final egress check, construct Delivery from the exact rendered bytes, canonical path/endpoint/reply target, operation and markings. The selected view token is not a write token. Pass the bound token to the final sink and test a changed-byte or changed-path refusal.

14. `Budget` carries the scalar limit and fixed reservation for rules, current question and history, including separators. CLI callers use Budget::for_question with empty history; Bridge uses Budget::with_history after selecting complete turns. The exact serialized prepared request is checked again by model-gate. ContextPack::to_text may render preview text for an unsendable pack; only a sendable pack may reach an outward writer. Tests compare reservation and final serialization counts, so a JSON escape expansion also cannot bypass the model transport cap.

15. In the binary integration suite for `context`, `context_waits_for_a_complete_generation` pauses a two-file writer between files and calls the real handler. It waits and sees one complete generation, or refuses on timeout; no mixed content appears. A crashed pending transaction is refused until recovery.

16. In the successful context test, capture the pre-run journal sequence in the isolated fixture, select the single subsequent `ai.pack`, and assert the later `ask` event separately using `asked_via = context`. Allow initialization and policy/settings observations without counting them as operation events. Do not infer operation counts from an unfiltered journal tail, and do not add a ticket field.

## Negative control

On the branch, make `context_pack` skip the conflict closure: `a_selected_claim_brings_its_conflict_and_opponent` and the golden of a claim in a conflict must fail. Restore it. Make `export_units` read the unfiltered model instead of the view: `a_record_outside_the_allowed_set_never_reaches_a_pack_or_the_export` must fail and print the marker's id. Restore it. Make the view drop a record without counting it: the `Left out (policy): 3 records` assertion must fail. Restore it. Append `ai.pack` after printing in `context.rs`: `a_journal_that_refuses_appends_prints_no_pack` must fail. Restore it. Treat a Closed state as the floor in `context.rs`: `a_closed_policy_is_fb0413_and_appends_one_refuse_event` must fail. Restore it. Build the view from a token over the question's labels alone: `context_prints_the_pack_after_appending_ai_pack` must fail on an empty pack. Restore it. Write `ai.pack` from the view token: `pack_event_labels_are_the_union_of_the_included_items` must fail. Restore it. Index the first byte of the text in `Scope::parse` without a length check: `context_arguments_never_panic_on_random_and_mutated_bytes` must fail. Restore it. Build the index from the whole Model in place of `index_of(view)`: `pack_never_ranks_a_unit_outside_the_view` must fail. Restore it.

Drop a pin or count UTF-8 bytes as scalars: the matching budget vector must fail. Restore it.

In resolve_pack, let a changed fingerprint set included=true for an id the current view lacks: resolve_pack_never_reincludes_an_unavailable_pin must fail. Restore it.

Bypass the handler's store lease: `context_waits_for_a_complete_generation` must fail. Restore it.

## Rollback

Revert the merge commit. The command, the item types, `apply_edits`, `resolve_pack` and `export_units` go, `page_pack` and `ContextPack::to_text` return to the text of `page-context-packs`, and `cli.md` regenerates. Journal events already written stay, and `audit verify` still passes.
