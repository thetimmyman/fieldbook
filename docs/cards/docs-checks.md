# docs-checks

- **Runs where:** home, CI Linux
- **Schema impact:** none
- **Review:** auto

## Outcome

`cargo xtask cards --check` fails, naming the file and the line, on any of these: a card file, open or draft, that is out of the ten-section template; PLAN.md and the card files that do not match; two cards whose Scope overlaps with no precondition path between them; a relative Markdown link that does not resolve; an `AGENTS.md` over 100 lines or a Hard stop with no reason tag; the word "card", "gate" or "owner gate" followed by a digit, or a spelled-out count of the gates, in a Markdown file outside `docs/design/`; a count of IT questions that differs from the rows of `docs/intake/it-questions.md`; a network-posture sentence that does not name the build; a `later-` slug that is not a row of the AD-24 table; a heading or bold lead that begins `Adding ` in a Markdown file outside the cards README and is not listed in the README's Recipes section; a dagger row of the control register whose cards have merged and that has no test carrying its id; a generated reference file that differs from what `cargo xtask docs` writes; a card or component named in `docs/design/MAP.md` that does not agree with PLAN.md and HANDOFF section 5; a component of HANDOFF section 5 with no row in that section's root-selector mapping, or a declared root that the mockup does not carry, that is not a class or a native element name, or that two components declare; a line that claims "unsafe code" or "C code" without saying "first-party" or "build graph"; a `cargo nextest run` command whose filter is a bare word that is neither a module path nor the whole name of a test; or a control id in the Critical failures table that is not a row of the register. `just check` runs it in step 8, and `just new-card <slug>` starts a card file from the template. In `ci-ok`, `cargo xtask scope BASE HEAD` fails a pull request that deletes a card file and changes a path that card's Files and Registration lines do not list, apart from `Cargo.lock`, `CHANGELOG.md`, the files `cargo xtask docs` writes and the card file itself.

## Why

- The card anatomy is in [AD-21](../decisions/0001-foundation.md#ad-21-codex-execution-plan). The template, the header values and the rules for a card are in [docs/cards/README.md](README.md#the-template), which says `just new-card` comes from this card. `new-card` is one of the recipes of [AD-07](../decisions/0001-foundation.md#ad-07-developer-tooling).
- The line forms of PLAN.md, and the rule that a slug there names a card file, a draft, or a card file that a merged commit deleted, are in its header ([How Codex uses this plan](../plan/PLAN.md#how-codex-uses-this-plan)) and in AD-21. Status is on the work items in the tracker, so PLAN.md carries none. Read them before coding.
- CI checks the length of `AGENTS.md`, the reason tag of each Hard stop, and that every command in it exists ([AD-22](../decisions/0001-foundation.md#ad-22-agentsmd-and-the-docs-set)). Control AG-01 in [docs/controls.md](../controls.md#agent-boundary-and-change-control) names that check, and nothing runs it yet.
- The drift checks named in the recipes of the cards README: [Changing the network-posture sentence](README.md#changing-the-network-posture-sentence), [Adding a Later item](README.md#adding-a-later-item) and [Adding an IT question](README.md#adding-an-it-question). The generated reference files are named under "Writing a card" in the same README.
- Documents link only to files inside the repository.
- The register says a control is in force once its card merges ([docs/controls.md](../controls.md)), yet several built rows had no test that plants the fault. `controls_have_tests` finds the test by the id in a `// control: <ID>` marker, or by `control = "<ID>"` in a known-bad case. `adding_recipes_are_indexed` keeps one index of recipes: the same recipe was once written in two places and one copy went stale.
- The overlap lint trusts the `Files:` bullet of a card, and an unlisted edit defeats it: it shows up as hidden coupling or a merge conflict. `cargo xtask scope` reads the card as it stood before the commit that deleted it, so listing the path in the card, in an earlier commit of the same pull request, is the way through. Codex fixes a red check by listing the path.

## Scope

- Files: `xtask/src/{main.rs,cards.rs,links.rs,docs_lints.rs,scope.rs}`, `.github/workflows/ci.yml`, `xtask/Cargo.toml`, `Cargo.lock`, `justfile`, `docs/cards/README.md`, `xtask/tests/card_lifecycle.rs`.
- Registration lines: `xtask/tests/deps.rs` (the control marker for the dependency-register rule, directly above the test of `day1-dependencies` that plants a dependency with no row in `dependencies.md`; use the id of that row in the controls table). Each other dagger row of a merged card is marked by the card that built its test; if the first run of `controls_have_tests` still names one whose test exists, add the marker above that test and list its test file on this line; `AGENTS.md` (Commands: the new-card, cards and scope commands, this card's entries only); `docs/controls.md` (the Brought by cell of AG-01); `docs/reference/dependencies.md` (the Used by cell of `pulldown-cmark`); `.config/tools.toml` (shared `[lock]` record only), `.config/lock-inputs/` (only replay artifacts generated by this dependency change).
- Docs to update: `docs/cards/README.md` (drop "Until then, copy it by hand." and the "(from the `docs-checks` card)" aside), `AGENTS.md` (Commands: one more sentence that begins "From `docs-checks`:" and names `just new-card`, `cargo xtask cards --check` and `cargo xtask scope`, within the 100-line cap), `docs/controls.md` (AG-01 is brought by `docs-checks`), `dependencies.md` (`pulldown-cmark` is also used by `xtask`), and the `justfile` header comment, which no longer lists `new-card` as still to come.

## Out of scope

- The content of any card, of PLAN.md or of `docs/design/`. This card checks them; it does not edit them.
- Tracking work status: that is in the owner's tracker. The plan lint rejects status marks and prerequisites listed after their consumers.
- The generators of `errors.md`, `cli.md`, `audit.md` and `ports.md`: `check-v0`, `check-ci-and-docs`, `audit-journal` and `ai-kernel` each own the file they add. This card adds the test that ties them to the committed files.
- Links inside `corpus/` (FB0136 and FB0135, `check-page-links` and `check-page-body`).
- The scope check reads the `Files:` and `Registration lines:` bullets only. A hand-edited document of Docs to update (not `CHANGELOG.md`, not a generated file) is named in Files if one card alone owns it, or under Registration lines with the file and line when other cards also extend it, as the cards README says.

## Preconditions

- Cards merged: `check-ci-and-docs`.
- It may run beside `check-files`; their paths are disjoint.

## Steps

1. In `xtask/Cargo.toml`, add `pulldown-cmark = { workspace = true }`, Follow the dependency recipe: run `just lock`, review its lock/replay inputs, then `just lock-verify`; retain `cargo xtask deps --check` and `cargo deny check`.
2. Write `cards.rs` with the card lint, for every `docs/cards/*.md` and `docs/cards/drafts/*.md` except `README.md`: the title is `# <file stem>`; the three header lines come in the template's order with values from [The three header fields](README.md#the-three-header-fields), and a Schema impact other than `none` goes with `Review: owner`; the ten `##` sections come in the template's order, each exactly once, and an `## Evidence` section is an error; the last command of the Acceptance code block is `just check`. Every `cargo nextest run` command in a code block or a code span of the card must follow the filter rule of [Writing a card](README.md#writing-a-card): after the flags (`-p CRATE`, `--locked`, `--features F`, `--exclude C`, `--workspace`, `--test FILE`, `--run-ignored WHICH`), each remaining word either holds `::` or is the whole name of one test, which the lint reads as a word that is a code span of its own elsewhere in the same card and holds at least two underscores. A word such as `known_bad` or `audit` fails, and the message gives the file, the line and the word. Read the section names from the template between the `card-template` markers, not from literals.
3. Add the plan lint to `cards.rs`. An item is a line `- <slug>: <text>` under the `##` headings F0, P1, P2 and P3 (a `###` heading inside a phase does not end it). It needs `docs/cards/<slug>.md`, or a commit in the history of `HEAD` that deleted that file: `git log --diff-filter=D --format=%H -- docs/cards/<slug>.md` prints a line (on a pull request, the deleting commit is the branch's last commit). The history must be full: the lint stops with a message when `git rev-parse --is-shallow-repository` prints `true`, and a repository with no commits has no deletions. The `rust` job of `.github/workflows/ci.yml` already checks out with `fetch-depth: 0`; a job that runs `cargo xtask cards --check` later must do the same. `workspace-skeleton`, built before cards existed, is exempt. An item under P4, P5, P6, P7 or P8 is accepted when its draft is in `docs/cards/drafts/`, when its card file is in `docs/cards/`, or when it is a one-line item with no file; an item whose slug begins `later-` is accepted only under P6, P7 and P8, with no card yet, a draft, an open card, or completion proved by the same deletion-history rule, and fails under F0 and every phase P1 to P5 (that it is a row of the AD-24 table is checked by `later_slug`); a draft moves to `docs/cards/` by one `git mv` when the phase before it ends, and this rule then applies to it as to any P1 to P3 item. Lines that end `(owner)` or `(lead)` are exempt. Every card file and every draft needs a PLAN.md item with its slug, in any phase. In the phase sections, a list line is an error when it is neither an item nor ends `(owner)` or `(lead)`, or when it starts `- [ ]`, `- [x]` or `- [!]` or holds `-> pass`. The header text above the first phase may describe these forms.
4. Add the scope-overlap lint to `cards.rs`. For each card file and draft, read the paths of the `Files:` bullet of Scope (a `Registration lines:` bullet is not read, as the cards README says): the literal-path, directory-prefix and brace grammar in [Shared scope paths](README.md#shared-scope-paths), using the same parser as changed-path scope checking. Two cards overlap when a path of one equals, contains or lies under a path of the other. The pair passes when one card reaches the other through the slugs under `Cards merged` in Preconditions, followed any number of steps, or when every shared path is in the `SHARED_PATHS` constant of `cards.rs`: `docs/plan/PLAN.md`, `CHANGELOG.md`, `Cargo.lock`, `justfile`, `xtask/Cargo.toml`, `xtask/src/main.rs`, every `lib.rs`, every `check/mod.rs`, `crates/fieldbook/src/{cli.rs,io/mod.rs}`, `crates/fieldbook/tests/chips.rs`, `crates/fieldbook-render/assets/{app.css,app.js}`, `tests/known-bad/{cases.toml,pending.toml,elsewhere.toml}`, `.github/workflows/scheduled.yml` and `.github/workflows/ci.yml`. Each is a registration file that many cards extend by a line, so git merges the lines; a card rebases onto `main` before its last commit. Otherwise it prints both file names and the shared path.
5. Write `links.rs`. For every Markdown file under `docs/` and for `README.md`, `AGENTS.md`, `CHANGELOG.md` and `SECURITY.md`, read the links and images with `pulldown-cmark` (code is skipped). Ignore targets with a scheme. Every other target must stay inside the repository root and name an existing file or folder. A `#fragment` on a link to a Markdown file, or alone, must match a heading anchor of that file, made as GitHub makes it: lowercase, characters other than letters, digits, spaces, hyphens and underscores removed, spaces turned into hyphens, and `-1`, `-2` added to repeats.
6. In `links.rs`, check `AGENTS.md`. At most 100 lines (`AGENTS.md: <n> lines, limit 100`). Every bullet under `## Hard stops` starts with one or two of `[leak]`, `[certify]`, `[corrupt]` and `[lane]` (`AGENTS.md:<line>: Hard stop has no reason tag`). Every `just <recipe>`, `cargo xtask <command>` and `fieldbook <verb>` in backticks names a recipe of the `justfile`, a command of `xtask` or a verb of the clap `Cli` (the `fieldbook` edge comes from `check-ci-and-docs`). A command in a sentence that begins "From" and a card slug in backticks is exempt, because it names a command still to come.
