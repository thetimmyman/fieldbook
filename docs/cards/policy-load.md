# policy-load

- **Runs where:** home, CI Linux, CI Windows
- **Schema impact:** none
- **Review:** owner

## Outcome

Every run of `fieldbook` knows the state of the company policy: Floor (no file, none loaded here before), Loaded, or Closed (a bad file, a lower `revision`, a file that a non-administrator can write, or a file that was loaded here before and is now missing). On the Laptop preset the program reads one machine-level file, `%ProgramData%\Fieldbook\policy.toml`, found by the operating system's known-folder call. The release binary has no flag or variable that names a policy or moves a laptop folder. A file inside the data root, the Corpus or a git work tree is refused before it is opened (FB0414, exit 2). A file or folder that a non-administrator can write closes the policy (FB0418). The program records the highest revision, the hash and the audit sink it has loaded in `state/policy-seen.toml`, and a verb that writes appends `policy.change` when the hash is new. `fieldbook policy show` prints what the program sees, and `fieldbook policy check FILE` validates a draft with no side effects, in any release build. A Closed state does not stop `check`, `build`, `search` or `status`; it stops every send.

## Why

- The path, the three states, the writer check, the recorded revision and the commands are in [the policy reference](../reference/policy.md#where-it-is-read-from) and [ADR 0004, section 3](../decisions/0004-company-boundary.md#3-the-company-policy-file). `core-policy` made the parser, the floors and the decision; this card makes the program read a file and act on the result. The controls are PL-01 and PL-03 in [controls.md](../controls.md).
- Review is `owner` because this card decides what the program does when the company's file is wrong. The two ways to get it wrong are both leaks. If a bad file were treated as no file, a restriction IT wrote would silently stop applying. If a broken file stopped the program, the owner could not read the knowledge base or run a build because of a text file IT edited.
- The owner must not be able to choose the policy. A flag or a variable that names the file, or that moves `ProgramData`, lets the owner (or an agent running as the owner) write a permissive file and point the program at it, keeping the real store. So the release binary compiles those flags out, the folder comes from the operating system, and the program asks the operating system who can write the file before it reads it. What it cannot see is an administrator who writes the file; for that, designated egress and outward-write events carry the policy hash, and `policy.change` records changes to the observed policy ([event contract](../reference/audit-contract.md)); `policy show` prints it.
- `revision` exists so that an older, more permissive file cannot be put back by accident (a restore of an old copy of `%ProgramData%`, a deployment from a stale share). The record lives in the state folder, which the owner can edit, so it guards against accident and not against the owner. Deleting `policy-seen.toml` does not open anything: a laptop with a company store and no policy is on floor B, which sends nothing to a model and refuses exports, and the journal shows a `policy.change` whose `prev` is zeros after a revision that was not the first. IT can still roll back; a roll-back is a new revision with the old content.
- A policy read from a place the owner can edit is no control at all (FB0414). The data root, the Corpus and a git work tree are never fine; a test build may name a fixture inside a checkout.
- The recorded audit sink exists so that `audit-export` still works in the Closed state: the one destination a Closed policy leaves open is the journal export, and the sink cannot be read from a file that failed to parse.
- No page, template or string shown in a browser is built here, so there is no Design bullet.

## Steps

1. `policy/place.rs`, pure: `Placement { in_data_root: bool, in_corpus: bool, under_git: bool, fixture_ok: bool }` (a different type from the `Placement` of `labels::placement`; the module path tells them apart) and `policy::place(&Placement) -> Result<(), PlaceWhy>`. `PlaceWhy` is `DataRoot`, `Corpus` or `GitWorkTree`. The first two refuse on every layout. `under_git` refuses unless `fixture_ok`, which only a test build sets. `Flags { state: Option<PathBuf>, overlay: Option<PathBuf>, working: Option<PathBuf> }` and `LaptopFolders { state: PathBuf, overlay: PathBuf, working: PathBuf }` are pub structs of this file and use no `Layout`. `flags_allowed(laptop: bool, fixed: &LaptopFolders, flags: &Flags) -> Result<(), Refusal>` refuses (FB0419) a `--state`, `--overlay` or `--working` flag that names a folder other than the fixed folder of the same name when `laptop` is true, and allows every flag when `laptop` is false. Tests: `a_policy_in_the_data_root_is_refused`, `a_policy_in_the_corpus_is_refused`, `a_policy_under_git_is_refused`, `a_test_build_fixture_under_git_is_allowed`, `a_policy_beside_the_data_root_is_allowed`, `on_the_laptop_a_state_flag_elsewhere_is_fb0419`, `on_the_laptop_the_fixed_folders_are_allowed`, `at_home_any_state_flag_is_allowed`.
2. `policy/writers.rs`, pure: `WriterFacts { file: Vec<Writer>, folder: Vec<Writer> }` where `Writer` is `Administrators`, `System`, `Other` or `Unknown`, and `writer_check(&WriterFacts) -> Result<(), WriterWhy>`. It refuses (FB0418) when the file or its folder lists any `Other` or `Unknown` writer. `World` gains `program_data(&self) -> Option<PathBuf>` and `writers(&self, path: &Path) -> WriterFacts` (the signatures are written once, here; each `Disk` body is one line in `io/mod.rs`). On Windows `writers` calls the wrapper `writers(&Path)` of `io/win.rs` (`Option<Vec<WriterKind>>`) for the file and again for its folder; each `WriterKind` becomes the `Writer` of the same name, and a `None` becomes one `Unknown` writer, so the check fails closed (this card has no Windows API call and no first-party unsafe code); on Linux it returns `Other` only when the world write bit is set on the file or on its folder, and it ignores the owner's bit and the group's: the user who runs a test owns the files the test copies, the fixtures in the repository are mode 0644, and on a system with a umask of 002 a new file is group-writable, so a rule that counted the owner or the group would close the fixture policy of a correct run with FB0418. Linux reads no policy except in a test build (step 5), so the weaker rule loses no protection. `windows-facts` tests the access-list read itself in the `windows` job of `ci.yml`, and this card adds the Windows feature-enabled policy tests. The "laptop" half of PL-01 is the owner running `fieldbook policy show` on the laptop at the release check and reading `writer check: ok`. Tests: `administrators_and_system_alone_pass`, `a_user_who_can_write_the_file_fails`, `a_user_who_can_write_the_folder_fails`, `an_unknown_entry_fails`, `the_refusal_names_the_path_and_no_account`.
3. `policy/seen.rs`, pure: `Seen { revision: u64, hash: Sha256, audit_sink: Option<PathBuf> }` and `Seen::parse(text) -> Option<Seen>`, `Seen::to_text(&self) -> String` (fixed key order, `seen_schema = 1`). An unreadable or unknown-schema text gives `None`, and the caller prints one warning line `warning: state/policy-seen.toml is unreadable; no revision is recorded`. `FileObservation { fact: FileFact, digest: ObservationDigest, writers: Result<(), WriterWhy> }` retains the observed bytes digest and writer result. `ObservationDigest` is `Whole(Sha256)`, `Prefix { bytes: u64, sha256: Sha256 }`, `Absent` or `Unreadable`. Bounded readable input, including invalid UTF-8, gets Whole before decoding. Oversized input gets Prefix for exactly the first 1,048,577 bytes, encoded `prefix:1048577:sha256:<hash>`; never claim a whole-file hash. `FileFact` is `Absent`, `Unreadable` (the open or the read failed), `TooLarge`, `NotUtf8 { utf16: bool }` or `Text(&str)`, and `FileFact::from_bytes(&[u8]) -> FileFact` is the one function that turns the bytes that `PolicySource::read` returns into one: more than 1 MiB is `TooLarge`; a leading `FF FE` or `FE FF` is `NotUtf8 { utf16: true }` (what PowerShell 5 writes with `>` or `Out-File`); other bytes that are not valid UTF-8 are `NotUtf8 { utf16: false }`; the rest is `Text`, with the bytes unchanged, so a UTF-8 byte order mark and CRLF line endings stay in the text and the hash is the SHA-256 of the file's bytes (`core-policy` skips one leading mark when it parses). `resolve(file: FileObservation, seen: Option<&Seen>, has_company_store: bool) -> Resolved`. It returns the `PolicyState`, the `Outcome` word of the journal (`loaded`, `absent`, `invalid`), the `Seen` to record and `note: Option<&'static str>`, using `Policy::parse(text, seen.map(|s| s.revision))` of `core-policy`: `Absent` with no `seen` is `Floor(FloorKind::for_machine(has_company_store))` and has no outcome (nothing changed); `Absent` with a `seen` is `Closed(Absent)` with outcome `absent`; `Unreadable`, `TooLarge`, `NotUtf8` and a parse failure are `Closed(Invalid)` with outcome `invalid`, and `note` names the cause for the first three (`the file could not be read`, `the file is larger than 1 MiB`, `the file is UTF-16; save it as UTF-8` or `the file is not valid UTF-8`) and is none for a parse failure, whose cause is the `PolicyError`; a failed writer check is `Closed(Writable)` with outcome `invalid`; a lower `revision` is `Closed(LowerRevision)` with outcome `invalid`; otherwise `Loaded`. The `Seen` to record is new only for `Loaded`; a Closed run leaves the old record as it is. Tests: `a_missing_file_with_no_record_is_the_floor`, `the_floor_is_b_when_a_company_store_exists`, `a_missing_file_with_a_record_is_closed_absent`, `a_valid_file_is_loaded`, `an_invalid_file_is_closed_invalid`, `a_writable_file_is_closed_writable`, `a_lower_revision_is_closed`, `an_equal_revision_with_new_bytes_is_loaded`, `a_closed_run_keeps_the_old_record`, `the_sink_is_recorded_from_the_loaded_policy`, `a_policy_with_no_audit_table_records_no_sink`, `seen_round_trips`, `an_unreadable_record_is_none`, `a_file_saved_by_windows_tools_loads` (the fixture with a UTF-8 byte order mark and CRLF line endings is `Loaded`, and its hash equals the SHA-256 that the test computes over the same bytes), `a_utf16_file_is_unreadable_and_says_so` (the fixture encoded as UTF-16 LE with its mark is `NotUtf8 { utf16: true }`, resolves to `Closed(Invalid)` with outcome `invalid`, and the note names UTF-16 and UTF-8), `a_file_over_one_mib_is_too_large` (a file of exactly 1,048,576 bytes is `Text`, one byte more is `TooLarge`).
4. `policy/show.rs`, pure: `show(&Resolved, &EffectivePolicy, &Seen, &Source) -> PolicyShowText` and the `PolicyShow` report. The text starts `policy: none (floor)`, `policy: loaded` or `policy: closed (<CODE>): <why>`, where `<CODE>` is the resolved closure cause's existing code — FB0418 for a writable file and FB0413 otherwise — and `<why>` is `Resolved::note` when there is one and otherwise the rule and the key path of the first finding, then `path:`, `hash:` (64 hex), `writer check:` (`ok` or what failed), `revision:`, `recorded:` (revision and the first 12 hex of the hash), then the labels (`id`, title, banner), the stores (`holds`, `default`, `readers`, `changers`, `hold`), the rules (`[[marking]]`, `[[source]]` with its root, rules and maps), the destination rows (kind, name, url, `allow`, `expires` and whether it has passed, `keep_calls_days_max`, `ref`, `clients` as hashes, `paths`), the `[audit]` table (`sink`, `max_unshipped_hours`, and `export requirement: on` or `export requirement: off`, which is `on` when `require_fresh_export` is absent), the fixed rows marked `built in` (`audit`, `git`, `edition`), the advisory kinds marked `advisory`, and the effective table from `EffectivePolicy::explain`: for every destination row, the narrowed `allow` and, for each label cut, whether the policy or the owner's settings cut it. `policy_line(&PolicyCtx) -> String` is `policy: <floor|loaded|closed> <first eight hex digits of the hash>`, the first line that every AI verb prints. Titles, banners and `ref` appear in `show` because this output goes to the terminal of the person who owns the file; the journal never holds them. The floor prints its own table so that IT sees what applies with no file. Tests: `show_floor_prints_none_and_the_floor_table`, `show_floor_b_prints_the_narrow_backup_route`, `show_loaded_prints_every_row`, `show_closed_prints_the_code_and_the_reason`, `show_prints_the_writer_check`, `show_prints_the_export_requirement_on_off_and_by_default` (a policy with the key `false`, with `true` and with no key: `off`, `on`, `on`), `show_marks_the_fixed_rows_built_in`, `show_marks_the_advisory_kinds`, `show_names_the_side_that_cut_a_label`, `policy_line_has_the_state_and_eight_digits`, `show_is_deterministic`.
5. `io/policy.rs`: `PolicySource::read(world, &Source) -> Result<FileObservation, Refusal>`, the one function that opens a policy path. On the Laptop preset `Source` is the machine file: `world.program_data()` (on Windows `fieldbook_win::known_folder(Folder::ProgramData)` through `io/win.rs`, the operating system's known-folder call and never the environment; off Windows it has no answer, so `Source` is `None` there unless a test build gives `--program-data`) joined with `Fieldbook\policy.toml`. At home and in CI `Source` is `None` and the floor applies. A test build (feature `test-hooks`) also accepts `--policy FILE` and `--program-data DIR`; they are compiled out of the release binary. It reads at most 1 MiB plus one byte so that `TooLarge` can be told from a file of exactly 1 MiB. `PolicySource::read_draft(path)` reads a draft for `policy check` in any build. Before the read, `resolve_place(world, path, state, corpus) -> Result<(), Refusal>` canonicalises the path (links and junctions resolved; when the file does not exist, the nearest folder that exists is canonicalised and the remaining components are appended, so that an absent file under a link into the data root is placed where it would be: `an_absent_policy_path_is_placed_by_its_nearest_folder`) and the state folder and the Corpus root, computes `in_data_root` and `in_corpus` on whole path components, and `under_git` by looking for a `.git` entry in each ancestor with `World::exists`; it passes the facts to `policy::place`. A refusal prints `error[FB0414]: the policy file <path> is in <the data folder|the Corpus|a git work tree>, where the owner can edit it; the policy is read from a place only IT can write` and exits 2 before the file is opened and before any journal line is written. Then `world.writers(path)` is passed to `writer_check`. `seen_path(state)` is `state/policy-seen.toml`; `read_seen` and `write_seen` go through `World` and `io::atomic` under a `StateScope`. `owner_settings(world) -> OwnerSettings` returns `OwnerSettings::unset()` (Out of scope). `company_store_beside(world, state: &Path) -> bool` is true when `overlay/store.toml` exists in the folder beside `state` (found with `World::exists`); it is the fact that `r2-state-and-journal` calls `store_toml_beside_state`, and that card calls this function and does not read the file a second time.
6. `policy.rs` in the binary: `policy::resolve(world: &dyn World, state: &Path, corpus: &Path, laptop: bool) -> Result<PolicyCtx, Refusal>` is called initially, and refreshed before each outward operation; the initial call is after the state folder and the Corpus root are known and before the journal opens, and the result goes into `Ctx`. Callers pass `laptop = false` until the laptop exists. The dispatcher in `lib.rs` then passes `EffectivePolicy::new(` the `PolicyState` of that `PolicyCtx` and `owner_settings(world))` to `build`, `backup` and `restore`, in place of the `EffectivePolicy::floor(false)` that `build-v0`, `backup-snapshot` and `restore-and-drill` passed until now. It passes `company_store_beside` for the state folder to `resolve` as `has_company_store`, so floor B applies as soon as a company store is on the machine, whatever the preset says. `PolicyCtx` holds the `PolicyState`, the path, the observation digest and writer result copied from `Resolved`, the resulting observation hash, the `Seen` read, the `Seen` to record and the `Outcome`. `PolicyCtx::loaded(policy: Policy) -> PolicyCtx` and `PolicyCtx::closed(why: ClosedWhy) -> PolicyCtx` build one for a test that runs a verb in process under a policy without writing a file (the path is empty, the hash is the hash of the text given to `Policy::parse`, nothing is recorded, and the outcome is none). A `Closed` state prints one line to standard error for a verb that is not `policy`, `status`, `check`, `build` or `search`: `warning: the policy is closed (<CODE>): <why>; every destination is denied except the audit sink`, where `<CODE>` is the same resolved closure cause's existing code that `policy show` prints, FB0418 for a writable file and FB0413 otherwise. The line carries one code, never a combined `FB0413|FB0418` placeholder, and the fail-closed behaviour is unchanged. `policy::observe(&mut Journal, &PolicyCtx)` is called by `Journal::open` for a verb that writes: compare the observation with the latest validated `policy.change`, not with `Seen`. Append only when it differs. For Loaded, `policy` is the file hash. For Closed, `policy` is SHA-256 of the fixed UTF-8 encoding `closed\n<reason>\n<file-fact>\n<writer-fact>`, where reason is the closed-reason word, file-fact is `sha256:<hash>` for bounded readable bytes, `prefix:1048577:sha256:<hash>` for oversized input, or `absent` or `unreadable`, and writer-fact is `ok` or the closed writer-reason word. Use `prev` for the previous observation hash (64 zeros when none), the last valid revision for Closed, the existing outcome words and zero counts for Closed; add no event field. Loaded writes `Seen` after the event. Closed leaves `Seen.revision`, `Seen.hash` and `Seen.audit_sink` unchanged. Read-only verbs (`check`, `status`, `policy show`, `policy check`, `audit verify`, `audit show`) append and write nothing. Tests are in step 8.
7. `cli.rs`: the subcommands `policy show [--json]` and `policy check FILE [--json]`, and, under the feature `test-hooks` alone, the hidden global flags `--policy FILE` and `--program-data DIR`.
