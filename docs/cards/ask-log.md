# ask-log

- **Runs where:** home, CI Linux
- **Schema impact:** none
- **Review:** auto

## Outcome

Every `fieldbook search` query that is not a bare id is written as one row of `asked/asked.csv` in the state folder, with the result it got on that day: the tool version, the Corpus fingerprint, the number of results, the top ids and an outcome of `answered` or `no_result`. The journal gets an `ask` event that holds the question only as a hash. `[asked] mode` turns the text off or reduces it to a hash, and `keep_days` expires old rows with a `purge` event. A log that cannot be written never stops a search.

## Why

- The owner's own questions are the test set; nobody writes a held-out question as a chore. The row keeps the first-run result, taken before anyone could tune the ranking for it, and later gates count those rows ([Gates](../decisions/0001-foundation.md#gates), control HG-07 in [controls.md](../controls.md)). Turning a miss into a regression case or a gap question is `ask-promote`; this card only records.
- The log is the one file that holds question text, and the journal holds the hash. So the owner can clear the log, keep hashes only or turn it off without touching the audit trail, and the journal file can still go to IT ([data-handling.md](../intake/data-handling.md), section 7). On the laptop the log lives in the state folder with the rest of its files. Each row carries the labels it was asked under (`labels`: `owner-supplied` for the question, and the labels of the pack when a caller sent one), so a backup or an export of the log passes the same rule as any other output ([ADR 0004](../decisions/0004-company-boundary.md#2-labels)). Each row also carries `by`, the principal that asked, so a log shared between people is a later change of the store (`later-shared-store`) and not of this format.
- A bare id is a lookup and not a question, so it is not logged. A repeat of the last question with the same via, labels and inputs within a minute is one row, so a re-run of a query does not count twice.
- This is a Could ([Cut line and floor](../decisions/0001-foundation.md#cut-line-and-floor)). The regression set and the tests do not depend on it.
- No page, template or string shown in a browser is built here, so there is no Design bullet. The `status` line is this card's: step 6 adds one `StateLine` to the summary that `status-command` prints.

## Scope

- Files: `crates/fieldbook-core/src/asked.rs`, `crates/fieldbook-core/tests/asked.rs`, `crates/fieldbook/src/{search.rs,asked.rs}`, `crates/fieldbook/src/io/{mod.rs,asked.rs}`, `crates/fieldbook/tests/{asked.rs,search.rs}`, `tests/fixtures/state-asked/` (the whole folder).
- Registration lines: `crates/fieldbook-core/src/lib.rs` and `crates/fieldbook/src/lib.rs` (the asked module lines); `crates/fieldbook/src/io/state.rs` (the `[asked]` table is read there, with its own check); `crates/fieldbook-core/src/backup/labels.rs`, `crates/fieldbook/src/backup.rs` and `crates/fieldbook/tests/backup.rs` (question-log parsing, current input labels and the real backup tests, this kind only).
- Docs to update: `CHANGELOG.md` (`- Added: search records each question in the question log.`).

## Out of scope

- The callers `context` (`handoff-context`), `ask` (`model-handoff-ask`) and the chat page (`chat-bridge`). They call the logger written here with their own `via`, labels and trusted input references.
- `queue flag`, `queue pin`, the questions to look at in `queue review` and every write to `regression.toml` (`ask-promote`). The outcomes `flagged` (`ask-promote`) and `cite_failed` after the fact (`model-handoff-ask`) are set through `with_outcome` and `set_outcome` of this card. `cite_failed` is written when a caller passes `Cited::Broken`; `search` has no citations, so this card's own caller writes `answered` and `no_result` only.
- Any change to what `search` prints or to its exit code.

## Preconditions

- Cards merged: `search-cli-and-regression`, `status-command`, `audit-journal`, `core-labels`, `core-policy` and `backup-snapshot` (the backup kind dispatch and test fixture).

## Steps

1. Core, `asked.rs`, pure and without a clock: `AskedRow` with the columns `id` (`A-nnnn`, the newtype `AskedId`), `at`, `via` (the audit producer's AskedVia, re-exported as asked::Via and written as its lowercase word), `question`, `labels` (sorted label ids joined by `|`), `inputs` (sorted unique `ItemRef` pairs), `by` (`World::principal()`: `os:<DOMAIN>\<user>` on Windows, `os:local\<account>` on Linux, and `local` from the `TestWorld` of `audit-journal` that tests use), `tool_version`, `fingerprint`, `result_count`, `top_ids`, `outcome` (`answered`, `no_result`, `cite_failed`, `flagged`) and `state` (`open`, `promoted`, `dismissed`). `inputs` is one CSV cell containing a single-line TOML array of inline tables, each with `store` then `id`, sorted by store/id; the existing TOML serializer escapes the strings and core-csv escapes the cell. An empty list is `[]`; a missing or malformed cell is an error, never known empty. `parse` and `render` use the CSV rules of `core-csv` and reject an unknown column. Also `next_id(rows, journal_last) -> Result<AskedId, Exhausted>`, one above the larger of the highest id in `rows` and `journal_last`, the `asked` of the newest `ask` event that has one, which the caller reads through the journal reader behind `audit show --last` (the journal is never rewritten, so an id is not reused after rows expire or after the owner deletes the log; it is unique within one state folder, and a shared log would key a row by `by` and `id`, which is part of `later-shared-store`), `is_bare_id(query)` (the whole query is one id of the grammar in [Identifiers](../reference/corpus-format.md#identifiers)), `is_repeat(last, query, via, labels, inputs, now)` (same text, via, labels and input pairs within 60 seconds), `expire(rows, now, keep_days) -> (kept, removed)`, `hashed(question)` (`sha256:` and 64 hex) and `summary(rows) -> AskedSummary { asked, misses, promoted }`, where a miss is any row whose outcome is not `answered`. Also `with_outcome(rows, id, to: Outcome) -> Option<Vec<AskedRow>>`, which preserves its inputs and labels and changes only a row whose outcome is `answered` to `to` (`cite_failed` or `flagged`) and returns `None` for an unknown id or any other outcome, so the first-run result of a miss is never overwritten.
2. `audit-journal` already defines the `ask` event with `asked` optional, `asked_via` (mapped from the CSV via), `question_sha256`, `result_count`, `outcome` and `labels`. This card does not edit `audit/kind.rs` or `audit-samples.jsonl` (the test `every_kind_has_sample_and_no_free_text` allows one sample line per kind). Mode `off` writes no row, so the mode-off event is built with `asked: None`; step 8 tests it.
3. `io/state.rs` reads `[asked]` (`mode` of `text`, `hash` or `off`, default `text`; `keep_days`, default 365) from `settings.toml`, with its own check. An unknown key or a bad value makes `search` print one warning line, log nothing and carry on. `io/asked.rs` reads and rewrites `asked/asked.csv` through the atomic helper with a `StateScope` token; the folder and the header are created on the first row. A file that does not parse is left alone and reported in the warning.
4. `asked.rs` (binary), `log_question(world, journal, settings, policy: &EffectivePolicy, via, labels: &LabelSet, inputs: &[ItemRef], query, hits, cited) -> Logged`, where `via` is a `Via`, `labels` is the set the question was asked under, `cited` is the enum `Cited { NotChecked, Broken }` (`search` passes `NotChecked`; a caller that has checked an answer's citations and found one broken passes `Broken`) and `Logged { id: Option<AskedId> }` holds the id of the row written, `None` for a bare id, a repeat, mode `off` or a failed write: skip a bare id; take the store write lease before the journal operation and reload the row file and dependencies through that lease. Scan the question with policy.marking_rules(), union those labels with the supplied labels, and resolve the current effective input labels. Refuse retention with the existing warning if state cannot hold the result. Then check repeats and decide the outcome (`cite_failed` when `cited` is `Broken`, else `no_result` for zero hits, else `answered`); append the `ask` event first, then write the row, so no row exists without its event. In mode `hash` the `question` column holds `hashed(question)`; in mode `off` no row is written and the event has no `asked` field. When rows are older than `keep_days`, append one `purge` event (`what = asked`, `count`) before the rewrite removes them. The `fingerprint` is the Corpus fingerprint of [Scope and versioning](../reference/corpus-format.md#scope-and-versioning): the SHA-256 of one line `<sha256 hex>  <path>` for each Corpus file `search` read, sorted by path as bytes, made by the function that writes the `fingerprint` of `edition.toml`, so a row and an edition built from the same files hold the same value. The row's `labels` keeps the scanned own/request labels, and `inputs` keeps the supplied pairs so later reads can resolve current labels. With no marking, the supplied labels are: `owner-supplied` alone for `search` and for a question refused before a pack exists, and `owner-supplied` plus the pack's labels for a caller that sends a pack. `by` is `World::principal()`. The `ask` event carries the resolved label union at logging time. A later source relabel changes the row's effective labels, not the historical event. `io/asked.rs` has `set_outcome(id, to, lease: Option<&StoreLease>)`: it reuses the supplied write lease or acquires a short one for None, reads the file, applies `with_outcome`, and writes the whole file through the atomic helper with the `StateScope` token. It appends no journal event, because the `ask` event keeps the first-run outcome. An unknown id is an error that names it.
5. `search.rs` calls `log_question` with `Via::Search`, own labels `owner-supplied`, and store-qualified input pairs for exactly the hits retained in top_ids, after it has printed its results. Until policy-load wires the current policy here, pass EffectivePolicy::floor(false). Top-level search logging is outside its shared read lease; it retains the owned search result and takes a short write lease only for recording. Writes fail open: if the journal or the file cannot be written, `search` prints one warning line to stderr, `question not recorded: <reason>`, and its exit code and output are unchanged. `search` still writes nothing to the Corpus.
6. The status line. `read_state_summary` in `crates/fieldbook/src/io/mod.rs` gets this card's `StateLine`, after the lines of `status-command`: `N questions asked, M misses, K promoted`, made from `asked::summary` on the rows of `asked/asked.csv`, and no line when the file is absent or does not parse. `report` and `crates/fieldbook-core/src/status.rs` are not edited, and the snapshot test of `status` passes unchanged.
7. The fixture `state-asked` is a state folder with six synthetic rows in `asked/asked.csv` covering every outcome and state, each with labels, inputs and by, one with `np-0007|owner-supplied` and one older than a `keep_days` of 365, and a `settings.toml` with `role = "lead"` and `[asked]`. Its journal is written by `build_state(dir, events)` of `crates/fieldbook/tests/support/state.rs` (`audit-journal`) with one `ask` event for each row, and its `asked/asked.csv` by `asked::render` from the six rows. The test `state_asked_matches_the_writer` (`mod support;` in `tests/asked.rs`) rebuilds both in a temporary folder and compares the bytes. `settings.toml` is written by hand and has no writer: `state_asked_settings_parse` reads it with the `[asked]` reader of step 3. `ask-promote` reuses the fixture.
8. Tests. Core, in `tests/asked.rs`: `csv_round_trips`, `unknown_column_is_rejected`, `bare_id_is_detected`, `repeat_within_a_minute`, `expiry_by_days`, `next_id_is_above_the_rows_and_the_journal` (rows up to `A-0009` and a journal that ends at `A-0012` give `A-0013`; no rows and no journal give `A-0001`), `summary_counts_misses_and_promoted`, `with_outcome_changes_only_an_answered_row` (an `answered` row becomes `cite_failed` or `flagged`; a `no_result` row, a `flagged` row and an unknown id give `None`), `hashed_form` and `asked_parse_never_panics_on_random_and_mutated_bytes` (200 seeded byte strings from `tests/support/rng.rs`, and single-byte mutations of the fixture's `asked/asked.csv`: a typed error or a value, never a panic). Binary, in `tests/asked.rs`, on a temporary copy of `corpus-mini` and `state-mini`: `search_logs_a_miss_and_a_hit` (a word with no result writes `no_result`, a word with results writes `answered` with `top_ids`), `bare_id_is_not_logged`, `repeat_is_one_row`, `row_holds_version_and_fingerprint`, `hash_mode_keeps_no_text`, `off_mode_keeps_no_row_and_keeps_the_event` (the `ask` event is built with `asked: None`; it passes the journal validator and its line has no `asked` key), `expiry_writes_a_purge_event`, `event_holds_only_the_hash` (the journal line has no substring of the question), `event_matches_the_row`, `broken_verdict_writes_cite_failed` (a direct call with `Cited::Broken`), `set_outcome_rewrites_one_row_and_appends_no_event` (after a logged `answered` row, `set_outcome(id, CiteFailed, None)` changes that row only and appends no journal event; an unknown id is an error that names it), `unwritable_journal_does_not_stop_search` (and the log gains no row), `unwritable_log_does_not_stop_search`, `bad_settings_warn_once`, `ids_are_not_reused_after_expiry_or_a_deleted_log` (a search after every row has expired, and after the log is deleted, gets an id above the last `ask` event of the journal), `asked_settings_never_panic_on_random_and_mutated_bytes` (the same generator on the fixture's `settings.toml`: the `[asked]` reader gives a typed error or a value), `state_asked_matches_the_writer`, `state_asked_settings_parse`, `status_prints_the_question_line` (`status` on a copy of `state-asked` prints `N questions asked, M misses, K promoted` with the fixture's numbers) and `logging_adds_little` (prints the time of a logged search against an unlogged one; no failing bound). Also `inputs_round_trip_across_stores` (equal ids in different stores stay distinct; escaping survives CSV/TOML), `missing_inputs_is_not_empty`, `repeat_with_different_inputs_or_labels_writes_a_row`, `outcome_updates_keep_inputs`, `marked_search_question_is_not_retained_under_floor_a`, `row_records_labels_and_principal` (a `search` row has `labels` `owner-supplied` and `by` `local` under `TestWorld`), `a_packs_labels_are_added_to_the_row` (a direct call under a synthetic policy whose state holds np-0007, with labels np-0007 and owner-supplied, writes np-0007|owner-supplied) and, in core, `labels_column_round_trips`.

9. Register question-log rows with backup: parse the exact schema, resolve each row's own labels plus current effective inputs under the snapshot lease, and pass the union to CopiedFile. A malformed row adds unlabelled. In `tests/backup.rs`, `backup_keeps_asked_inputs` uses the real logger then backup for a permitted row; `backup_rechecks_asked_inputs` relabels only its referenced source and requires refusal for the old target; `backup_refuses_asked_missing_inputs` deletes that column and requires unresolved-data refusal. Use in-memory label fixtures available to core-policy, not future company files.

10. After A-9999, next_id returns Exhausted. A logging mode needing a new row returns `Logged { id: None }`, prints one `question not recorded: id space exhausted` warning, and writes no row or event claiming an ID; search stdout and exit stay unchanged. Mode off keeps its ID-free event. `asked_id_exhaustion_does_not_reuse_or_widen` tests A-9998 to A-9999, exhaustion from either rows or journal, and empty rows after expiry/deletion.

11. The event payload uses asked_via from the producer enum, while the CSV keeps via. The envelope via remains the actual cli/chat/mcp channel. Extend the existing logging tests to assert both values in one event.

12. Acquire state-only write authority with `journal.state_scope(&lease)?` under the retained exclusive store lease, or reuse the active operation lease. Propagate its acquisition/head errors through this producer’s existing failure path: optional saves warn and preserve the previous file and command exit; page-generation failures exit 3. No state token is fabricated on failure.

## Acceptance

```sh
cargo nextest run --locked -p fieldbook-core --test asked
cargo nextest run --locked -p fieldbook --test asked --test search --test backup
cargo build -q --locked -p fieldbook && B="$PWD/target/debug/fieldbook" && T="$(mktemp -d)" && cp -R tests/fixtures/corpus-mini/. "$T"
(cd "$T" && "$B" search zzzznotaword; echo "exit $?"; "$B" search synthetic | head -n 3; "$B" audit show --last 2; cat .fieldbook/asked/asked.csv)
just check
```

Expected: the tests pass; the first search prints the abstention phrase and `exit 1`; `audit show` ends with two `ask` events that carry `question_sha256` and no question text; the file has a header, one `no_result` row for `zzzznotaword` and one `answered` row for `synthetic` with its top ids; `just check` exits 0. Remove the temporary folder afterwards.

## Negative control

In the temporary copy, make `.fieldbook/audit/journal.jsonl` read-only and run `"$B" search zzzznotaword`: the output and the exit code must be those of an unlogged search, plus one `question not recorded` line on stderr, and `.fieldbook/asked/asked.csv` must not gain a row. Restore the journal's original write permissions before setting `[asked] mode = "off"`. Run a fresh query that is not a bare ID: require no new CSV row and exactly one new `ask` event with no `asked` field, so repeat suppression cannot mask this check. On the branch, write the row before the event in `log_question`: `unwritable_journal_does_not_stop_search` must fail, because the log gains a row with no event. Restore it.

Drop inputs during render or an outcome update, or ignore them in repeat detection: the corresponding asked tests must fail. Treat the log as label-free metadata or use saved labels alone: `backup_rechecks_asked_inputs` must fail. Skip the marking scan: `marked_search_question_is_not_retained_under_floor_a` must fail. Restore each.

Wrap, reuse or emit five digits after A-9999: `asked_id_exhaustion_does_not_reuse_or_widen` must fail. Restore each.

## Rollback

Revert the merge commit. `search` stops recording. An existing `asked/asked.csv` stays in the state folder, untracked, and the owner can delete it with no effect on the journal. The `ask` and `purge` events already written stay in the journal, which is never rewritten.

## BLOCKED

`search` has no `World` or journal at the point where it prints, because `search-cli-and-regression` built it without the state folder, and passing one in changes what `search` prints or its exit code. Set the item to Blocked with `BLOCKED: search cannot log without changing its output`, and stop. Do not log from inside the core query.
