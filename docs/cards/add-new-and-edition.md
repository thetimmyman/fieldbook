# add-new-and-edition

- **Runs where:** home, CI Linux, CI Windows
- **Schema impact:** none
- **Review:** auto

## Outcome

`fieldbook add <file> [--source <source-id>] [--metadata-only] [--confirm-public]` stores a public original byte for byte under `corpus/sources/public/`, appends its version row with the next free id and the label `public` when the person gives `--confirm-public` (without it the file is `unlabelled` and is refused, FB0410), refuses a file whose labels the store `corpus` may not hold (a marking banner is the case, FB0400), and changes nothing when the file is already in the register. It writes the original first and the register row last, each through one atomic helper, so a run that stops half way is finished by running it again. Each write appends a begin and an end event to the audit journal (AL-01).

## Why

- What `add` writes, which columns it fills, `--metadata-only` and idempotence are [Adding a version](../reference/corpus-format.md#adding-a-version). Id allocation is [Identifiers](../reference/corpus-format.md#identifiers); the stored name is the version id plus the original's extension ([Originals](../reference/corpus-format.md#originals)).
- The flags and exit codes are [AD-17](../decisions/0001-foundation.md#ad-17-authoring-experience). `add` reads the file it is given and asks `labels::for_text` (from `core-labels`) for its labels; that function wraps the marking shapes of [Scans](../reference/corpus-format.md#scans) and gives `public` to text that has none only under a named act. For `add` the act is the person's typed `--confirm-public` (`PublicAct::typed`, [How `public` is given](../reference/corpus-format.md#handling-and-labels)); without the flag the text is `unlabelled`. The target is the repository Corpus, so the store is `corpus`, which holds `public` only. A file whose labels that store may not hold is refused (FB0410 for `unlabelled`), and a marking keeps its old code, FB0400 ([ADR 0004](../decisions/0004-company-boundary.md#4-stores-and-admission)). Only `fieldbook/src/io` touches the disk ([AD-05](../decisions/0001-foundation.md#ad-05-crate-layout-and-enforcement)), and writes there go through `io::atomic`.
- Design: the [MAP.md](../design/MAP.md) row "CommandChip", for the `add` chips only. [HANDOFF.md](../design/HANDOFF.md) [§5 Components](../design/HANDOFF.md#5-components) (CommandChip). No template or style changes. No token group.

- Docs to update: `AGENTS.md` (Commands: `fieldbook add` is available), `README.md` (the quick start line for adding a source), `cli.md` through `cargo xtask docs`, `corpus-format.md` (in "Adding a version", delete the bullet that says the lead copies the file by hand until this card lands, so there is one way to add a source), `CHANGELOG.md` (`- Added: the add command.` under `## Unreleased`).

## Out of scope

- `new` (`new-verbs`), extraction (`extract-and-locators`), the edition (`edition-zips`).
- A target other than the repository Corpus. `add` into a company store (the store `overlay`, which holds the labels its policy lists and keeps the original under `sources/org/`), the labels that a marking maps to there, and the person's confirmation of a proposed label belong to `r2-org-intake`, which builds on `core-labels`. Here a marking is refused, as it always was.
- Completing the row. The cells `add` cannot know stay empty, and `check` reports them until the lead fills them.

## Preconditions

- Cards merged: `check-scans`, `core-labels`, `audit-journal`.
- This card merges before `core-policy`, which turns the helper of `io/atomic.rs` into two doors, and so before `build-v0` and every `build-*` card, which need `core-policy` (`build-v0` asks it for the `Allowed` token). It does not run beside any of them, and it cannot wait for `build-v0`: that would be a cycle. It never runs beside a card that edits `cli.rs`.

## Steps

1. In `fieldbook-core/src/add.rs`, a pure `plan_add(model, file_name, sha256, options, completed: Option<&CompletedSourceCells>, today) -> Result<AddOutcome, AddError>`, where `enum AddOutcome { Present(VersionId), Planned(AddPlan) }`. It returns `Present(version_id)` when the hash is in `sources.csv`, otherwise `Planned(AddPlan)` with the new row, with `handling` set to `public` and the three origin cells empty, and the stored name. The binary validates that `--source` exists before calling the planner, else exits 2; a valid option takes the next version of that source. `AddPlan { ids, files: Vec<WriteFile>, sources_csv: Vec<u8> }` carries the ids and, for each file, its path and SHA-256, and no labels: `add.rs` builds the `WriteSet` of `audit-journal` from it and adds the labels.
2. In `io/atomic.rs`, one helper that writes a file: it writes to a temporary name in the same folder, flushes and syncs it, then renames it into place, and returns the SHA-256 of what it wrote. `io` writes files only through it. A failure leaves no partial file and exits 3. If the rename fails with a sharing violation or access denied (Excel can hold the target open on Windows), the helper retries 3 times, 200 ms apart, then returns `Error::InUse(path)`: exit 3 and the message `<file> is open in another program; close it and run the command again`. It removes the temporary file. Because the original is written first and the row last, a rerun finishes the job. There is no new check code. `Journal::begin(&lease, &intent, &write_set)` appends `write.begin` and returns the `Audited` token; `Journal::end(token, outcome)` appends `write.end`. `io_writes_only_through_atomic` accepts raw filesystem calls only in `atomic.rs` and `journal.rs`. `World` gains `write_file(&self, audited: &Audited, path: &Path, bytes: &[u8]) -> Result<Sha256, Error>`; `Disk::write_file` calls this helper, and `add.rs` writes every file through `world.write_file`, so a test can fail a write by name. `new`, `fmt` and `verify` write through the same method when they land. Add `World::has_company_store(&self) -> bool`; Disk returns false, TestWorld adds `set_company_store(bool)`, and FaultyWorld forwards it. `build-v0` extends the raw writer scan with audited folder helpers; this card adds no raw directory writer outside atomic.rs or journal.rs.
3. In `add.rs`, take `world.write_lease()`, open the journal, then read the tree with `world.read_tree_under(&lease)` and the file, and call `labels::for_text(text, &MarkingRules::builtin(), &context)` from `core-labels`, which wraps the marking scan from `check-scans` (a marking with no rule gives `marked`; text with none gives `public` under a named act and `unlabelled` without one). Define `pub fn label_context(world: &dyn World, confirm_public: bool) -> Result<LabelContext, Refusal>` in `add.rs`, the single caller of `PublicAct::typed`: the flag yields `LabelContext::act(PublicAct::typed(world.has_company_store(), true)?)`; no flag yields `LabelContext::none()`. Direct add, folder proposal and home new commands call it once per run. An FB0822 from this helper appends one refuse event with reason `label`, hashes and no matched text, prints `refused <file>`, exits 1 and makes no content write. Then call `labels::admit(&labels, &StoreRule::corpus())`. A refusal stops with exit 1 before anything is written. Text with a marking gives FB0400, with or without the flag: the repository Corpus keeps the old code, and `scan-allow.toml` keeps its meaning. Text with no marking and no flag is `unlabelled` and gives FB0410. A refusal appends one `refuse` event (code, `sha256`, `name_sha256`, `labels`, and `reason`: `store` for a marking, `unlabelled` for FB0410) and no begin. The event holds the label ids and never the text that matched. Only after labelling, admission, `--source` validation and resolving matching pending intent under the write lease as in step 7, call `plan_add` and match its outcome. When no matching intent exists, `Present` writes nothing and appends nothing. For `Planned(plan)`, build the `WriteSet` (the labels above and `plan.files`) and call `Journal::begin`, so a plan is never made from a tree that another writer is changing, and apply the plan in this order: the original first (not for `--metadata-only`), the complete `plan.sources_csv` register last through `world.write_file`. For a pending add, compare the replanned complete WriteSet against PendingWrite and require each existing file to match its before or after hash. An original already at the planned name with the after hash is retained, so the matching rerun adds only the missing row. An unrelated pending verb or different plan is refused. Print one line: `added <version-id> <file>`, `present <version-id> <file>` (exit 0, nothing written) or `refused <file>` (exit 1).
4. Add the `add` subcommand to `cli.rs` with the flags of AD-17, `--confirm-public` among them, and remove `add` from the `NOT_BUILT` list of `verbs_match_ad17` in `crates/fieldbook/tests/cli.rs`. `add` has a chip in `strings`, so `every_verb_has_a_chip` from `check-command` keeps passing. Remove `fieldbook add <file>`, `fieldbook add <file> --source <source-id>` and `fieldbook add <folder>` from the existing PENDING list created by check-command. The folder placeholder already parses as a path; retain the unbuilt --propose chip.
5. Tests in `tests/add.rs`, each on a temporary copy of `tests/fixtures/corpus-mini` made by `temp_copy(fixture: &Path) -> tempfile::TempDir` in `crates/fieldbook/tests/support/mod.rs` (every test that expects `added` passes `--confirm-public`). `FaultyWorld { inner: TestWorld, fault: Fault }` is in `crates/fieldbook/tests/support/faulty.rs`, built by `FaultyWorld::new(inner: TestWorld, fault: Fault)`, with `enum Fault { FailOnName { name: &'static str, kind: FaultKind } }` and `enum FaultKind { Io, InUse }`. Its `write_file` returns `Error::Io` (kind `Io`) or `Error::InUse` (kind `InUse`), before anything is written, for a path whose last component is `name`, and forwards everything else to `inner`, including `write_lease` and `read_tree_under` from audit-journal. `backup-snapshot` and `add-folder-mode` use it with no new file. The tests: `adds_a_new_source`, `adds_a_version_with_source`, `metadata_only_copies_nothing`, `second_add_changes_nothing`, `copy_is_byte_exact`, `marking_banner_is_refused_and_tree_unchanged`, `add_without_confirmation_is_refused_fb0410` (no flag: exit 1, FB0410, one `refuse` event with `reason` `unlabelled`, no `write.begin`, tree unchanged), `add_with_confirmation_is_public` (the row is `public`, and the `write.begin` event carries `labels` `[public]` and the actor), `add_marked_text_is_refused_even_with_confirmation` (FB0400 with the flag), `unknown_source_is_a_usage_error`, `add_recovers_after_register_write_before_end`, `rerun_after_interruption_completes` (a `FaultyWorld` with `FailOnName { name: "sources.csv", kind: Io }` leaves the original and no row; a rerun with a working `World` adds one row and no second file), `io_writes_only_through_atomic` (a scan of `crates/fieldbook/src/io/*.rs` finds no raw `rename`, `create` or `write` outside `atomic.rs` and `journal.rs`), `add_writes_begin_then_end`, `refused_add_is_journaled`, `refused_add_names_store_and_labels`, `interrupted_add_is_visible_then_completed` (ordinary readers refuse the pending generation until recovery; a different command cannot use it; a `FaultyWorld` with the same fault on `sources.csv` fails the row after the original: `audit verify` warns FB0803; the rerun completes the row and the warning goes), `no_write_without_journal` (a read-only journal: `add` exits 3 and no Corpus file exists), `held_open_target_is_in_use` (`cfg(windows)`, the real helper: the test opens the target with share mode none; `add` retries, exits 3 and prints the `InUse` message), `in_use_fault_exits_3_and_names_the_file` (a `FaultyWorld` with `FailOnName { name: "sources.csv", kind: InUse }`: `Error::InUse`, exit 3, the message names `sources.csv`, and a rerun with a working `World` finishes the row) and `a_failed_rename_leaves_no_temporary_file` (the real helper; the planned path of the original is an existing non-empty folder, so the rename fails: exit 3 and no temporary file in the folder). Add `duplicate_without_confirmation_is_refused` and `duplicate_marked_text_is_refused`: pre-seed the matching hash, then require FB0410 without confirmation or FB0400 with marked text, one refusal and no writes. Add `typed_public_act_is_refused_with_a_company_store`: `TestWorld::set_company_store(true)`, flag given, exit 1, FB0822, one `refuse` with reason `label`, no `write.begin`, unchanged tree.
6. Run `cargo xtask docs` and commit the regenerated `cli.md`.

7. Before ordinary `Present` handling, after label, admission and option checks, resolve matching pending add intent under the write lease. If the original and register already have all recorded after-hashes, finish the original transaction, publish the generation and remove the descriptor without rewriting content or adding a begin. Refuse a different intent or any third hash. `add_recovers_after_register_write_before_end` checks reader refusal before recovery, success afterward, and an unchanged subsequent rerun; restoring an early `Present` return must fail it. A real addition puts its source/version reference in both write events; `audit show --id` finds both, and deleting those references fails the test.

8. AddError carries the allocator Exhausted value. Report `<family> id space exhausted`, exit 2, no content change and no write.begin. The existing duplicate and matching-recovery paths run before fresh allocation. `source_id_exhaustion_writes_nothing` in `tests/add.rs` fills the public source space through 9999 and exercises the real handler; duplicate and matching recovery still succeed at the limit.

9. `first_add_initializes_state` in `tests/add.rs` calls the real confirmed-add handler on a fixture with no state folder. Require success, stable lock files and one closed write transaction.

10. Build the add OperationKey from verb, destination store and the input content hash; normalize the canonical input-path hash, filename, input hash, source option, metadata-only and confirmation through the shared request hash. `io/root.rs` supplies `input_path_sha256(&Path) -> Result<Sha256, Error>`: canonicalize the existing input, encode Unix paths as raw OsStr bytes and Windows paths as UTF-16LE code units, and hash ASCII `input-path 1\n`, S(OS tag `unix` or `windows`), then the byte-length-framed lossless path bytes. S is decimal byte length, colon, bytes; no lossy display conversion. Only this digest enters normalization; persist only the request hash, never the path. Direct and folder adds use this same helper; ordinary Present deduplication remains content-based. Supply original allocations and captured planning date in OperationIntent to begin. Recovery first reuses the stored allocations/date and compares the complete replan before resuming.

11. Define `CompletedSourceCells` in core add.rs as a validated map of the ten source cells title, publisher, source_kind, authority_tier, licence, published, effective_from, volatility, tag and purpose. `CompletedSourceCells::parse(&BTreeMap<String, String>) -> Result<Self, AddError>` uses the existing source cell rules and rejects unknown/reserved fields. Define `render_source_row(base: &SourceRow, completed: Option<&CompletedSourceCells>) -> Result<Vec<u8>, AddError>`: apply only those cells and serialize through the existing CSV writer, preserving allocated IDs, hash, location, handling, lifecycle and other reserved defaults. plan_add assembles `sources_csv`, the complete replacement register with every existing row retained, through the existing CSV writer; the planned sources.csv hash covers exactly those bytes. Direct add writes this payload, never only the appended row. Direct add always passes None and stays byte-identical. `completed_cells_preserve_reserved_defaults` covers suggestion/edit values, invalid cells and reserved-field rejection; `direct_add_row_bytes_are_unchanged` pins direct output. Later admission composes extraction files around this row rather than inventing a row renderer.

12. In `io/root.rs`, supply `git_context(world, destination) -> Result<GitContext, Error>` before later consumers: resolve the canonical target and ancestors, determine under_git, and set ignored_home_state only for the actual Home preset, verified ignore coverage and component containment in its resolved State root, including its drill. Read existing configuration through World, with no new writer or core filesystem access. Custom State without verified ignore coverage has no exception. Use this helper wherever git_guard is called; later Laptop layout supplies its preset and always has ignored_home_state=false. Test canonical containment, false prefix matches, unignored State and a sibling target. Preserve independent placement/admission rules.

13. Extend the add payload/hash tests: completed and edited cells, reserved defaults and all existing rows survive in the complete sources_csv; direct add remains byte-identical. The metadata hash must equal those exact payload bytes. Centralize refusal event mapping at the shared add boundary: FB0410 -> unlabelled, FB0400 -> store, FB0822 -> label, FB0821 -> store. Keep type checking first and include only hashes/labels already known, never invented labels.

## Acceptance

```sh
cargo nextest run --locked -p fieldbook --test add
cargo build -q --locked -p fieldbook && B="$PWD/target/debug/fieldbook" && T="$(mktemp -d)" && cp -R tests/fixtures/corpus-mini/. "$T" && printf 'Synthetic text, made up for tests.\n' > "$T/synthetic.txt"
(cd "$T" && "$B" add synthetic.txt --confirm-public && "$B" add synthetic.txt --confirm-public && "$B" check --strict --today "$(date -u +%F)"); echo "exit $?"
cargo xtask docs --check
cargo nextest run --locked -p fieldbook --test chips
just check
```

Expected: the tests pass; the first `add` prints `added` and a new version id, the second prints `present` and the same id and adds nothing; `check` then reports FB0205 for the empty cells of that one new row and nothing else, and `exit 1`; `cargo xtask docs --check` and `just check` exit 0. The date is the clock's because `add` stamps `retrieved` with the day it runs.

## Negative control

In a fresh temporary copy of tests/fixtures/corpus-mini, separate from Acceptance, write a file outside its corpus/ whose first line is one of the banner shapes in [Scans](../reference/corpus-format.md#scans) and run `"$B" add` on it there. It must exit 1 and print an FB0400 line, `audit show --kind refuse` must show one event with `reason` `store` and the label `marked`, and `diff -r tests/fixtures/corpus-mini/corpus "$T/corpus"` must print nothing. Then write a plain text file with no marking and run `"$B" add` on it without `--confirm-public`: it must exit 1 and print an FB0410 line, and the tree must be unchanged. Remove the copy. Then write the row before the original in `add.rs`: `rerun_after_interruption_completes` must fail. Restore it. Then, in a temporary copy, make the journal file read-only: `add` must exit 3 and leave the Corpus unchanged. Then make `add` exit 1 for `Error::InUse`: `in_use_fault_exits_3_and_names_the_file` must fail. Restore it. Then leave the temporary file in place when the rename fails: `a_failed_rename_leaves_no_temporary_file` must fail. Restore it.

Ignore `has_company_store`: `typed_public_act_is_refused_with_a_company_store` must fail. Restore it.

Return Present before labelling and admission: `duplicate_without_confirmation_is_refused` and `duplicate_marked_text_is_refused` must fail. Restore it.

Return `Present` before resolving pending intent: `add_recovers_after_register_write_before_end` must fail. Remove source/version references from write events: the `audit show --id` assertion must fail. Restore each.

Restore any removed add chip in PENDING: the chip parser test must fail. Restore the list.

Permit allocation beyond the source limit: `source_id_exhaustion_writes_nothing` must fail. Restore it.

Drop a completed cell, accept a reserved override or change direct defaults: the completed-cell and direct-output tests must fail. Restore each.

Change sources_csv bytes without changing their planned hash, or drop an existing register row: the payload/hash tests must fail. Restore each.

## Rollback

Revert the merge commit. Originals added with `add` stay in the Corpus; they are ordinary committed files, and the lead adds the next ones by hand again.

## BLOCKED

The marking scan from `check-scans`, or `labels::for_text` from `core-labels`, cannot be called on a single file's text from outside `check::run`: set the item to Blocked with a `BLOCKED:` comment that says so, and stop. Do not copy the banner shapes into this card's code.
