# check-ci-and-docs

- **Runs where:** home, CI Linux
- **Schema impact:** none
- **Review:** auto

## Outcome

`fieldbook check --strict` runs on the real `corpus/` wherever a pull request is judged: as step 7 of `just check`, and in a `corpus` job that `ci-ok` needs, both with the commit date as today. `cargo xtask docs` also writes `docs/reference/cli.md` from the program's own definitions, and `docs --check` diffs it. A job `changes` says whether code or the Corpus changed, so that a docs-only pull request skips the gated jobs that later cards add; `ci-ok` needs every job, and a test fails when it does not.

## Why

- Step 7 of `just check` is `fieldbook check --strict` ([AD-07](../decisions/0001-foundation.md#ad-07-developer-tooling)). The `corpus` job downloads the binary the `rust` job uploads, and `ci-ok` needs it ([AD-08](../decisions/0001-foundation.md#ad-08-ci-design)).
- The flags, the `--strict` rule list and the report layout are in `cli.md`, generated with the card that adds `check` and diffed in CI ([AD-17](../decisions/0001-foundation.md#ad-17-authoring-experience), [AD-22](../decisions/0001-foundation.md#ad-22-agentsmd-and-the-docs-set)). The [Check catalogue](../reference/corpus-format.md#check-catalogue) says that `cli.md` prints the strict rules by code.
- A run takes its date from the commit, not the clock ([Dates](../reference/corpus-format.md#dates)). The download action and its pin are in [CI actions](../reference/dependencies.md#ci-actions).
- A job missing from `needs` of `ci-ok` is never required, and a card with `Review: auto` is merged on a green `ci-ok` ([the README](README.md#closing-a-card)); the test `ci_ok_needs_every_job` makes the omission a failure. The job `changes` is the one place that decides what changed ([AD-08](../decisions/0001-foundation.md#ad-08-ci-design), Gated jobs). A gated job still finishes with success and skips its steps, because `ci-ok` accepts only `success`. The recipe for a new job is "Adding a CI job" in the [README](README.md#adding-a-ci-job).

## Scope

- Files: `.github/workflows/ci.yml`, `justfile`, `xtask/Cargo.toml`, `xtask/src/{main.rs,cli_doc.rs}`, `Cargo.lock`, `.config/tools.toml` (the `[lock]` record only), `.config/lock-inputs/`, `crates/fieldbook/src/{lib.rs,cli.rs}`, `docs/reference/cli.md` (generated), `.github/scripts/changes.sh`, `xtask/tests/ci_workflow.rs`.
- Registration lines: `docs/reference/dependencies.md` (add xtask to the clap Used by cell); `xtask/src/docs.rs` (one row of `GENERATORS`); `AGENTS.md` (Commands: step 7 of just check; Where things live: cli.md and errors.md).
- Docs to update: `docs/reference/cli.md` by `cargo xtask docs`; `AGENTS.md` (Commands: step 7 of `just check` runs `fieldbook check --strict`; Where things live: `cli.md` and `errors.md`).

## Out of scope

- `build`, the Edge harness and the `windows` job in CI (`build-v0` and `edge-harness`; `windows-facts` creates the `windows` job and `transfer-and-windows-drill` extends it).
- Gating `rust` or `corpus` by `changes`. They always run, because they check the docs and the Corpus.
- Any new check code. The 01 to 04 ranges arrive with `check-files` to `check-scans`.
- The card, plan and link lint (`docs-checks`).
- Any edit under `corpus/`.

## Preconditions

- Cards merged: `check-known-bad`.

## Steps

1. In `justfile`, replace the step-7 comment of `check` with `cargo run -q --locked -p fieldbook -- check --strict --today "$(git log -1 --format=%cs)"`, under a comment line that says what step 7 is.
2. In `crates/fieldbook/src/cli.rs`, give the four exit codes of AD-17 one named value each with a one-line meaning, and use those values where the program exits. Make the clap `Cli` public from `lib.rs`. The behaviour of `check` does not change.
3. In `xtask/Cargo.toml`, add `fieldbook = { path = "../crates/fieldbook" }` and `clap = { workspace = true }`. Add xtask to the clap Used by cell in `dependencies.md`. Follow the dependency recipe: run `just lock`, review its lock/replay inputs, then `just lock-verify`; retain `cargo xtask deps --check` and `cargo deny check`.
4. Write `xtask/src/cli_doc.rs`. It prints `cli.md` from: the clap `Command` (each verb, its arguments and flags with their help text, value names and defaults, and `--version`); the exit codes of step 2; one row for each `Code` whose level is strict, with the check text the catalogue row gives it (reuse the catalogue parser of `errors.rs`); and the `--json` layout of the `check` report, read from the golden `tests/golden/json/check.json` that `check-command` wrote: each key with its JSON type, `report_version` first. The first line says the file is generated by `cargo xtask docs` and is not edited by hand. Nothing in it is typed into `cli_doc.rs` except headings and that line. A final section, "JSON reports", prints each golden of `tests/golden/json/` under a heading with the name of its report. The goldens exist when this card runs only for `check`; later cards add theirs, and the section grows with them.
5. Register `cli` in `GENERATORS`, so `cargo xtask docs` writes `cli.md` and `--check` compares it, naming the file and the first differing line.
6. Tests in `xtask`, named `docs::cli::...`: the strict rows equal the catalogue codes whose severity is `strict`; every flag of `check` appears in the text; two runs give the same bytes.
7. In `ci.yml`, add the job `corpus`: `needs: [rust]`, `ubuntu-24.04`, `timeout-minutes: 20`, the pinned `actions/checkout` as in `rust` with `persist-credentials: false`, the pinned `actions/download-artifact` for `fieldbook-dev`, a step that marks the binary executable (an artifact loses its file mode), a step that runs it as `./fieldbook check --strict --today "$(git log -1 --format=%cs)"`, then the toolchain install and `cargo xtask docs --check`. Leave `permissions: contents: read` as it is. Add `corpus` and `changes` (step 8) to `needs` of `ci-ok`, written as a one-line list such as `needs: [rust, corpus, changes]` (the test of step 9 requires one line), and correct the header comment that says the job is still to come.
8. Write `.github/scripts/changes.sh BASE`. It prints two lines, `code=true|false` and `corpus=true|false`. When `BASE` is empty or all zeros, or `git diff --no-renames --name-only "$BASE" HEAD` fails, it prints `code=true` and `corpus=true`. Otherwise it collects paths with that same no-renames command and reads the changed paths and, for each, in this order: a path under `corpus/` sets `corpus` (so a `corpus/*.md` file sets `corpus` and not `code`); a path under root `tests/`, `crates/` or `xtask/` sets `code`, including Markdown fixtures; a path under `docs/` or ending `.md` sets neither; any other path sets `code`. In `ci.yml` add the job `changes`: `ubuntu-24.04`, `timeout-minutes: 10`, the pinned `actions/checkout` with `fetch-depth: 0` and `persist-credentials: false`, and the outputs `code` and `corpus`, read from one step with `id: scan`. That step sets `BASE` from environment variables, not from an expression inside the script: `github.event.pull_request.base.sha` on a pull request, `github.event.before` on a push, and empty on any other event. It then runs `bash .github/scripts/changes.sh "$BASE" >> "$GITHUB_OUTPUT"`. `rust` and `corpus` do not read `changes`.
9. Write `xtask/tests/ci_workflow.rs`, a plain text scan with no YAML crate. `ci_ok_needs_every_job` collects the keys indented by two spaces under `jobs:` of `.github/workflows/ci.yml`, reads the `needs:` list of `ci-ok` (it must be a one-line `[a, b]` list; the test fails with "needs of ci-ok must be a one-line list" when it is not) and fails naming every job id, other than `ci-ok`, that the list lacks. `changes_script_classifies_paths` builds a temporary git repository with a base commit and runs the script after one more commit for each case: `crates/x/src/lib.rs` gives `code=true corpus=false`; `docs/a.md` and `README.md` give both false; `corpus/pages/a.md` gives `corpus=true code=false`; `corpus/registers/a.csv` with `justfile` gives both true; `.github/workflows/ci.yml` gives `code=true corpus=false`. `changes_script_fails_open` runs it with an empty base, forty zeros and a sha that is not in the repository: each prints both true.
10. Run `cargo xtask docs` once and commit `cli.md`. Update `AGENTS.md`.

11. Extend `changes_script_classifies_paths` with Markdown fixtures under each of root tests/, crates/ and xtask/ (code=true, corpus=false). Enable rename detection in the temporary repository; unchanged-content code-to-docs and Corpus-to-docs renames must yield code=true/corpus=false and code=false/corpus=true respectively. Retain ordinary documentation cases.

## Acceptance

```sh
cargo nextest run --locked -p xtask docs::
cargo nextest run --locked -p xtask --test ci_workflow
cargo xtask docs --check
cargo run -q --locked -p fieldbook -- check --strict --today "$(git log -1 --format=%cs)"; echo "exit $?"
just lock-verify
just check
```

Expected: the tests pass; `docs --check` exits 0 and prints `docs: up to date`; `check` prints its summary line and `exit 0`; `just check` exits 0 and its output shows the step-7 summary. The pull request's `ci-ok` run lists a green `corpus` job and a green `changes` job. On a pull request that changes only files under `docs/`, the log of `changes` shows `code=false` and `corpus=false`.

## Negative control

Change one word of the generated `cli.md` by hand. `cargo xtask docs --check` must exit 1 and name `docs/reference/cli.md` and the line. Restore it with `cargo xtask docs`. Then change the step-7 date in the `justfile` to `--today 2025-02-30`: `just check` must stop at step 7 with exit code 2. Restore the line. Then add a job `x:` to `ci.yml` without adding it to `needs` of `ci-ok`: `ci_ok_needs_every_job` must fail and name `x`. Remove the job. Last, in `changes.sh` test `.md` before `corpus/`: `changes_script_classifies_paths` must fail on the `corpus/pages/a.md` case. Restore the order.

Remove `--no-renames` or put the Markdown-suffix exclusion before fixture roots: `changes_script_classifies_paths` must fail the rename or fixture cases. Restore each.

## Rollback

Revert the merge commit. Step 7 returns to a comment, `ci-ok` no longer needs `corpus` or `changes`, and `cli.md`, the script and the test go with the revert. A later card whose job has `needs: [changes]` (`windows-facts` and the cards after it) is reverted first. The ruleset requires only `ci-ok`, so it needs no change.

## BLOCKED

- Step 7 fails on the lead's committed Corpus: write the code and the file and stop. Codex may not edit `corpus/` before `guard-statuses`.
- The dependency-policy checks fail, or the `corpus` job needs a permission or a secret (release gate): write what and stop.
