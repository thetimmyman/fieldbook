# pipeline-ports

- **Runs where:** home, CI Linux
- **Schema impact:** none
- **Review:** owner

## Outcome

The four intake stages exist as typed ports. `Extractor` has the shape of the port contract, and `Classifier`, `Correlator` and `Admit` are new traits in `fieldbook-core::pipeline` (their signatures are in steps 4a and 6) with the data they pass: `Candidate`, `Vocab`, `Suggestion`, `Suggestions`, `Support`, `Link`, `CorpusView`, `Proposal`, `Edits`, `StageError` and `AdmitError`. A proposal file (`queue/P-nnnn.toml`) parses and renders to the same bytes. `corpus-add@1` turns a `new_source` or `new_version` proposal into one ordered list of planned writes and refuses every other kind as not built, `TARGETS` lists what a proposal may write (one row, `sources`), and `staged@1` reads `staging/<sha256>/`. Each stage has a contract suite, and `ADAPTERS` has two new rows. No verb calls any of this yet: `add --propose` and `queue` are `review-queue`.

## Why

- Intake is a chain of ports so that the rules, the correlator and a model can be swapped without touching the writer, and so that a proposal can come from a person, a sweep or a model and still be admitted by one path ([AD-01](../decisions/0001-foundation.md#ad-01-architecture), Ports and One gate). The proposal is state, not Corpus: it holds extraction text and model output, which stay out of git, editions and the journal.
- The classifier may suggest only ten `sources.csv` columns in the Corpus and an eleventh, `doc_kind`, in a company store ([ADR 0004](../decisions/0004-company-boundary.md)). A closed `SuggestField` enum makes that a type: `source_role`, `source_family`, `family_basis`, `as_of`, `lifecycle`, `handling`, `series` and the three origin cells have no variant, so no classifier, rules file or model reply can fill them. `Vocab::fields()` says which of the eleven a store offers: `Vocab::from_schema()`, which the Corpus uses, offers ten and never `doc_kind`. A label is not a column the classifier writes either: the `labels` of a candidate come from the labeller and nothing else. A classifier may return a `LabelHint`, a real label id for a person to confirm in a company store ([step 3](#steps)); a hint changes no label by itself, and the repository Corpus, which holds `public` only, drops every hint. Only a person's acceptance admits content, and the accept order (original, extraction, `extraction.toml`, row last) is what lets a crash be finished by running `queue accept` again ([Adding a version](../reference/corpus-format.md#adding-a-version), FB0211).
- A stage may defer to a Handoff pack, so `Classifier` and `Correlator` return `Result<_, StageError>` with `Deferred(HandoffTicket)`. `rules@1` never defers. Core never sees a model: a model-backed stage is a binary type that implements the core trait (`pipeline-model-adapters`).
- `Correlator` takes an `&dyn IndexPort`. That trait is data and a function signature, so it is written here, in `ports/index.rs`; `pipeline-correlate` implements it over the BM25 index, and `index-output-ports` later adds `merge_exact_first` beside it.
- The recipes are [Adding an adapter to a port](README.md#adding-an-adapter-to-a-port) [Adding a proposal kind](README.md#adding-a-proposal-kind) and [Adding an intake target](README.md#adding-an-intake-target). The proposal's keys are written out in `tests/fixtures/queue/new_source.toml` and in the doc comment of `proposal.rs`; its codes are in [08: audit, backup and pipeline](../reference/corpus-format.md#08-audit-backup-and-pipeline). No document lists the kinds by hand. The kind `reclassify` moves a source version to another `doc_kind` or `series` and changes nothing else: this card defines and parses it, `review-queue` lists it as not built, and `r2-org-intake` admits it. `TARGETS` is the one list of what a proposal may write: it has the row `sources` here, `r2-records` adds `records`, and the drift check `targets_have_known_bad` keeps every row backed by valid and known-bad proposals.
- No page, template or string shown in a browser is built here, so there is no Design bullet.

## Steps

1. `extraction.rs` and `xtask/src/extract.rs`: give `Extractor` the shape of the port contract: `id()`, `accepts(ext, head) -> bool` and `extract(bytes, ext) -> Result<Extraction, ExtractError>`, where `ExtractError` is the enum of `extract-and-locators` (`NotText`, `TooLarge { bytes: u64 }`, `ToolMissing(String)` and `ToolFailed { status: i32 }`), kept as it is, and gains one variant, `Missing(&'static str)`, the thing that was not found (`staged@1` says `"staging folder"` and `"matching staging folder"`; `extract-xlsx-sheets` adds `NotWorkbook` in its own card). No variant carries the extractor's name: the line that `extract` and `run_pipeline` print is the extractor's `id()` and the cause, and `extract` prints a `Missing` as it prints `NotText` (one line, no folder written, exit 1). Move `Plain`, `HtmlStrip`, `extraction::select` and `PdftotextLayout` to it. No byte of any extraction changes: the `xtask` extract tests and the `corpus-mini` extraction must pass untouched, and `extractor_contract` keeps its cases (empty and malformed vectors and expected refusals are declared per adapter; malformed text is `NotText`, missing staged data is `Missing`, malformed workbook data is `NotWorkbook`; each refusal names the extractor) and calls `extract(bytes, ext)`.
2. `ports/index.rs`: `Scope` (a list of unit kinds from [Document units](../reference/search.md#document-units); empty means everything), `Query { text, scope, limit }`, `Tier { Exact, Ranked }`, `Hit { unit, score, tier }`, `Hits`, `IndexError` and `trait IndexPort { fn id(&self) -> &'static str; fn query(&self, q: &Query) -> Result<Hits, IndexError>; }`. Types and the trait only; no implementation here.
3. `pipeline/candidate.rs`: `Candidate { file, sha256, bytes, ext, labels, origin, extraction }`, where `file` is a name relative to the inbox, `origin` is the `Origin` of a pulled file (`sync` sets it) or none, `labels` is the `LabelSet` that `labels::for_text` gives the extraction text in the context of the store the proposal targets (`LabelContext::act(..)` for `corpus-add@1`, built by `add::label_context` for the run (given `--confirm-public`, `public` unless a marking is found; without the flag `add --propose` refuses a Corpus file before a candidate exists), and `LabelContext::store(&StoreRule)`, the profile of a company store, for `overlay-add@1`, so what a source rule gives or `unlabelled`) and `extraction` is the `Extraction` of step 1 or none. Two pure helpers: `first_line()`, the first non-empty line of page 1 and its page, and `first_words(n)`, the first `n` words of page 1. `SuggestField`, the closed enum of eleven fields: the ten of the Corpus (`title`, `publisher`, `source_kind`, `authority_tier`, `licence`, `published`, `effective_from`, `volatility`, `tag`, `purpose`) and `doc_kind`, whose values are `DocKind::ALL`. `Vocab`, built by `Vocab::from_schema()`: the allowed values of `source_kind`, `authority_tier` and `volatility` from the schema, and the cell rule (form and length, FB0204) of the others. `Vocab::fields()` lists the fields the vocabulary offers. `from_schema()` offers the ten of the Corpus and never `doc_kind`; the vocabulary that offers the eleventh is `Vocab::for_store` of `r2-org-intake`. Rules files, classifier schemas and reply readers read the list, so a store that offers another field needs no change to them. `LabelHint { label, support, by }` is a real label id (`public`, `unlabelled` and `marked` are not accepted), the `Support` that justifies it and the adapter; `validate` drops a hint whose id is not in the `LabelTable` or whose support does not hold, and the stage's `Suggestions` (step 4a) carries `hints` beside its fields. A hint is shown at review as a proposal and applied only by a person who may add that label (`labels::change::may_add`); it never lowers a label, and the proposal's own `labels` are never a hint.
4. `pipeline/suggest.rs`: `By` (`rules@1`, `exact-ids+bm25@1`, `model:<adapter>:<model id>`, `person` or `origin`, with `parse` and `format`; `origin` is the value that a stream declares in `systems.toml`, and only `sync` writes it), `Support::{Quote { page, quote }, Id { id, score }, Origin { system, stream }}`, `Suggestion { field, value, by, support, rule: Option<RuleRef> }`, `LinkKind { VersionOf, Related, Answers, Present }`, `Link { kind, target, by, support: Vec<Support> }` (never empty) and `StageError { Deferred(HandoffTicket), Failed(Fb) }`. A `Present` link is supported by one `Support::Id { id: <the version id>, score: 0 }`: an exact hash match has no score. One pure `validate(&Suggestion, &Candidate, &Vocab) -> Result<(), DropReason>` keeps a suggestion only when its field is one that `vocab.fields()` lists (otherwise `DropReason::FieldNotOffered`), its value is in the vocabulary or obeys the cell rule and every `Quote` support is found on its page by the claim-quote match, and keeps a suggestion `by = origin` only with an `Origin` support that names the candidate's `origin` system and stream, so a classifier or a model cannot return one. Rules and model adapters both call it; `pipeline-model-adapters` raises FB0823 from its result.
4a. `pipeline/suggest.rs` also holds `Suggestions { fields: Vec<Suggestion>, hints: Vec<LabelHint> }`, the value that a classifier returns, and the two stage traits: `pub trait Classifier { fn id(&self) -> &'static str; fn classify(&self, candidate: &Candidate, vocab: &Vocab) -> Result<Suggestions, StageError>; }` and `pub trait Correlator { fn id(&self) -> &'static str; fn correlate(&self, candidate: &Candidate, view: &CorpusView, index: &dyn IndexPort) -> Result<Vec<Link>, StageError>; }`. `id()` is the adapter's id as `ADAPTERS` names it (`rules@1`, `exact-ids+bm25@1`), the same string that `By` carries. A correlator returns links and builds no `Suggestion`: `run_pipeline` (`review-queue`) reads the text of the question that an `Answers` link names through `CorpusView` and makes the `purpose` entry itself. The suites of step 10 call exactly these signatures.
5. `pipeline/proposal.rs`: `ProposalKind` (`new_source`, `new_version`, `regression_case`, `gap_question`, `note`, `decision`, `reclassify`) with `fn target(&self) -> Option<&'static str>`, the id of the row of `TARGETS` (step 6a) that the kind writes: `sources` for `new_source`, `new_version` and `reclassify`, and none for the others, which a later card may give a row, `ProposalState` (`proposed`, `accepted`, `rejected`, `stale`), `Judged { value, by, because, rule: Option<RuleRef> }`, `RowBody` (a map from `SuggestField` to `Judged`), `Links`, `AiRecord { request_labels: LabelSet, inputs: Vec<ItemRef>, calls, dropped }` and `Proposal { id, state, kind, labels, writer, origin, candidate, extraction, source_choice: Option<SourceChoice>, body, hints, links, ai }`. `body` is `Row(RowBody)` for the first two kinds, `Reclassify { source_version, doc_kind, series }` for `reclassify` (the table `[reclassify]`: `source_version` is a version id, `doc_kind` is empty or a word of `DocKind::ALL`, `series` is empty or has the form `vocab::stream_id_form`, and at least one of the two is not empty; a file with any other value does not parse) and `Opaque(table)` for the others, kept verbatim. `parse` requires `candidate` for the two source kinds; `extraction` is optional, omitted when unavailable and validated when present: a `reclassify`, like the opaque kinds, has no file. The keys are `proposal_version = 1` (a file with `zone` and no `labels` is refused as old: a proposal is state and is made again), `state`, `kind`, `labels` (a list of ids, set by the labeller at the time the proposal was made), `writer` (an integer, the writer digits of the store the proposal was made for; 0 at home), `origin = { system, stream, key, as_of, retrieved, base, series, workbook }` (optional; only `sync` writes it; `base` is the source version that a `new_version` replaces and is absent otherwise; `series` is the stream id and is present only for a vintage stream, with the form of `vocab::stream_id_form`; `workbook` is a boolean that is present, and true, only for a stream saved from a workbook, and `workbook = false` does not parse, so each meaning has one spelling; `overlay-add@1` copies the rest to the origin cells, `as_of` and `retrieved` of the row, writes `series` to the `series` cell and sets `supersedes` from `base`), `candidate = { file, sha256, bytes }`, `extraction = { adapter, method, pages, thin_pages }`, `[row]` (one `{ value, by, because }` for each field), `[links]` (`version_of`, `related`) and `[ai]` (`calls` with `seq`, `adapter`, `template` and `output_sha256`, and `dropped`); `source_id` is not a key, because it is allocated at accept. `parse(id, text)` denies unknown keys and an unknown `proposal_version`; `render` writes keys in one fixed order, so `render(parse(x)) == x` for every fixture. A proposal with any `by = "model:..."` and no `ai.calls` entry does not parse (the provenance lookup itself is FB0917, at accept).
6. `pipeline/view.rs` and `admit.rs`: `CorpusView::from_model(&Model)` is read-only and answers `has_hash(sha256)`, `next_source_id()`, `next_version(source)`, `source(id)` and the question rows. `Edits { fields: BTreeMap<SuggestField, String>, source_choice: Option<SourceChoice> }` separates field edits from a person's source selection; an edited value is written as `by = person` with no `because`. `pub trait Admit { fn id(&self) -> &'static str; fn plan(&self, proposal: &Proposal, edits: &Edits, view: &CorpusView, extraction: Option<&VerifiedExtraction>) -> Result<AdmitOutcome, AdmitError>; }`, `AdmitError` (`KindNotBuilt(kind)`, `MissingField(field)`, `Invalid(Fb)`) and `corpus-add@1`, which fills the cells `add` cannot know from the proposal and the edits, then validates them through `CompletedSourceCells::parse` and calls `plan_add` with Some(&completed), using the producer’s shared render_source_row. Propagate an AddError through AdmitError with its typed cause, including allocator exhaustion; on Ok, match `AddOutcome`: `Present` gives `AdmitOutcome::Present { id }`; `Planned(plan)` gives `AdmitOutcome::Planned { files, affected }`, where affected contains the allocated ItemRefs, and pairs each file of its AddPlan with its source: the original is `Inbox` or `Staging(name)`, and the extraction files, `extraction.toml` and the new `sources.csv` are `Rendered`, with bytes rendered from the proposal, edits and complete `VerifiedExtraction`. A hash already in the register gives `Present`, distinct from a planned empty write set. The order inside the list is fixed: the original, the extraction files, `extraction.toml`, the row last. A kind other than the first two returns `KindNotBuilt`, and so does `reclassify`: its handler is `overlay-add@1` of `r2-org-intake`, because `doc_kind` and `series` are empty in the repository Corpus.
6a. `pipeline/targets.rs`: `TargetKind { Source, Record, Dataset }`, `KeyShape { Sha256, SourceId, VersionId }`, `Target { id, kind, keys, required }` and the const `TARGETS`, which has one row at Day 1: `sources` (kind `Source`, keys `Sha256`, `SourceId` and `VersionId`, and `required`, the names of the columns of `sources.csv` that `check` requires to be filled). The recipe is [Adding an intake target](README.md#adding-an-intake-target); a record type is data and adds no row. `tests/fixtures/pipeline/sources/known-bad/` holds four known-bad proposals, each with a first line that names how it is refused: `unknown_key.toml`, `model_by_without_calls.toml` and `reclassify_changes_nothing.toml` (`# expect: parse`) and `new_source_without_title.toml` (`# expect: admit MissingField`).
7. `admit.rs` holds `pub enum WriteSource { Inbox, Staging(String), Rendered(Vec<u8>) }` (`Staging` holds the file name under `staging/<sha256>/`) and `pub struct PlannedWrite { pub file: WriteFile, pub source: WriteSource }` (`WriteFile` is the type of `audit-journal`). `PlannedWrite::new(file, source)` is the one way to build one outside `admit.rs`, so a later field with a default (`shown`, added by `r2-org-intake`) edits `admit.rs` only. Use core add’s completed-cell input and shared row renderer from its producer; consume `AddPlan { ids, files: Vec<WriteFile>, sources_csv: Vec<u8> }`. Wrap its complete replacement register as `WriteSource::Rendered(plan.sources_csv)`, retaining the exact planned hash and original/extraction/register write order; preserve direct add output.

A missing folder, or a file of it that cannot be read, is `ExtractError::Missing("staging folder")`, and an original hash, a page hash or a page count that differs, or a page file that is absent, is `ExtractError::Missing("matching staging folder")`; the printed line starts with `staged@1`.
