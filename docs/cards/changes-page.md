# changes-page

- **Runs where:** home, CI Linux
- **Schema impact:** none
- **Review:** auto

## Outcome

Every built edition holds `changes.html`: the `## edition-NNN` sections of `corpus/changes.md`, newest first, and, when `fieldbook build --since <edition>` names an earlier edition, the ids added and removed since it, by group. A build without `--since` shows the sections and a plain empty-state line in place of the id diff.

## Why

- The need. The owner reads what changed between editions before relying on a new one. The data exists: `corpus/changes.md` holds the notes (FB0124 checks its shape) and every `edition.toml` holds sorted `[ids]` for pages, source versions, claims, questions, conflicts and terms. Nothing renders them yet ([ADR 0001](../decisions/0001-foundation.md) AD-12 outputs table row `changes.html`, "`edition-002`"; [corpus-format.md](../reference/corpus-format.md) Change records and `edition.toml`).
- `changes.html` is always built, so `planned_paths` is one fixed list and the debug assertion `site.files() == planned` stays simple. A first build, or one without `--since`, is valid: it shows the notes and the empty-state line, never an error. The page ships in `edition-002` because the owner cuts that edition after this card merges; this card does not tag.
- `--since` takes the path of the earlier edition's folder or of its `edition.toml` (AD-17 gives the flag as `build [--out DIR] [--since EDITION]` and does not say how an edition is named). Only the `fieldbook` crate reads the file (`io/`); `fieldbook-render` receives the parsed `EditionInfo` as a value, so render and core do no I/O.
- The diff is a pure function over two `EditionIds` values, so it is tested without a build and the page lists public ids only: the earlier edition's `edition.toml` holds only ids already published, and the current ids come from the permitted view.
- Design: `MAP.md` row Changes (no mockup route); `HANDOFF.md` section 2 (Routes) gives the route and nothing else, so the layout needs a design revision first (see Preconditions). Reuse existing parts only: PageHeader, Panel, RegisterTable, Chip, the `unavailable` part and the empty-state line pattern; no new token, no inline `style=""`, CSP unchanged. `nav.rs` and `app.js` already map `changes.html` to Today, and `xtask/src/allowlist.rs` already admits it, so neither changes.

## Scope

- Files: `crates/fieldbook-render/src/changes.rs`, `crates/fieldbook-render/templates/changes.html`, `crates/fieldbook-render/tests/changes.rs`, `crates/fieldbook/src/since.rs`, `crates/fieldbook/tests/since.rs`, `CHANGELOG.md`, `docs/reference/cli.md`.
- Registration lines: `crates/fieldbook-render/src/lib.rs` (`pub mod changes;`); `crates/fieldbook-render/src/site.rs` (the `changes.html` path in `planned_paths`, one insert, and `render_with_previous`, with `render_with_info` delegating `None`); `crates/fieldbook/src/lib.rs` (`mod since;`); `crates/fieldbook/src/cli.rs` (`BuildArgs.since`); `crates/fieldbook/src/build.rs` (`plan_edition_with_previous`, with `plan_edition_with_originals` delegating `None`, and the `since` read in `run_with_info`); `crates/fieldbook/tests/leak_outputs.rs` (the `changes_page` row of `SURFACES` and `BUILT_SINKS`); `docs/reference/corpus-format.md` (the `build` row of the output table, flag text only).
- Docs to update: `docs/reference/cli.md` (regenerated by `cargo xtask docs`); `CHANGELOG.md` (`- Added: changes.html, the edition's changes and the ids added since an earlier edition (build --since).`).

## Out of scope

- `crates/fieldbook-core/src/edition.rs`, `xtask/src/edition.rs` (`REQUIRED_FILES` stays as it is, so `edition-001` still validates), `xtask/src/allowlist.rs`, `nav.rs`, `app.js`.
- A new check code: a bad `--since` value is a usage or I/O error of `build`, not a finding.
- Writing the `## edition-002` section of `corpus/changes.md` and tagging the edition (the owner's step).
- The browser harness: it opens every built page already; if a run shows it does not, the card is BLOCKED.

## Steps

1. In `changes.rs`, add `OUTPUT_PATH = "changes.html"`, `PAGE_TITLE`, a pure `diff_ids(previous: &EditionIds, current: &EditionIds) -> IdDiff` (per group: added and removed, both sorted, via set difference) and `render_page(view, ctx, nav, planned, previous: Option<&EditionInfo>)` built like `about::render_page` from the frame page, with an askama template `templates/changes.html`. The notes come from `corpus/changes.md` in `view.tree()` (the sections newest first, bullets `Added:`, `Changed:`, `Verified:` as written); with `previous` the page adds one panel per group that has changes and a count line, with none it shows the empty-state line the design revision gives. Every id links by the existing `*_href` helpers where its page is planned and is plain text otherwise.
2. In `site.rs`, add `render_with_previous(view, ctx, info, previous)`, make `render_with_info` call it with `None`, add `changes.html` to `planned_paths` and insert the page.
3. In `since.rs`, add `read_since(arg: &str) -> Result<EditionInfo, SinceError>`: accept a folder (read `edition.toml` in it) or a file, read through `io::tree::read_file`, parse with `EditionInfo::parse`; an unreadable or invalid file is `SinceError` with a plain one-line message. Add `check_order(previous, current)`: refuse a previous edition whose number is not lower than the current one when both are numbered.
4. In `cli.rs`, add `--since <EDITION>` to `BuildArgs`. In `build.rs`, add `plan_edition_with_previous` (the arguments of `plan_edition_with_originals` plus `previous: Option<&EditionInfo>`) and make `plan_edition_with_originals` call it with `None`; in `run_with_info`, read `--since` before any write and map `SinceError` to `EXIT_USAGE` (unparsable or out of order) or `EXIT_IO` (unreadable). `BuildInfo` is not changed, so the struct literals in `tests/build.rs` still compile.
5. In `leak_outputs.rs`, add the `changes_page` surface to `SURFACES` and its sink to `BUILT_SINKS` (they stay parallel, `output_surfaces_cover_built_sinks`): build with the planted canaries and a `--since` file, and assert that no canary and no id outside the permitted view appears in `changes.html`.
6. Tests in `tests/changes.rs`: `diff_lists_added_and_removed_per_group`, `diff_is_empty_for_equal_ids`, `page_lists_notes_newest_first`, `page_without_previous_shows_empty_state`, `page_with_previous_links_planned_ids`, and `planned_paths_equal_the_site_keys` in `tests/frame.rs` must keep passing. Tests in `crates/fieldbook/tests/since.rs`: `since_reads_folder_and_file`, `since_rejects_invalid_edition_toml` (exit 2, tree unchanged), `since_rejects_newer_or_equal_edition`, `build_without_since_builds_changes_page`. Add a snapshot of the page if the render suite snapshots pages; read the diff.
7. Run `cargo xtask docs` so `docs/reference/cli.md` lists `--since`. Run `just site` and record in the pull request the size of `changes.html`.

## Acceptance

```sh
cargo nextest run --locked -p fieldbook-render --test changes --test frame
cargo nextest run --locked -p fieldbook --test since --test leak_outputs --test cli
just site && test -f out/edition/changes.html
cargo run --locked -q -p fieldbook -- build --out out/edition2 --since out/edition/edition.toml && test -f out/edition2/changes.html
cargo xtask docs && git diff --exit-code docs/reference/cli.md
just check
```

Expected: the tests pass; both `test -f` lines pass; the `git diff` line passes after `cli.md` is committed with the card; `just check` exits 0.

## Negative control

In `diff_ids`, drop one group (for example claims): `diff_lists_added_and_removed_per_group` must fail. Restore it. Make `read_since` accept a numbered edition equal to the current one: `since_rejects_newer_or_equal_edition` must fail. Restore it. Add a canary id outside the permitted view to the `--since` input's counterpart in `leak_outputs.rs`: the `changes_page` row must fail. Restore it.

## Rollback

Revert the merge commit. Editions build without `changes.html` and `build` has no `--since` again.
