# core-labels

- **Runs where:** home, CI Linux
- **Schema impact:** none
- **Review:** owner

## Outcome

`fieldbook-core` has the label types and the rules that keep a label from being lost: `LabelId`, `LabelSet`, `LabelTable`, `StoreId`, `StoreRule`, the labeller `labels::for_text`, store admission `labels::admit`, the label ledger and the effective labels of an item (`labels::ledger`), the placement rules `labels::git_guard` and `labels::placement`, and the rule for who may add a label. A store refuses a record whose labels it may not hold (FB0412), an id outside the company's table is a warning (FB0411), and a non-public item under a `.git` ancestor, or a store in a place that fails the place test, is refused (FB0415). The field of a `LabelSet` is private, so nothing outside the module builds one by hand. Text reaches `public` only by a named act (`PublicAct`). Nothing defaults to it.

## Why

- Labels, the four built-in ids and the set rules are in [ADR 0004, section 2](../decisions/0004-company-boundary.md#2-labels). Stores and admission are in [section 4](../decisions/0004-company-boundary.md#4-stores-and-admission), and what stays refused is in [section 13](../decisions/0004-company-boundary.md#13-what-stays-refused). The `handling` cell is in [Handling and labels](../reference/corpus-format.md#handling-and-labels).
- This code decides whether a record may be kept, and later whether it may leave. A wrong rule is a leak. The card is `owner` reviewed because the label, policy and egress modules of `fieldbook-core` are on the release gate (AD-21).
- The failure each rule prevents is named in the ADR: a pricing workbook labelled `public` by hand so that a model will read it (`public` comes from an act, never a default or a say-so); a candidate for the repository Corpus with no banner that was admitted as `public` because nothing said otherwise (the labeller gives it `unlabelled`); a marking that was stripped on the way in (the labeller never edits text); company figures committed by a developer who points the state folder at a checkout (the git guard); a store placed in a synced folder (the place test); a record rewritten to change its label, which breaks its hash (the ledger).
- The policy file, the egress decision and the view are the next card, `core-policy`. This card has no policy type: `MarkingRules` and `LabelTable` take plain values, which `core-policy` fills from the file.

## Scope

- Files: `crates/fieldbook-core/src/labels/{mod.rs,id.rs,set.rs,table.rs,store.rs,marking.rs,placement.rs,ledger.rs,change.rs}`, `crates/fieldbook-core/tests/{labels.rs,labels_no_panic.rs}`; `crates/fieldbook-core/src/labels/dependencies.rs`, `crates/fieldbook-core/tests/label_dependencies.rs`.
- Registration lines: the `pub mod labels;` line in `crates/fieldbook-core/src/lib.rs`; `tests/known-bad/elsewhere.toml` (the `test` key of the rows FB0411, FB0412 and FB0415 only).
- Docs to update: none. [Handling and labels](../reference/corpus-format.md#handling-and-labels) and ADR 0004 are the source; this card mirrors them and does not edit them.

## Out of scope

- The policy file, `egress::check`, `Allowed`, `LabelledView` and the leak matrix (`core-policy`).
- The verbs `label add`, `label reapply` and `label show`, and the intake of a company file (`r2-org-intake`). This card writes the rules `labels::change::may_add` and `labels::ledger`; the verb calls them.
- `World::place`, the method that reads the facts about a folder from the operating system (`backup-snapshot` adds the method, a `Disk` that answers every fact false and the double that returns what a test sets; `windows-facts` gives the Windows `Disk` its real read). This card takes those facts as a plain value and does no file access.
- The call sites of the store rules: the company layout (`r2-state-and-journal`), the intake (`r2-org-intake`) and the sync (`r2-pull-and-sync`). Each of those cards names the test that shows it calls `admit` and `git_guard`.
- A new built-in label. That is an amendment to ADR 0004.
- `label remove`. The ledger has room for it ([Deferred](../decisions/0004-company-boundary.md#deferred-with-triggers)).
- Model-assisted labelling. It is not offered ([ADR 0004, section 7](../decisions/0004-company-boundary.md#7-model-endpoints-and-the-ai-before-any-approval)).

## Steps

1. `labels/id.rs`: `LabelId`, a validated string. `LabelId::parse(&str)` calls `vocab::label_form` (from `core-schema-pages`), which holds the one shape rule: one of the four built-in ids, or a company id `[a-z]{2,4}-[0-9]{4}`. A company id is an opaque code, so that the id in the journal tells a reader nothing about a counterparty; no second copy of the rule is written here. Add the four built-ins as consts, `PUBLIC`, `UNLABELLED`, `MARKED` and `OWNER_SUPPLIED`, and `BUILTINS` with them in that order. Tests: `accepts_the_builtins_and_the_opaque_shape`, `rejects_a_name_upper_case_a_long_prefix_a_short_number_and_empty`, `builtins_are_the_four_ids`.
2. `labels/set.rs`: `LabelSet`, a sorted vector of unique `LabelId` with a private field. Constructors: `LabelSet::public()`, `LabelSet::unlabelled()` and `LabelSet::from_ids(iter)`, which applies the rules of the ADR: an empty input becomes `unlabelled`; `public` is dropped when any other id is present; `unlabelled` is retained beside every other label; the result is sorted. Methods: `with(&self, id)`, `union(&self, other)` (the rule for anything derived), `is_subset_of(&self, other)` (the rule for sending), `contains`, `is_public()`, `is_unresolved()` (holds `unlabelled` or `marked`), `ids()`, `to_cell()` (ids joined by `|`, the form of the CSV `handling` column) and `parse_cell(&str)`, which is strict: an empty cell is an error, because an empty `handling` is a defect in a file, whereas an empty input to `from_ids` is a computation with nothing found. `marked` is never dropped by `with`, `union` or `from_ids`. The one function that may drop it is `LabelSet::reapplied(&self, found: &LabelSet)`, which replaces `marked` by `found` and refuses (`None`) when `found` itself holds `marked`; `label reapply` is its only caller. `owner-supplied` is request-only: a `LabelSet` may hold it (a prompt's text does), and `admit` (step 4) lets only the `state` store keep it. Tests: `empty_becomes_unlabelled`, `public_is_dropped_beside_another_label`, `unlabelled_survives_derived_union`, `marked_survives_with_union_and_from_ids`, `reapplied_is_the_only_way_to_drop_marked`, `union_is_the_derived_rule`, `subset_is_the_sending_rule`, `a_set_is_sorted_and_unique`, `cell_round_trip`, `an_empty_cell_is_an_error`. `LabelAllow` is a separate sorted unique vector of LabelId, with `empty`, `from_ids`, `ids`, `contains`, `intersection` and `permits(&LabelSet)`. It keeps public beside other labels and permits an empty set. StoreRule.holds and every destination/owner allow-list use LabelAllow; defaults and actual item labels use LabelSet. Data union is associative, commutative and idempotent; unlabelled and marked survive it. `classified` refuses builtin ids in its argument and is called only by ledger application. Add `permission_sets_keep_empty_and_mixed_public`, `data_union_preserves_unresolved_inputs` and `label_union_laws`.
3. `labels/table.rs`: `LabelTable`, the ids that are defined and which of them are restricted: `LabelTable::builtin()` and `LabelTable::with(ids, restricted)`. `check_known(&LabelSet, &LabelTable) -> Vec<LabelFinding>` returns one finding (FB0411, a warning) for each id outside the table, naming the id and never a title; the caller treats a set with such an id as unresolved. `is_restricted(&LabelId)` is read by `core-policy` (the `readers` rule) and by `label add`. Tests: `unknown_id_is_fb0411`, `builtins_are_always_known`, `a_known_set_has_no_finding`, `restricted_ids_are_reported`.
4. `labels/store.rs`: `StoreId` (`Corpus`, `Overlay`, `Working`, `State`; `as_str()` gives the root name and `from_root_name` reads it), `StoreRule { store, holds: LabelAllow, default: LabelSet, readers, changers, hold }` with `StoreRule::corpus()` (holds `public` only) and `StoreRule::floor(StoreId, holds_marked: bool)` (the floor row of ADR 0004, section 3: `overlay` and `working` hold `public` and `unlabelled`; `state` also holds `owner-supplied`, because only its logs carry that label; all three also hold `marked` when `holds_marked` is true, which is floor B and nothing else; all three default to `unlabelled`), and `admit(&LabelSet, &StoreRule) -> Result<(), Refusal>`. `readers` and `changers` are optional group names and `hold` a switch; `core-policy` fills them and `admit` reads none of them. A `Refusal` holds a `Code`, a closed `Reason` word of the journal `refuse` event (`store`, `git`, `place`) and the `LabelSet`, never the text. In the store `corpus`, a set holding `marked` is refused with FB0400, and any other set that is not `public` is refused with FB0410: the repository Corpus keeps its old codes. In every other store, a set with an id outside `holds` is refused with FB0412. `state` is a transit store: an item in `state\inbox`, `staging` or the queue is admitted with the rule of the store it is bound for, and the `holds` of `state` itself governs its logs and the derived site, so the policy lists a label once for intake. Tests: `corpus_refuses_marked_with_fb0400`, `corpus_refuses_another_label_with_fb0410`, `corpus_admits_public`, `overlay_floor_admits_unlabelled_and_refuses_owner_supplied`, `state_floor_admits_owner_supplied_for_its_logs`, `overlay_floor_refuses_a_company_label_with_fb0412`, `floor_b_rows_admit_marked_and_floor_a_rows_refuse_it` (all three stores; FB0412 for the refusal), `a_set_is_admitted_only_if_every_label_is_held`, `a_staged_item_is_admitted_by_the_store_it_is_bound_for`, `the_refusal_holds_ids_and_no_text`.
5. `labels/marking.rs`: `MarkingRules`, with `MarkingRules::builtin()` (the banner shapes of `scan::marking`, each mapped to `marked`) and `MarkingRules::with_rows(rows)` (a `[[marking]]` row is literal text of 3 to 80 characters, compared in any case with runs of whitespace collapsed, and its labels; `core-policy` builds the rows). `LabelContext` holds the default of the place the text came from: `LabelContext::none()` (default empty), `LabelContext::store(&StoreRule)` (the store's `default`) and `LabelContext::act(PublicAct)`. There is no context for the repository Corpus that defaults to `public`. `PublicAct` is the closed list of ways text becomes `public`: `PublicAct::edition()` (the edition build), `PublicAct::source_row(folder, root)` (a stream whose folder lies inside the `root` of a policy `[[source]]` row; it returns `None` for a folder outside the root, by a test on whole path components of canonical paths) and `PublicAct::typed(has_company_store: bool, confirmed: bool)` (a person's typed confirmation, which for `add` and home `new` commands is `--confirm-public`; valid only when the machine has no company store and the confirmation was given; otherwise a `Refusal` with FB0822. A caller with no confirmation uses `LabelContext::none()` and never calls `typed` with `confirmed` false). `markings_in(text, &MarkingRules) -> Option<LabelSet>` is pure: it unions the labels of every row that matches, and `marked` for a built-in shape that no row covers, and returns `None` when the text holds no marking; `egress::check` uses it on outbound text. `for_text(text, &MarkingRules, &LabelContext) -> LabelSet` adds the context default to that result; nothing found gives `unlabelled`. If the normalized result is public-only and the context carries no valid PublicAct, return unlabelled, even when a store default or global marking row supplied public. This does not change derived unions of already public inputs. It reads text and returns a set; it has no way to change the text, so it cannot strip or edit a marking. Tests: `plain_text_with_no_act_is_unlabelled`, `plain_text_with_an_edition_act_is_public`, `a_banner_without_a_rule_is_marked`, `a_rule_maps_a_marking_to_its_labels`, `a_rule_row_is_matched_in_any_case_and_across_whitespace`, `no_default_and_no_marking_is_unlabelled`, `a_marking_beside_the_default_keeps_both`, `markings_in_is_none_for_plain_text`, `same_text_same_labels`, `a_source_folder_outside_its_root_gives_no_act`, `a_typed_public_is_refused_when_a_company_store_exists`, `a_typed_public_needs_the_confirmation`, `a_confirmed_typed_public_gives_public_with_no_company_store`. Use synthetic banner text built in the test from the scan's own list.
6. `labels/placement.rs`: `GitContext { under_git: bool, ignored_home_state: bool }` and `git_guard(labels: &LabelSet, context: GitContext) -> Result<(), Refusal>` are pure. Outside Git the guard passes. Under Git it permits public; owner-supplied is permitted only when ignored_home_state is true; any other label refuses FB0415, reason `git`. I/O establishes the home preset, verified ignore coverage and canonical containment in resolved State (including its drill); no caller infers the exception from a label or folder name. add-new-and-edition supplies the shared I/O helper before its consumers. `PlaceFacts { reparse, sync_root, network }` is the plain value that `World::place(path)` returns (the operating system's answer for the folder: a reparse point or junction, a sync client's cloud-file attributes or sync-root registration, a network drive or UNC path). `placement(Placement { laptop, under_git, role, facts, declared }) -> Result<PlaceKind, Refusal>` takes a `PlaceRole` (`LiveStore`, `State`, `Drop`, `ExportTarget`, `BackupTarget`). On the laptop, a live store or the state folder under a `.git` ancestor, or with `reparse`, `sync_root` or `network` set, is refused (FB0415, reason `place`); a drop folder under a `.git` ancestor, or a sync root, is refused, and local or network is valid; an export or backup target under a `.git` ancestor is refused, and a sync root or reparse point is valid only when `declared` (the target row says `kind = "synced"`). A refusal never depends on a folder's name. The result `PlaceKind` (`Local`, `Network`, `SyncRoot`, `Reparse`) is what the caller journals with the write. `fieldbook_is_ignored(ignore_text: &str) -> bool` is the pure check for the home layout: `.fieldbook/` must be named in an ignore file of the checkout. The shared I/O GitContext helper in `add-new-and-edition` calls it first; `r2-state-and-journal` step 2 reuses that helper. `backup-snapshot` calls `placement` for its synced-target warning (FB0813), with the facts from `World::place`, and keeps no list of folder names. Tests: `a_company_label_under_git_is_refused`, `public_may_sit_under_git`, `owner_supplied_requires_ignored_home_state` (State and drill pass; unignored State, export and backup targets under Git refuse), `nothing_is_refused_outside_git`, `a_laptop_store_under_git_is_refused`, `a_laptop_store_in_a_sync_root_is_refused`, `a_laptop_store_behind_a_junction_is_refused`, `a_laptop_store_on_a_network_drive_is_refused`, `a_drop_folder_may_be_on_the_network_but_not_a_sync_root`, `a_sync_root_backup_target_is_valid_only_when_declared`, `a_folder_named_onedrive_that_is_local_is_not_refused`, `the_home_layout_may_sit_under_git`, `home_state_must_be_ignored`.
7. `labels/ledger.rs`: the label ledger of [the company store](../reference/company-store.md#the-label-ledger). `Ledger::parse(text) -> Result<Ledger, LedgerError>` is strict: the header is `seq,item_id,kind,labels,origin`; `seq` starts at 1 and goes up by one; `kind` is `add`; `labels` is a cell that `LabelSet::parse_cell` reads and holds none of `public`, `unlabelled`, `marked` or `owner-supplied`; `origin` is `person`, `reapply` or `intake`. `effective(cell: &LabelSet, id: &str, &Ledger) -> LabelSet` is the one function that gives the labels of an item: its cell plus the `labels` of every `add` line for its id, line by line in `seq` order, through `LabelSet::classified(&LabelSet)` for a `person` or `intake` line (an explicit classification removes unlabelled from this item only, then adds the real labels) and through `LabelSet::reapplied` for a `reapply` line, which is the only line that replaces `marked`. `Ledger::plan_add(ids, &LabelSet, origin) -> LedgerPlan` returns the new text of the file (the header when the file is new, then one line for each id) and writes nothing; the verb applies it in a write set. A ledger that cannot be read is reported once with its line number as FB0412, and every item of that store is treated as unresolved until it is fixed, so nothing is sent. Tests: `ledger_round_trip`, `a_gap_in_seq_is_an_error`, `a_line_that_adds_public_is_an_error`, `an_unknown_kind_is_an_error`, `effective_is_the_cell_plus_the_add_lines`, `an_add_line_resolves_unlabelled`, `marked_survives_an_add_line`, `a_reapply_line_replaces_marked`, `plan_add_continues_seq`, `plan_add_on_a_new_ledger_writes_the_header`, `a_broken_ledger_makes_every_item_unresolved`. `parser_never_panics_on_200_seeded_inputs`, in `crates/fieldbook-core/tests/labels_no_panic.rs`: It includes the generator with `#[path = "../../../tests/support/rng.rs"] mod rng;`, builds 200 byte strings of length 0 to 128 from `Rng::new(1)`, and takes a valid ledger of three lines with each of its bytes once flipped and once deleted. Each goes through `String::from_utf8_lossy` into `Ledger::parse`. The result is a `Ledger` or a `LedgerError` and nothing panics.
8. `labels/change.rs`: `may_add(&AddContext, &LabelId) -> Result<(), Refusal>`. `AddContext` holds the preset, the declared role, whether input and output are both an interactive console, the typed confirmation (whether it named the number of items), the store's `hold`, and `in_changers` (`Some(bool)` when the store row names `changers`, from the logon token; `None` when it does not). It refuses `public`, `unlabelled`, `marked` and `owner-supplied` (a person assigns a real label or none), a caller that is not at a console on both input and output, a confirmation that did not name the count, a store with `hold`, and a token outside `changers` (FB0822). On the laptop preset the declared role is not read at all; at home it must be `owner` or `lead`, and `agent` is refused. There is no `may_remove`. Tests: `a_person_at_a_console_may_add_a_real_label`, `a_pipe_on_input_is_refused`, `redirected_output_is_refused`, `the_confirmation_must_name_the_count`, `the_role_word_is_ignored_on_the_laptop_preset`, `at_home_the_agent_role_is_refused`, `a_token_outside_changers_is_refused`, `a_store_on_hold_is_refused`, `no_person_may_add_public`, `no_person_may_add_unlabelled_marked_or_owner_supplied`.
9. `tests/labels.rs` holds the cases above that need two modules at once: `a_derived_set_checked_against_a_store` (the union of two inputs is admitted only if the store holds both), `an_added_label_is_admitted_by_the_store` (`effective` over a ledger line, then `admit`), and `the_repository_corpus_path_end_to_end`: `for_text` with no act and `admit` with `StoreRule::corpus()` for a plain text (`unlabelled`, refused with FB0410, so `corpus-add` has nothing to write), the same text with `PublicAct::edition()` (admitted), the same text with `PublicAct::typed(false, true)` (admitted: the `add --confirm-public` case), and a text with a synthetic banner (FB0400, with or without the act). FB0411, FB0412 and FB0415 are raised by a company store and by the layout, so `check` over `corpus-mini` cannot raise them. Their rows are already in `tests/known-bad/elsewhere.toml` with the card `core-labels` (`check-known-bad` wrote them); set the `test` key of each to its known-bad test: `unknown_id_is_fb0411`, `overlay_floor_refuses_a_company_label_with_fb0412` and `a_company_label_under_git_is_refused`. This card adds no row. `every_code_is_accounted_for` must pass.

## BLOCKED

- `scan::marking` offers no function that takes text and returns the banner shapes it found: write the signature you need and stop. Do not copy the banner list into this module; one list is the rule.
- A rule in this card contradicts ADR 0004 or Handling and labels in the Corpus format: write the two sentences, name the sections, and stop. Do not edit either document.
- A test seems to need the policy parser: use `LabelTable::with` and `MarkingRules::with_rows` in the test. If that is not enough, the work belongs to `core-policy`.
- A test seems to need the real operating system for the place test: pass a `PlaceFacts` value. The real call is `World::place`, which `backup-snapshot` adds and `windows-facts` fills in on Windows.
