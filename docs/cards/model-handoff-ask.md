# model-handoff-ask

- **Runs where:** home, CI Linux
- **Schema impact:** none
- **Review:** auto

## Outcome

`fieldbook ask "<question>"` builds a context pack from the labelled view for the chosen route (the records the policy lets through to that destination; the rest are left out and counted), puts it in the `ask@1` prompt and sends it through the one gate. On the default route, Handoff, nothing is sent: the program writes the pack to `handoff/H-nnnn.txt` in the state folder, appends `ai.pack`, and prints the path and the command that finishes the round trip. The owner pastes the pack into an assistant the organisation approved, saves the reply in a file, and runs `fieldbook ask --resume H-nnnn --from FILE` (or `-` for standard input). The program appends `ai.paste`, runs `cite_check` on the reply, prints the answer with its citation report, and exits 1 when `report.unresolved > 0 || report.nothing_verifies()`, otherwise 0. `--note` files the answer in the review queue as a `note` proposal. `ai test` writes a fixed synthetic pack to show that the route works.

## Why

- This is the first verb that reaches a model door, and the route it uses first is the one that sends nothing over a connection: Handoff is the default route and the fallback in [AD-01](../decisions/0001-foundation.md#ad-01-architecture) (the one gate and the Surfaces table) and the Handoff design of [AD-18](../decisions/0001-foundation.md#ad-18-security-and-confidentiality-guardrails). An answer that comes back by paste goes through the same checks as one that comes from an endpoint, so both routes are audited and checked the same way. The codes it makes reachable from the command line are FB0901, FB0902, FB0903, FB0904, FB0915, FB0916 and FB0919 in [09: model, decide, index, output, MCP and chat](../reference/corpus-format.md#09-model-decide-index-output-mcp-and-chat).
- An answer is not trusted because it came from an approved assistant. `cite_check` labels each citation (the nine statuses in [Citation checks](../reference/citation-check.md#status-and-exit); `--resume` gives the check the ids of the ticket's pack) and says "resolves" only when the applicable reference, locator and quotation checks pass; whether the answer is right stays a human question. This is the first half of HG-11 in [controls.md](../controls.md); the citation labels are those of HG-05. The second half of HG-11 (the decision checks) is `decide-port`.
- Handoff needs no key, no network and no feature flag, so this card ships in the silent build. The program never touches the clipboard (a hard stop in `AGENTS.md`); the owner moves the file. The pack's first line lists the labels it holds and the lines after it carry the banner of each, and its last line counts the records the policy left out, so a pack that holds company records cannot be mistaken for a public one and an answer from a thinner pack is known to be thin. Handoff stays the route for any label the `handoff` row of the policy lists: the owner reads the pack and decides where to paste it.
- The ten `ask` fixtures are the lead's item of the phase (PLAN.md: "Write 10 `ask` fixtures from the 20 cite-check seeds"), so the resume tests run on answers somebody wrote on purpose, one of them with a broken citation.
- No page, template or string shown in a browser is built here, so there is no Design bullet. The chip `fieldbook ask "<question>"` is already in the [Verb map](../reference/corpus-format.md#strings); the Assistant page that shows it is `assistant-page`.

## Steps

1. Consume the ask@1 template, fixture, golden and shared template tests built by ai-kernel; preserve its Rules, optional History, Context and Question contract.
2. `adapters/handoff.rs`: `Handoff` implements `ModelAdapter` with `id() = "handoff@1"`, `caps() = Caps { network: false, structured: false, embeddings: false, streaming: false, max_prompt_chars: 120_000 }` [J], and `attempt` returning `Attempt::Pack(PackText)`. The text is the label header, a blank line, `req.system()`, a blank line and `req.prompt()`. The label header is the line `Labels: <ids>` (the request's label ids, sorted and joined by a comma and a space, the frozen string `pack_labels`) followed, for each of those labels that has a banner in the policy, by the banner on a line of its own, in id order. Construct `Handoff::new(assistant_label)` without policy banners. Its prepare method consumes banner values from PreparationContext, derived from the same operation snapshot used for final authorization. It reads no policy or clock and serializes the pack exactly once. The text uses LF only and ends with one newline. The adapter reads no file, key or clock, and a pack for the same request and the same policy is the same bytes. The route for `handoff` takes `allow` and `assistant_label` from `[model.handoff]`, and a reply cap of 65,536 bytes [J]. Add the registry row (port Model, default, `Built`, `Silent`, crate `fieldbook`, needs `None`, sees `labelled`, `calls_model` false, keys `model.handoff.allow` and `model.handoff.assistant_label`, fixtures `tests/fixtures/ports/model/handoff@1/`, suite M) and the factory row. Run `cargo xtask docs`.
3. `tests/contract_handoff.rs`: `contract_model_handoff_1` calls `suite_m` of `model-gate` with a factory for `Handoff`, and adds the cases of this adapter: the label header for a request that carries `owner-supplied` and for one that carries a label with a banner (the banner follows the `Labels:` line); the same request gives the same pack; `attempt` never returns `Attempt::Reply`; the pack holds the question as its last part; a request with a marking is still refused by the gate before the adapter (the adapter is a `PanicModel` wrapper in that case). `tests/fixtures/ports/model/handoff@1/` holds the scripted requests (one `public`, one `owner-supplied` and one with the synthetic label `np-0007` and its banner) and the expected pack text for each.
4. `io/reply.rs`: `read_reply(path_or_dash) -> Result<String, ReplyError>` reads a file, or standard input for `-`, as UTF-8, and refuses a path that is a folder. It never reads the clipboard and has no other source. Add `pub mod reply;` to `io/mod.rs`. A non-UTF-8 file is a usage error (exit 2), not FB0916.
5. `cli.rs`: `ask [QUESTION] [--scope area:<code>|page:<id>] [--via NAME] [--note] [--resume H-nnnn --from FILE|-] [--assistant LABEL]`. A question and `--resume` are exclusive; `--resume` needs `--from`; `--via` and `--scope` are refused with `--resume` (the ticket fixed them); `--assistant` is accepted only with `--resume`, and its value is a label of `[a-z0-9-]{1,32}`. `--note` needs an area, taken from `--scope area:<code>` or the page's area. Anything else is a usage error and exit 2. Add `ask` and `ai test` to `AI_VERB_FILES`, remove `ask` from `PENDING` in `tests/chips.rs` (`ai test` is in `NO_CHIP`), and register its case in `tests/support/chip_cases.rs` (fresh Home `corpus-mini`, default Handoff settings and no endpoint configuration, exit 0 with a deferred pack). `parse_ticket_id` delegates to `HandoffId::parse` and maps its error to a usage error. `parse_assistant(&str)` retains the label rule above and returns a value or typed usage error.
6. `ask.rs`, a new question. Read the settings (FB0900, exit 2). When the policy is Closed, `plan` gets FB0413 from `egress::check` for every candidate, and `ask` stops with that code and not with FB0901: no pack is built and nothing is written or sent. Call `assist::context_pack(&view, question, scope, budget, &Include::default())` with the budget `[assistant] pack_budget_chars` from `corpus.toml`; the view is the `LabelledView` for the chosen route. First `ModelPort::plan(via, base)` returns the destination of the first candidate whose effective allow set covers `base`, the labels of the Rules part (`public`) and the Question part (`owner-supplied`); then `egress::check(&effective, &dest, None, None, now, shipped)` gives the selection-only token for `LabelledView::new`, using the current policy snapshot and export age. Its `permitted: LabelAllow` is the complete narrowed permission set; never pass that set as data labels. A record whose labels are not all in that set is left out whole, so the route and the pack agree by construction (the count is shown to the owner on a Handoff pack and never to a model), and a request with no covering candidate stops here with FB0901 before a pack is built. Build `ModelRequest::new(Purpose::Ask, Template("ask@1"), parts, None, limits)` with the parts Rules (the text of `ASSISTANT.md`), empty History for this single-question CLI, Context (the pack's blocks with their ids and its last line, the one that `LabelledView::left_out_line` gives for the destination: the fixed line `Some records were omitted.` with no number for a model, and `Left out (policy): N records` for Handoff; the leading `ASSISTANT.md` and the `Labels:` line of the pack text are left out, because the Rules part has the first and the adapter prints the second from the labels of the whole request) and Question (a part the owner typed, so it carries `owner-supplied`), in that order. Construct `Budget::for_question` for the actual Rules, empty History, Context, Question and separators. If `request_budget.sendable` is false, print its reason and exit 2 before preview or run; required question logging still occurs, with no pack or adapter call. Ask the model port for `preview` and print one line to standard error before anything is written or sent: `ask: route <name>, labels <ids>, <N> characters, left out <M> records`. Call `ModelPort::run(&req, via, &|| false)`. The model port is passed in as `&dyn ModelPort`, so the tests can pass a router built on `ScriptedModel`.
7. Before advertising any resume command, complete that shared ask-sidecar finalizer; a failed finalizer does not advertise a usable resume. Preserve the original endpoint-error exit code for fallback. A `Deferred(ticket)` result prints `pack written: <path> (<N> characters, Labels: <ids>)` and then `paste it into an assistant your organisation approved, save the reply in a file, then run: fieldbook ask --resume H-nnnn --from FILE`, and exits 0. An `Answer` (a route other than Handoff, in tests the scripted one) goes to step 8. A `ModelError` prints its code, the help line from the catalogue and, when the router offered a fallback, the pack path and the resume command; the exit code is the error's own (2 for FB0413, FB0901, FB0902, FB0915, FB0918 and FB0925, 3 for FB0903, FB0904 and FB0919). A refusal never prints a pack.
8. `ask --resume H-nnnn --from FILE`: read the reply (step 4), call `ModelPort::resume(ticket, text)` (FB0916 for a missing or used ticket or an empty reply; FB0919 over the cap), and treat the returned answer as in step 7. The provenance says `adapter = handoff` and `model = unrecorded`, or the `--assistant` label, or `assistant_label` of the settings. For an answer, in both cases: rebuild the view for the pack's destination as step 6 does, from the policy now in force (a Closed policy stops here with FB0413, because it denies Handoff too), run `assist::cite_check(&view, answer, Some(&ids))`, where `ids` are the `context_ids` that the ticket `H-nnnn.toml` holds for `--resume` and the ids of its own request for an answer from a route, print the answer, then the report with the printer `cite-check` uses ("N of M citations do not resolve", and "Do not use this answer." when nothing verifies), then one line naming the provenance (`via handoff, assistant <label>`). For both endpoint and resumed answers, exit 1 when `report.unresolved > 0 || report.nothing_verifies()`, otherwise 0. For resume, the question, scope and area are read from the sidecar `H-nnnn.ask.toml` that step 9 writes, not from the gate ticket; an endpoint answer uses the retained current ask inputs, and a broken citation sets the row `cite_failed` as step 9 says. The answer is printed as text and never executed, opened or run as a command.
9. Before the route is tried, run `labels::markings_in(question, &policy.marking_rules())`, where `policy` is the run's `EffectivePolicy` (its `marking_rules()` gives the `[[marking]]` rows of a loaded policy, and `MarkingRules::builtin()` under the floor and a Closed policy). `labels` is `owner-supplied` plus every label the scan found, and `owner-supplied` alone when it found none. A question for which any label of `labels` is outside the `holds` of the `state` store (ADR 0004: `state` holds `public`, `unlabelled` and `owner-supplied`, and `marked` only on floor B or when its `[[store]]` row lists it) is not logged, because its row would put text under a label that the store cannot hold; the gate refuses it with FB0902 as before. Every other question, refused or not, is logged: call `asked::log_question(world, journal, settings, policy, Via::Ask, &labels, hit_inputs, query, hits, Cited::NotChecked)` once per new question, before the route is tried, and keep `Logged.id`. No pack exists yet, so the row carries no pack label. hit_inputs contains exactly the store-qualified references of the pre-route hits recorded in top_ids, empty when there are none; keep the first-run count and outcome. The sidecar/ticket retains the later request inputs. A resume never calls it, and nothing calls it twice for one question. A broken citation sets the row `cite_failed` with `io::asked::set_outcome(id, Outcome::CiteFailed, None)`: for an `Answer`, in the same run with the kept id; for either a `Deferred` ticket or an availability-fallback ticket carried by `ModelError`, one finalizer writes the id as `asked` in the sidecar `handoff/H-nnnn.ask.toml` (`ask_version = 1`, `asked` left out when `Logged.id` is `None`, `question`, `scope`, `area`, `request_labels` and `provenance`; the last two copy `req.labels()` and `req.input_refs()` as sorted ids and `{ store, id }` tables) through `io/reply.rs`, and `ask --resume` reads the sidecar, takes the id from it and makes the same call. The resume paths of steps 8 and 10 read question, scope and area from the sidecar, not the gate ticket. An endpoint answer keeps those current ask inputs in memory and creates no sidecar. A log or outcome failure prints its warning and changes neither the output nor the exit code.
10. `ask_note.rs`, `--note`: after an answer whose report has no broken citation, write `queue/P-nnnn.toml` (the next free number in `queue/` and `queue/done/`) in the format of the review-queue row: `proposal_version = 1`, `state = "proposed"`, `kind = "note"`, `labels = [...]` (the answer's saved request labels, sorted), a `[note]` table with `area` (the retained current ask area for an endpoint answer, the sidecar area for resume), `title` (the question cut at 80 characters), `question` (the retained current question for an endpoint answer, the sidecar question for resume), `context` (the current request's context_ids for an endpoint answer, the ticket's ids for resume), `body` (the answer text), `origin = "ai_drafted"`, `request_labels` (the answer's saved request labels) and `provenance` (its sorted input `{ store, id }` references), and `[ai]` with `calls = [{ seq, adapter, template = "ask@1", output_sha256 }]`, where `seq` is the sequence number of the `ai.paste` (or `ai.call`) event and the hash is that event's `output_sha256`. `title` is for display only; the page title is derived when the note is accepted. Append `queue.propose` using the shared queue payload (`proposal_kind = note`, proposal, optional sha256, labels and the recorded adapter-role map) and print the path. An answer with a broken citation is not filed: the program prints `note not written: N of M citations do not resolve` and exits 1. A person accepts the note interactively; `queue accept` is not here. Use `ModelAnswer::request_labels()` and `input_refs()` for both endpoint and resumed answers; never infer them from the reply text. The queue file retains the request labels and input ItemRefs, and acceptance preserves their effective labels. Corpus admission requires the explicit permitted public act and wholly public provenance; a company-derived note stays waiting until an authorized company target accepts it. An unmarked body never clears a company label.
11. `ai_test.rs`, `ai test [NAME]`: build a fixed request of purpose `Ask`, template `ask@1`, labels `public` (the question is fixed program text, not the owner's), with an empty context and the question "Reply with the word OK." With no name it tests each entry of `order` in turn (Handoff alone when `order` is not set), and the first failure decides the exit code. A name that is not `handoff` and not in the settings is a usage error. The request holds no Corpus text. This path is written once for every adapter, so an endpoint adapter adds no code to this file.
