# audit-journal

- **Runs where:** home, CI Linux, CI Windows
- **Schema impact:** none
- **Review:** auto

## Outcome

The program keeps one append-only, hash-chained journal in its state folder, and `fieldbook audit verify` says whether the chain is whole. The journal holds typed fields only: no event holds a question, a prompt, a file's text or the name of a file outside the Corpus. An event names what it touched by typed references only (a record id, a hash, a store, a set of labels), and every event says who acted (`actor`), in which store and by which door (`via`), so the journal can answer who read, sent or changed which labelled record. A write that the journal cannot record is not made, and the program exits 3.

## Why

- What the journal records, its fail-closed rule and the outside copy of its head are the audit bullet of [AD-16](../decisions/0001-foundation.md#ad-16-release-2-shell-and-its-gate) and control AL-01 in [controls.md](../controls.md). The codes FB0800 to FB0805 and their known-bad examples are in [08: audit, backup and pipeline](../reference/corpus-format.md#08-audit-backup-and-pipeline); the state folder is not part of the Corpus ([AD-01](../decisions/0001-foundation.md#ad-01-architecture)).
- `add-new-and-edition` and every later write verb need the `Audited` token that this card makes, so no write path exists without a journal entry. Only `fieldbook/src/io` touches the disk ([AD-05](../decisions/0001-foundation.md#ad-05-crate-layout-and-enforcement)).
- The home gate runs Drill 4 on this journal ([restore-drill.md](../runbooks/restore-drill.md)), and every backup records its length and head as the copy kept outside the file.
- The envelope (`actor`, `role`, `store`, `via`) and the label fields are decided in [ADR 0004](../decisions/0004-company-boundary.md#12-audit). They are built in this card, the first journal card, because the parser denies unknown keys and the hash covers each line: a key added after a journal exists is a new journal version.
- No page, template or string shown in a browser is built here, so there is no Design bullet. The Activity log page (`status-command`) and the Review queue page read `audit show --json` and `audit verify --json`.

## Out of scope

- Emitting any kind except `journal.open`, `journal.recover`, `write.begin`, `write.end`, `refuse` and `settings.change`. Every kind of the vocabulary is defined and has a sample line here; the card that owns a verb emits its own events (`add-new-and-edition`, `backup-snapshot`, `ask-log`, `model-gate` and the rest). `policy-load` emits `policy.change`, `r2-org-intake` emits `label.change`, `audit-export` emits `audit.export`, and `r2-pull-and-sync` emits `sync.begin` and `sync.end`.
- Strict validation of `settings.toml` (`ai-config-and-keys`). This card reads one key, `role`, and ignores the rest.
- A signed journal (`later-signed-journal`) and any read of a page opened in Edge: the program cannot see either, and the IT documents say so.
- A journal shared by several writers, an identity source other than the operating system and a service (`later-shared-store`, `later-accounts`). This card fixes the keys that make them possible later (`actor`, `store`, `via`) and the chain that belongs to one writer; it builds none of them.
- A repair that merges journals or restores lost events. `audit verify --repair` only sets a broken journal aside and starts a new chain; the old events stay readable in `journal.broken-<seq>` and nothing is deleted.

## Steps

Implementation order: declare the StoreLease, pending-descriptor, OperationKey/OperationIntent and StoreUid types and complete their lease/pending invariants from steps 11, 12, 15 and 26 before implementing `Journal::begin` or either transaction door. Those later paragraphs remain the detailed contract. A measured split follows the atomic provider rule and keeps required authorization, invariants and negative controls with the first enabled handler.

1. `audit/vocab.rs`: the newtypes `Id` (an id of any family), `RecordRef` (a store and an id, written `overlay/SO-000042`, for a list that can span stores), `CorpusPath`, `Sha256`, `Count`, `Role` (owner, lead, agent), `Word` (a value from a closed list per field), `Verb` (the words of a command, `[a-z]+( [a-z]+)*`, at most 32 bytes: a shape, not a list), `StreamKey` (`[a-z][a-z0-9-]{0,31}`, the id of a sync system or stream), `LabelSet`, `LabelAllow` and `StoreId` (from `core-labels`; permission fields use LabelAllow and retain empty sets), `EndpointName` (`[a-z0-9-]{1,32}`; this type was called `Label` before labels became the company's table), `ModelId`, `Principal` (`os:<DOMAIN>\<user>` or `local`) and `Via` (`cli`, `chat` or `mcp`). Each validates its shape on construction; `Verb::parse(&str) -> Result<Verb, VocabError>` and `StreamKey::parse(&str) -> Result<StreamKey, VocabError>` are the makers of the two new ones, and neither has a panicking constructor. `audit verify` parses a `verb`, `system` or `stream` with them (a bad shape is FB0801) and holds no list of verbs. No event field is a `String`. `Actor { principal, role, via }` is built from them.
2. Implement `audit/kind.rs` from [the audit event contract](../reference/audit-contract.md#kinds-and-fields): all 32 kinds, their typed fields, envelope and label rules. `Kind::ALL` and one synthetic sample per kind must agree with it. A field deferred to its raising card stays envelope-only until that card extends the contract and sample.
3. `audit/chain.rs`: `H(n) = SHA-256(prev_hex || 0x0A || body(n))`, where `body(n)` is the line up to the final `,"hash":"<64 hex>"}` and the first `prev` is 64 zeros. `verify` cuts the fixed 75-byte suffix and hashes the rest; it never re-serialises. The parser denies unknown keys.
4. `io/state.rs`: the state folder is `.fieldbook/` beside the Corpus, overridden by `--state` or `FIELDBOOK_STATE` (read by clap, not by `std::env`); it reads `settings.toml` only for `role`. With no role the journal records `agent`. The actor's principal comes from `World::principal()`, a new method of the trait: `Disk` returns `os:<DOMAIN>\<user>`. On Windows it comes from `fieldbook_win::principal()` (`windows-facts`, through `io/win.rs`), the domain and name of the user in the process token. Elsewhere it is `os:local\<account>`, the account name found by mapping the uid of `/proc/self` through `/etc/passwd`. It reads no environment variable for it, because any process can set one. An in-memory `World` returns `local`, and on the laptop preset a token that cannot be read is refused (FB0822) and not recorded as an unknown account. Fieldbook does not authenticate the principal. The operating-system logon does, and the prefix says which source set the actor, so a later identity source adds a prefix and not a key. Event time comes from `World::now() -> Now`, a new method of the trait here and the only clock seam of the program. `Now { date: CivilDate, seconds: u32 }` (a civil date and the seconds of the UTC day) is defined in `audit/mod.rs`. `Disk` reads the system clock, an in-memory `World` returns a fixed `Now`, and no flag or variable reaches it. `Journal::open` reads it once for `journal.open`, and `Journal::begin` and `Journal::end` each read it once. `World::today()` of `check-command` is unchanged and stays the `--today` of `check`. `io/journal.rs`: `Journal::open` takes an exclusive lock on `state/lock`, finds the last hash, and appends `journal.open` at the start of a segment, with its `writer`, `event_schema`, `tool_version` and `stores` (the `store_uid` of every store the run opened; empty before a company store exists). Open releases its initialization lock before returning the handle. Each later append reacquires the lock and rereads the head; a transaction retains that lease through its end. A competing transaction retries every 100 ms for 3 s and is then refused: exit 3 and the message `the journal is in use by another fieldbook process`. This lock serializes journal events; the separate store lease of step 11 protects the tree. `chat.lock` is a separate lock for one chat session. If the last line is torn it moves it to `journal.torn-<seq>` and appends `journal.recover` with `reason = torn_tail` and the `last_seq` and `last_hash` of the last line that chains (0 and 64 zeros when none). `reason` is a `Word` from the closed list `torn_tail`, `broken_chain`. Compare and record the typed settings baseline under the journal lease using [Settings baseline](../reference/audit-contract.md#settings-baseline). Recover it from the last successfully recorded settings.change; initial recording distinguishes absent from empty. Keep group hashing in core, file reads in I/O and AI-key validation in ai-config-and-keys. `Journal::last_time_of(kind: Kind) -> Option<Now>` returns the event time of the newest event of that kind in any segment, and `None` when there is none. `Kind::AuditExport` is the variant for `audit.export`. `egress::shipped` of `core-policy` takes the result. The private initialization helper in journal.rs creates a missing state folder and stable state/lock and state/store.lock files. `write_lease()` calls it before acquiring store.lock; `Journal::open` reuses those files and acquires the journal lock second; read-only `audit show`, `audit verify`, `status` and `backup list` never create them. `tests/support/world.rs` defines `TestWorld { inner: Disk, .. }`, `TestWorld::new(root: &Path) -> TestWorld`, `set_now(Now)` and `set_principal(..)`. It forwards methods to a temporary Disk except these settable facts; its default Now uses fixture TODAY and 43,200 seconds, and its principal is `local`. Add `pub mod world;` to support/mod.rs. Later World method owners add their forwarding/setter entries here.
5. In `audit/mod.rs`: `WriteSet { labels: LabelSet, files: Vec<WriteFile>, affected: Vec<RecordRef> }` and `WriteFile { path: String, sha256: String }`, the one shape of what a write verb is about to write: every file with the hash of the bytes it will write. A verb's plan in core returns the files and affected record IDs; the verb qualifies those IDs as `audit::RecordRef` with their store and adds the labels it computed. The journal holds the file count, typed path/after hashes for in-root writes and sorted, distinct affected record references, never filenames or content. The planner supplies affected references with its files. Only a write to store-level configuration or a derived artifact with no record subject may have an empty list. In `io/journal.rs`: `Journal::begin(&StoreLease, &OperationIntent, &WriteSet) -> Result<Audited, JournalError>` appends `write.begin` with the `verb`, the `labels` of the write set, the count of its `files`, their typed path/after hashes and its `affected` references, and returns an `Audited` token retaining the journal lease; `Journal::end(token, outcome)` appends `write.end` with the same affected references retained by the token and releases it; `Journal::refuse(verb: Option<&'static str>, code: Code, reason: Word, about: &RefuseAbout) -> Result<(), JournalError>` appends `refuse`, where `Code` is the code type of `check-v0`, `JournalError` is the error of a failed append, and `RefuseAbout { sha256, name_sha256, labels, dest, system, stream }` has every field an `Option` (the name avoids `Refusal` of `core-labels`). OperationIntent holds a validated Verb; refuse parses its supplied verb with `Verb::parse`; a bad shape takes the path of a failed append: nothing is written, the exit is 3, and the message is `not a verb word: <text>`. `StateScope` is not a type: `Journal::state_scope(&self, lease: &StoreLease) -> Result<Audited, JournalError>` (in `io/journal.rs`, the only file that builds an `Audited`) appends no event and returns an `Audited` marked state-only, by a private flag with no setter, retaining the journal lease until the token is dropped after the state write. Validate that the caller’s store lease is exclusive and belongs to these roots before acquiring the journal lease and validating the head. Timeout, invalid lease or head failure returns no token and makes no state write. The caller retains the store lease through the write. The two writer doors of `core-policy` take it like any `Audited`, so `io_has_two_writer_doors` is unchanged: `write_in_root` returns `Error::OutOfScope` when it gets a state-only `Audited` and a `RootPath` whose `store()` is not `StoreId::State`, and `write_outside` returns `Error::OutOfScope` for a state-only `Audited`, so a derived-file write cannot touch the Corpus with no `write.begin`; `core-policy` tests this (`state_scope_cannot_write_the_corpus`). A card that writes "under a `StateScope` token" passes the `Audited` that `Journal::state_scope(&lease)?` returns. It is for derived state files that have no event of their own: `reports/` and `pages/`. They are replaced whole through the atomic helper. Text-free controls hold ids, hashes, counts and closed words only; report names, directories and rendered pages are text-bearing metadata and retain their producer’s labels and input references. For a command whose work is something else (`add`, which keeps `reports/last-add.json`), a failed write of one is a warning and does not change the exit code; for `status --page`, whose work is the pages, a failed write is exit 3. Appends take a short lock, or reuse the active transaction lease on this Journal without locking again, write the whole line in one `write_all` and call `sync_data`; at 8 MiB the next event starts `journal-0002.jsonl` and chains to the last hash. Each newly acquired journal lease recomputes the hash of the last line; if it differs from the stored hash, the chain is broken and the append is refused (this is the "chain broken" case of the fail-closed rule, and `audit verify` still reads the file). If an append fails, the caller gets an error that exits 3 with the reason; nothing else is written. `Journal` fills the envelope of every append from the `Actor` it was opened with, and no caller builds one. Journal and its private operation guards own the lock and journal file. Dropping an unfinished transaction releases its lease and leaves its unmatched begin visible; an idle handle holds no lock. A shared store later replaces this implementation (`later-shared-store`). The chain belongs to one writer. In the ports table the folder form is `Store` `folder@1`, which is the `World` and `Disk` that already exist.
6. `audit.rs` and `cli.rs`: `audit verify [--expect-head HEX] [--expect-seq N] [--anchor-seq N --anchor-head HEX] [--repair] [--json]` checks the chain (FB0800), the vocabulary and the envelope (FB0801: a free-text value, an unknown key, or a missing `actor`, `role`, `store` or `via`), the expected length and head (FB0802), a `write.begin` with no `write.end` (FB0803, warning), a recovered torn tail (FB0804, warning) and a time that goes backwards (FB0805, warning). It prints `journal ok: <N> events, head <12 hex>` when clean; exit 0 clean, 1 on an error code, 3 on an I/O error. `--repair` is the only mode of `audit` that writes, and it is a flag and not a verb. On a clean journal it writes nothing and prints `journal ok`. On a broken chain (FB0800, FB0801, or a last line whose hash does not match) it takes the store write lease, rereads the broken chain, then retains the journal lease with `Journal::open_for_repair`, which skips the tail check that refuses appends, and moves every segment of the journal, unchanged, into a folder `journal.broken-<seq>` beside it, where `<seq>` is the sequence number of the first bad line. It then starts a new chain: `journal.open`, then `journal.recover` with `reason = broken_chain` and the `last_seq` and `last_hash` of the last line of the old journal that chains. It reports FB0804 as a warning that names the folder and exits 1. Nothing is deleted and the old events stay readable there; backup remains available only when classification and target permissions allow every retained byte; invalid journal/control schema contributes unlabelled. The repair has no `write.begin` pair, because the journal that would hold it is the broken one; the `journal.recover` event is its record. `audit show [--last N] [--kind K] [--id ID] [--label L] [--head] [--json]` prints events, or the sequence and head to keep. `--json` follows [Adding a JSON report](README.md#adding-a-json-report): the structs `AuditShowReport` and `AuditVerifyReport` in `fieldbook-core::report`, one row of the table in `crates/fieldbook/tests/json_reports.rs` for each, the goldens `tests/golden/json/audit-show.json` and `audit-verify.json`, and `cargo xtask docs`, which prints the shapes in the "JSON reports" section of [cli.md](../reference/cli.md). `check-command` made `report.rs`, `json_reports.rs` and the test `json_goldens_match_reports`.

   ```json
   {
     "report_version": 1,
     "verb": "audit show",
     "head": { "seq": 12, "hash": "<64 hex>" },
     "count": 12,
     "shown": 3,
     "events": [
       { "seq": 10, "kind": "write.begin", "hash": "<64 hex>" },
       { "seq": 11, "kind": "write.end", "hash": "<64 hex>" },
       { "seq": 12, "kind": "backup.verify", "hash": "<64 hex>" }
     ],
     "exit": 0
   }
   ```

   `events` are the journal lines parsed to objects, every key as stored in the line (so each event also carries its time and its kind's typed fields; the sample above shows three keys only), oldest first. `count` is the number of events in the journal and `shown` is `events.len()`. The default is `--last 50`; the Activity log page asks for 200. `--head` gives `head` and `count` and an empty `events`.

   ```json
   {
     "report_version": 1,
     "verb": "audit verify",
     "state": "ok",
     "events": 12,
     "head": { "seq": 12, "hash": "<64 hex>" },
     "findings": [],
     "unfinished": [],
     "exit": 0
   }
   ```

   `state` is `ok`, `broken` (FB0800, FB0801 or FB0802), `torn` (FB0804: a torn tail was moved aside) or `unfinished` (FB0803: a `write.begin` has no `write.end`). `findings` holds `{ "code", "severity", "seq" }` for each diagnostic in the order raised; FB0805 (time goes backwards) is a finding and never changes `state`. `unfinished` lists the `seq` of each `write.begin` with no `write.end`. A broken journal still prints the report and exits 1. `audit show` reads only, and `audit verify` reads only unless `--repair` is given, so both run when the journal is broken.

11. Build the coherent-read seam in [Policy](../reference/policy.md#consistent-reads): StoreLease read/write guards over the same state/store.lock, a committed generation hash and pending-write detection. A write guard encloses the complete in-root write.begin/write.end transaction.
