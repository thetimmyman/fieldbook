# core-policy

- **Runs where:** home, CI Linux
- **Schema impact:** none
- **Review:** owner

## Outcome

`fieldbook-core` can read a company policy and decide, in one pure function, whether labelled data may go to a destination. `Policy::parse` checks a policy file against schema 1 and raises FB0413 for every rule the loader enforces. `Policy::floor(FloorKind)` is the built-in policy that applies when none is configured: floor A when no company store is on the machine, floor B when one is. `egress::check` is the only function that makes an `Allowed` token, and it denies with FB0901, FB0902, FB0918 or FB0925. `LabelledView` is built from an `Allowed` token and from the stores the actor may read. The `Authz` port is declared with its default adapter `policy-readers@1`. The label-leak matrix runs a synthetic policy over every destination kind. `io::atomic` has two writer doors, one of which takes the token, and the built binary is scanned for network, process-start and clipboard calls in every pull request and in the release.

## Why

- The policy file, its states, the floors and the merge with the owner's settings are in [the policy reference](../reference/policy.md) and [ADR 0004, sections 3, 5 and 6](../decisions/0004-company-boundary.md#3-the-company-policy-file). The decision order is in [section 5](../decisions/0004-company-boundary.md#5-egress). The `Authz` port is in [section 11](../decisions/0004-company-boundary.md#11-actor-session-and-authorisation).
- Every later card that lets data leave takes the token this card defines: the page context pack, `backup`, the model gate, the tool server, export and print. So the type and its test come first and alone, and the pricing cards have a gate to stand on.
- The card is `owner` reviewed: the label, policy and egress modules of `fieldbook-core` are on the release gate (AD-21). The evidence IT can ask for is built here: the leak matrix, the negative controls, the scan of the built binary and, from `mutation-report`, a mutation gate.
- The token is a design aid, not a boundary. A new dependency, a macro or an unsafe block can still reach the operating system, and a text scan of the source cannot see that. So the types and the two writer doors stop honest mistakes, and the scan of the built binary is the check that something else did not slip in.
- Nothing is read from a disk or the environment here. The path, the file read, the writer check, `policy show`, `policy check` and the closed state at run time are `policy-load`.

## Steps

1. `policy/schema.rs`: the serde structs of schema 1, each with `deny_unknown_fields`: the top level (`policy_schema`, `revision`, `example`), `[[label]]` (`id`, `title`, `banner`, `restricted`), `[[marking]]` (`match`, `labels`), `[[source]]` with `[[source.rule]]` and `[[source.map]]` (`id`, `root`, `default`), `[[store]]` (`id`, `holds`, `default`, `readers`, `changers`, `hold`), `[[destination]]` and `[audit]` (`sink`, `max_unshipped_hours`, `require_fresh_export`), with the keys and limits of [the policy reference](../reference/policy.md#schema-version-1). A title and a banner are at most 80 code points with no control character; a `match` is 3 to 80 characters.
2. `policy/parse.rs`: `Policy::parse(text: &str, recorded_revision: Option<u64>) -> Result<Policy, PolicyError>`. It reads at most 1 MiB of valid UTF-8 and skips one leading U+FEFF (a byte order mark, which Windows tools write) before the parse; a second mark is part of the text and fails it. `policy_hash` is taken over the text as given, mark included, so the hash is the hash of the file's bytes. It parses with the structs of step 1, and then checks each rule of [Rules the loader enforces](../reference/policy.md#rules-the-loader-enforces), in the order of that table. Every failure is FB0413. A `PolicyError` names the rule and the key path (`destination[2].allow`) and the label id where there is one; it never prints a title, a banner or a `match` text. Accessors for the later cards: `Policy::source(system_id)` (the `[[source]]` row, with its `root`), `Policy::store_row(&StoreId)`, `Policy::label(&LabelId)`, `Policy::marking_rules() -> MarkingRules` (the `[[marking]]` rows, through `MarkingRules::with_rows` of `core-labels`) and `Policy::audit()` (the `sink`, the limit and `require_fresh_export`, which is `true` when the key is absent; the fields are in [Audit](../reference/policy.md#audit)). The rule "a `model` row that allows a non-public label needs a sink and a limit" applies only while `require_fresh_export` is true, and `sink` is required in an `[audit]` table only while it is true. Tests, one for each row of the table and one positive case: `the_fixture_policy_parses`, `unlabelled_in_allow_is_invalid`, `marked_in_allow_is_invalid`, `a_fixed_kind_is_invalid` (`git`, `edition` and `audit`), `a_store_row_for_corpus_is_invalid`, `an_undefined_label_is_invalid` (in `allow`, `holds`, `default` and `labels`), `a_company_label_must_be_opaque`, `a_duplicate_or_builtin_id_is_invalid`, `owner_supplied_is_refused_everywhere_but_state_holds`, `a_restricted_label_needs_readers`, `readers_changers_and_hold_are_invalid_on_corpus`, `default_outside_holds_is_invalid`, `a_source_needs_an_absolute_root_or_drop`, `mcp_and_clipboard_allow_public_only`, `a_model_row_with_a_company_label_needs_an_audit_sink_and_limit` (the requirement is on), `a_missing_require_fresh_export_means_on` (positive: an `[audit]` table with no `require_fresh_export` reads as `true`, and the model row of that policy is still invalid without a limit), `with_the_requirement_off_a_model_row_needs_no_sink_or_limit`, `a_non_boolean_require_fresh_export_is_invalid` (negative: `"no"` and `0` are each FB0413 naming `audit.require_fresh_export`), `a_model_row_needs_an_https_or_loopback_url`, `paths_only_on_export_and_backup`, `a_windows_or_posix_absolute_path_is_valid_on_every_host`, `a_relative_or_dotdot_path_is_invalid`, `an_expires_in_quotes_is_invalid`, `clients_only_on_mcp`, `an_example_file_is_invalid`, `unknown_key_table_or_schema_is_invalid`, `a_lower_revision_is_invalid`, `an_equal_or_higher_revision_is_valid`, `oversize_or_non_utf8_is_invalid`, `a_byte_order_mark_is_skipped_but_hashed` (the fixture with a leading U+FEFF parses to the same `Policy` as without it, and `policy_hash` of the two texts differs, the one with the mark being the digest of its bytes), `two_byte_order_marks_are_invalid`, `errors_never_print_a_title`. The fixture `policy.toml` has an `[audit]` table with no `require_fresh_export`, so the default is what the tests read; a test for the off setting edits that table in its own copy of the text. `parser_never_panics_on_200_seeded_inputs`, in `crates/fieldbook-core/tests/policy_parse_no_panic.rs`: It includes the generator with `#[path = "../../../tests/support/rng.rs"] mod rng;`, builds 200 byte strings of length 0 to 128 from `Rng::new(1)`, and takes the fixture policy with each of its bytes once flipped and once deleted. Each goes through `String::from_utf8_lossy` into `Policy::parse`, once with `recorded_revision` `None` and once with `Some`. The result is a `Policy` or a `PolicyError` and nothing panics.
3. `policy/floor.rs`: `Policy::floor(FloorKind)` is the floor table of the reference, as data, for `FloorKind::A` (no company store on the machine) and `FloorKind::B` (a company store and no policy): the stores (floor B's `overlay`, `working` and `state` also hold `marked`, through `StoreRule::floor(store, true)`), and one destination row each for `handoff`, `model` (the row an endpoint named in settings uses), `mcp`, `bridge`, `print`, `clipboard`, `export` and `backup`. Floor B's `model` row is empty and its `export` row is refused. Its `backup` row is the one narrow route: it allows `public`, `unlabelled` and `owner-supplied` only to a target whose `Dest::Backup` carries `company_storage = true` (the key of a `[[backup.target]]` in `settings.toml`), and never `marked`. No row of either floor allows `marked`. The layout, not the policy, chooses the kind: `FloorKind::for_machine(has_company_store: bool)`. `Policy::store_rule(&StoreId) -> StoreRule` is the `[[store]]` row of a loaded policy (`holds`, `default`, `readers`, `changers`, `hold`), the floor row for a store with no row (the floor table's own row when the policy is the floor, and `StoreRule::floor(store, false)`, which has no `marked`, when the policy is loaded), and always `StoreRule::corpus()` for `corpus`; it is the one place a layout asks what a store may hold. `FLOOR_HASH_TEXT` is `fieldbook-floor-policy-1`, and `policy_hash(&PolicyState)` is the SHA-256 of the file's bytes for a loaded policy and of that text for the floor, in lowercase hex through `hex::lower`. Tests: `store_rule_is_the_row_the_floor_or_corpus` (a policy with a row for `overlay` and none for `working`: the row, the floor row without `marked`, and `corpus` stays `public` only), `floor_a_allows_public_and_owner_supplied_to_handoff`, `floor_a_model_row_allows_public_only`, `floor_a_export_and_backup_allow_public_and_owner_supplied`, `floor_b_sends_nothing_to_a_model`, `floor_b_refuses_export`, `floor_b_stores_hold_marked_and_floor_a_stores_do_not`, `no_floor_row_allows_marked_to_any_destination`, `a_loaded_policy_gives_an_unlisted_store_no_marked`, `floor_b_backup_never_holds_marked`, `floor_b_backup_needs_the_recorded_target`, `floor_hash_is_the_hash_of_the_text` (compares with a digest stored in `tests/golden/policy/floor-hash.txt`, computed by a different tool), `a_loaded_policy_hash_is_the_hash_of_its_bytes`. `Policy::floor_sentence() -> String` writes the Floor block of the reference (the text after the prefix `> **Floor.** `) from the two floor tables in code: the lead sentence "Until a policy file has been loaded on this machine, the floor applies."; the stores clause (the stores that share one `holds` set listed together, the label that only `state` adds, then `corpus`); one sentence for each distinct floor-A `allow` set, the set with more labels first, with its kinds in the order of `DEST_KINDS`, the phrases "Handoff", "exports", "backups", "a model endpoint named in the owner's settings", "the tool server", "the chat Bridge", "print" and "the clipboard", and labels in the order `public`, `unlabelled`, `owner-supplied`; then one clause, opened by "On a machine that holds a company store,": first the stores whose floor-B `holds` are larger than floor A's, listed together and reading "the stores", their names, "also hold" and the extra labels; then, for each kind whose floor-B row differs from floor A, an empty set reading "no model endpoint receives anything" for `model` and "exports are refused" for `export`, and a larger set reading "a backup to a folder the owner recorded as company storage may also hold" and the extra labels; and the closing "No endpoint is approved, and nothing marked leaves.", whose second half is true because of `no_floor_row_allows_marked_to_any_destination`. Tests: `floor_sentence_matches_the_reference` (reads the line of `docs/reference/policy.md` that starts `> **Floor.** ` with `include_str!` and compares the rest of the line with the sentence), `floor_sentence_groups_kinds_by_label_set` (a floor value built in the test in which `print` allows `public` and `owner-supplied` moves `print` into the first group), `floor_sentence_changes_when_floor_b_changes` (a value in which floor B allows `export` changes the clause, and one in which floor B's `working` does not hold `marked` changes the stores clause). Every permission list and `allow_set` result is `LabelAllow`, not LabelSet; an empty allow set stays empty. Add `an_empty_permission_intersection_stays_empty` and `public_and_company_permissions_both_survive`.
4. `policy/state.rs`: `PolicyState::{Floor(FloorKind), Loaded(Policy), Closed(ClosedWhy)}` with `ClosedWhy::{Absent, Invalid, LowerRevision, Writable}`; `Absent` means that a policy was loaded here before (a revision is recorded) and the file is now missing, whereas a missing file with no recorded revision is `Floor`; `Writable` is the writer check of `policy-load` (FB0418). A `Closed` state denies every destination except `Dest::Audit`. Test: `closed_denies_all_but_audit`.
5. `policy/merge.rs`: `OwnerSettings`, a plain struct (the owner's lists and numbers, filled by the settings parser of `ai-config-and-keys`): for each model endpoint a `LabelAllow` (an endpoint with no entry accepts nothing), for the `handoff` and `mcp` rows an `Option<LabelAllow>` (`None` is no narrowing, so the policy row stands), `keep_calls` and `keep_days`, and `KEY_TABLE`, one row for each settings key that meets the policy: the key, its kind (list, switch, number or word) and the policy side. Merge rules: a list intersects, a switch is AND, a number is the minimum, a word is the policy's. `EffectivePolicy::new(&PolicyState, &OwnerSettings)` gives each destination row its narrowed `allow`. `allow_set(&Dest) -> LabelAllow` returns that narrowed set (empty when there is no row or the state is Closed; `check` tests expiry against its `now`), `banner(&LabelId) -> Option<&str>` returns the label's banner from its `[[label]]` row, `marking_rules() -> MarkingRules` returns `Policy::marking_rules()` of a loaded policy and `MarkingRules::builtin()` for the Floor and Closed states, and `explain(dest) -> Vec<Cut>` says, for each label that is cut, whether the policy or the owner cut it. An endpoint with no owner list accepts nothing. `OwnerSettings::unset()` is the settings of a run that has none (no endpoint list, no narrowing, no `keep_calls` or `keep_days`), and `EffectivePolicy::floor(has_company_store: bool)` is `EffectivePolicy::new(&PolicyState::Floor(FloorKind::for_machine(has_company_store)), &OwnerSettings::unset())`: the policy that `build`, `backup` and `restore` use until `policy-load` hands each run its own. Tests: `effective_floor_is_the_floor_of_the_machine` (`floor(false)` and `floor(true)` give the floor A and floor B `allow_set` for `Dest::Handoff` and for a `Dest::Backup` with `company_storage` true), `a_list_intersects`, `the_owner_cannot_widen`, `absent_handoff_and_mcp_lists_do_not_narrow`, `a_switch_is_and`, `a_number_is_the_minimum`, `an_endpoint_without_an_owner_list_accepts_nothing`, `explain_names_the_side_that_cut`, `allow_set_is_the_narrowed_set`, `a_banner_comes_from_the_label_row`, `key_table_matches_the_policy_reference` (reads the "Narrow only" table of `docs/reference/policy.md` with `include_str!` and compares keys and rules). The test `settings_keys_have_merge_rules` belongs to `ai-config-and-keys`, which owns the settings parser.
6. `egress/dest.rs`: `Dest`, with `Model { name, base_url }`, `Handoff`, `Mcp { client }`, `Bridge`, `Export { path }`, `Backup { path, company_storage }` (the target's switch from `settings.toml`; false for a one-off `--to` target), `Print`, `Clipboard`, `Audit`, `Git` and `Edition`, and `DEST_KINDS`, the one const list of kinds: kind, source (policy row or fixed), whether it is advisory, `shows_left_out_count`, what binds the row (name and url, a client list, a path prefix, nothing) and the token-taking API that sends to it. `shows_left_out_count` is true for `handoff`, `export` and `print`, and false for `model`, `mcp`, `bridge`, `clipboard` and `edition` (an edition is read by anyone who gets a copy). Tests: `dest_kinds_match_policy_docs_and_matrix` (compares `DEST_KINDS` with the kinds the loader accepts, with the rows of the "Destination kinds" table of `docs/reference/policy.md` including its advisory and left-out columns, and with the columns of the leak matrix), `fixed_rows_allow_public_only`, `advisory_kinds_are_handoff_print_and_clipboard`.
7. `egress/decision.rs`: `check(&EffectivePolicy, &Dest, labels: Option<&LabelSet>, delivery: Option<&Delivery>, now: Now, shipped: Shipped) -> Decision`, in the order of [The decision](../reference/policy.md#the-decision): Closed (the code is FB0413, the code of the file that closed it); any label `marked` or outside the table (FB0901), and any label `unlabelled` (FB0901) unless the state is `Floor(FloorKind::B)` and the destination is a `Backup` whose `company_storage` is true, where the order goes on to the next steps and the floor `backup` row decides; no row, expired row (the row applies through its `expires` date, judged against `now`), model URL different from `base_url`, client hash not listed, or a path outside every `paths` prefix (FB0918); a label outside the narrowed `allow` (FB0901); `delivery.markings` (from labels::markings_in on the exact outbound text) not a subset of the request's labels (FB0902); and, for a `Model` destination with a non-public label while `[audit] require_fresh_export` is true (the default), `shipped` older than `[audit] max_unshipped_hours` or `Shipped::Never` (FB0925); with it false this step is skipped and FB0925 is never raised. `Now` is the type of `audit-journal` (a civil date and the seconds of the day), and `Shipped` is `Never` or an age in hours; both are plain values. `shipped(last_export: Option<Now>, now: Now) -> Shipped` is in the same file, beside `Shipped`: `Never` when `last_export` is `None`, otherwise the whole hours since it, rounded down. A verb that calls `check` passes `egress::shipped(journal.last_time_of(Kind::AuditExport), now)`. One function, `World::now()`, reads the system clock, and the release binary has no flag or variable that reaches it. `covers(&EffectivePolicy, &Dest, &LabelSet, now, shipped) -> bool` is `check` with `Some(labels)` and no delivery, reduced to a yes or no, for status display after any refusal that must be preserved has been handled; it hands back nothing a caller can keep. Route selection inspects the complete Decision first and preserves FB0413 and FB0925 before reducing ordinary coverage to a bool, so missing/stale required audit export cannot silently select another route. `Decision` is `Allowed(Allowed)` or `Denied(Denial)`. `Denial` holds the code, a `Reason` word from the closed list of the journal `refuse` event (`label`, `unlabelled`, `marked`, `no-row`, `expired`, `url`, `client`, `closed`, `mismatch`, `shipped`) and the request's label ids; it holds no title and no text. `Allowed` has private fields, no public constructor and no `Clone`; it carries the destination kind, request labels, permitted LabelAllow, policy hash and private delivery binding (step 16), with a selection-only state when no delivery is supplied. The caller journals the decision before sending; every sink verifies the bound delivery. For a `Model` destination the row is found by `name`; for `Export` and `Backup` by the canonical `paths` prefix on whole components; if more than one export row contains the path, the allowed set is the union of those rows. Tests, in `tests/egress.rs`: one for each step of the order and one positive case for each kind: `closed_denies_first`, `unlabelled_is_denied_even_if_a_row_lists_it`, `floor_b_backup_takes_unlabelled_only_to_the_recorded_target` (allowed there; FB0901 for a backup whose `company_storage` is false, for every other kind of destination and under a loaded policy; `marked` is denied there too), `an_unknown_label_is_denied`, `no_row_is_fb0918`, `an_expired_row_is_fb0918`, `the_row_applies_through_its_last_day`, `a_different_url_is_fb0918`, `an_unlisted_client_is_fb0918`, `a_path_outside_every_prefix_is_fb0918`, `export_rows_union`, `a_label_outside_the_row_is_fb0901`, `the_subset_test_needs_every_label`, `a_marking_outside_the_request_is_fb0902`, `a_plain_text_has_no_mismatch`, `the_owner_list_narrows_the_decision`, `a_stale_export_stops_a_company_model_call` (fb0925; the requirement is on, by default), `no_export_ever_stops_a_company_model_call`, `with_the_requirement_off_a_lapsed_export_allows_the_call` (the same policy with `require_fresh_export = false`: `Allowed`, and `allowed_carries_kind_labels_and_hash` still holds for it), `a_public_model_call_ignores_the_export_age`, `shipped_is_never_with_no_export`, `shipped_counts_whole_hours_since_the_last_export`, `covers_agrees_with_check`, `allowed_carries_kind_labels_and_hash`, `a_denial_holds_no_title`.
8. `egress/view.rs`: `LabelledView::new(&Model, &Allowed, &ReadableStores) -> LabelledView`. A filtered Tree retains only known structural directories of its selected stores, including an empty originals root, and ancestors of permitted files. It never retains arbitrary directories emptied by filtering or infers originals-root absence from having no visible files. Directory presence grants no content access. It keeps a page, a source version or a record only if every label it carries is in the allowed set and it lies in a store the actor may read, and the rows that point only at kept ones. A record outside the set is left out whole, never redacted. `left_out()` returns the count, and `left_out_line(&Dest) -> String` returns `Left out (policy): N records` for a kind with `shows_left_out_count` and the fixed line `Some records were omitted.` for the others, with no number. `ReadableStores` is the list that `authz::readable` makes (step 9); `ReadableStores::corpus()` is the list with `corpus` alone, for the build and the edition pages, which read no other store. The view is the only content input of anything that builds an output for a destination. It exposes filtered equivalents of `Model`'s typed accessors (`pages`, `sources`, `claims`, registers, citations and index), and `tree()` contains only their permitted files plus public control metadata needed by renderers. No accessor returns the unrestricted model or tree; `BuildInfo` may be passed separately. Tests: `a_record_outside_the_set_is_left_out_whole`, `left_out_counts_what_was_dropped`, `a_record_inside_the_set_is_kept`, `a_row_that_points_at_a_dropped_record_is_dropped`, `a_view_for_public_keeps_only_public`, `a_store_the_actor_may_not_read_is_left_out`, `the_count_is_shown_only_to_kinds_that_show_it`, `the_model_reply_text_does_not_change_with_the_count`, `a_corpus_only_list_keeps_only_corpus_records`, `filtered_tree_keeps_structure_without_hidden_paths` (an empty selected originals root remains present; an arbitrary nested directory containing only a forbidden-label canary is absent, while ancestors of a permitted file remain).
9. `authz.rs`: the trait `Authz` with `allow(&Actor, Act, &Scope) -> AuthzDecision`, `Scope { store: StoreId, labels: LabelSet }` (what the act is on), the enums `Act` (`Read`, `Propose`, `Accept`, `Export`, `Admin`) and `AuthzDecision` (`Allow`, `Deny(Word)`), and the trait `Groups` (`in_group(&self, group: &str) -> Option<bool>`, where `None` is a token that could not be read). The default adapter is `PolicyReaders` (id `policy-readers@1`): `Read` on a store is allowed when the store's row names no `readers` or the token is in that group, and denied when the token cannot be read; `Admin` (for `label add`) follows `changers` the same way; every other act is allowed. `readable(&dyn Authz, &Actor, &[StoreId]) -> ReadableStores` is the one function that decides which stores a view may use; it is called before a store is opened. There is no `visible` function: a view takes the stores the actor may read, and the label subset takes care of the rest.
