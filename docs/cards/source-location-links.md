# source-location-links

- **Runs where:** home, CI Linux
- **Schema impact:** none
- **Review:** owner

## Outcome

Each `s/` page shows its version's official `location` as a link, and each section locator on it as a link to that section at the official publisher, for the publishers a rule table in `source.rs` names.

## Why

- The need. 28,234 of 28,857 claims (98%) cite eCFR HTML originals, which ship as raw markup with a `.txt` name ([intake README](../intake/README.md), the HTML originals paragraph), and every `s/` page says "Excerpt is not available until this version is extracted" until `extract-and-locators` and `quote-match-and-anchors` merge behind the release gate. Today the reader of `s/S-0003-v1.html` sees 79 § locators as plain `<span class="loc">` text and the register's `location` as plain text, with no way to read the section itself except by copying an address.
- This is against settled rules, and a link on an `s/` page makes each of these statements untrue: [AD-12](../decisions/0001-foundation.md#ad-12-site-generation-and-page-types) (Links) and decision D-20 in ADR 0001 say external URLs are text with a copy button, "a lint fails any `href=\"http`" (`FB0604`, `crates/fieldbook-render/src/lint.rs`), and control WB-02 in [docs/controls.md](../controls.md) says the same ("no `href=\"http`"); NFR-S-12 in ADR 0001 promises a Tier-0 intake pack stating that the edition holds no external links; `HANDOFF.md` section 11 (External URL) says "never a link"; and section 2 of [docs/intake/transfer-statement.txt](../intake/transfer-statement.txt) tells IT that the build refuses "a link to a remote address in any asset". [docs/intake/network-silence.md](../intake/network-silence.md) tells IT that the edition makes no outbound connection: a link does not make the page connect, but a click sends the laptop's browser to the publisher. AD-12, D-20 and NFR-S-12 change by an ADR amendment, and the transfer statement is an IT-facing statement under the release gate, both the owner's ([AGENTS.md](../../AGENTS.md#authority)); hence `Review: owner`.
- The owner's decision, recorded on the pull request that added this card: outbound links are allowed on `s/` pages, to the official publishers a rule table names, and nowhere else. The owner approved the exact wording of the two IT-facing edits in Step 1; this card makes them word for word, in the same pull request as the code, so the statements IT reads never run ahead of the build. `SECURITY.md` says nothing about links and does not change.
- The hosted CSP (`deploy/_headers`, equal to `CSP_STATIC` plus `frame-ancestors 'none'`) sets no navigation directive, so it neither blocks nor needs changing for a link; [ADR 0007](../decisions/0007-hosted-edition.md) keeps the hosted pages byte-identical to every other build of the commit, so a link cannot be hosted-only.
- Design: `MAP.md` row Source drawer (`LocatorView`); `HANDOFF.md` section 5 (`LocatorView`) and section 11 (External URL), as revision 22 (`design-r22-reader-pages`) words them after the owner's decision.

## Steps

1. Make the two owner-approved IT-facing edits, word for word, with the line wrapping of each file:
   - In section 2 of `docs/intake/transfer-statement.txt`, replace the sentence "The edition build refuses to pack an executable, library, script, shortcut or macro-enabled workbook, a link to a remote address in any asset, or an HTML or SVG original outside the site." with: "The edition build refuses to pack an executable, library, script, shortcut or macro-enabled workbook, a link to a remote address in any asset other than a source page's links to an official publisher, or an HTML or SVG original outside the site. A source page links each cited source, and each section it cites, to the official publisher's copy, for the publishers the build names. No page loads anything from those addresses. Following a link is the reader's own click, which opens the publisher's site in the browser."
   - In section 3 of `docs/intake/network-silence.md` ("What it does not prove"), add this bullet after the first: "- It covers what the pages load, not where a reader goes. Source pages (`s/`) link to the official publisher of each cited source, for the publishers the build names. Following one is a click that opens that publisher's site in Edge; the harness does not follow links."
   If a test or the edition build compares either file with a fixed copy, update that copy in the same commit and name it in the pull request.
2. Amend the AD-12 Links paragraph, the D-20 row and the NFR-S-12 row in ADR 0001 as the owner decided, and narrow `FB0604` to an `https:` link with the attributes the revision names, on an `s/` page only, to a host in the rule table; every other `href="http` still fails. Change the `FB0604` text in `code.rs` and the `FB0604` row of the corpus-format check catalogue to match, run `cargo xtask docs` and commit the regenerated `docs/reference/errors.md`, since `just check` runs `cargo xtask docs --check`. Give the WB-02 row of `docs/controls.md` the same `s/` official-publisher exception; its test `external_href_is_fb0604` (a link on `page.html`, outside `s/`) must still fail.
3. In `source.rs`, a rule table: for each publisher, the host and how a section locator becomes a section address (the eCFR first). A version whose `location` is on no listed host, or is `metadata-only: `, shows text as today.
4. In `source.html`, render the location link and each locator link with the locator text beside it, as the revision says.
5. Tests in `tests/source.rs`: `ecfr_location_is_a_link`, `ecfr_section_locator_links_to_its_section`, `unlisted_host_stays_text`, `metadata_only_location_stays_text`; in `tests/site_lints.rs`, `fb0604_still_fails_outside_source_pages`.

## Acceptance

```sh
cargo nextest run --locked -p fieldbook-render --test source
cargo nextest run --locked -p fieldbook-render --test site_lints
just check
```

Expected: the tests pass; `just check` exits 0.

## Negative control

Put an `https:` link on a `p/` page of a fixture build: `fb0604_still_fails_outside_source_pages` must fail with `FB0604`. Restore it. Remove the host check from the rule: `unlisted_host_stays_text` must fail. Restore it.

## Rollback

Revert the merge commit, including the ADR text and the regenerated `errors.md`. `s/` pages show text again and `FB0604` fails every external link.

## BLOCKED

If the build or a check needs any `docs/intake/` text other than the two approved edits, any `SECURITY.md` line, a CSP change or a link outside `s/` pages: comment `BLOCKED: source-location-links needs <what>`, push the branch and take the next card. Never edit `SECURITY.md` from this card, and never reword the approved intake text.
