# model-gate

- **Runs where:** home, CI Linux
- **Schema impact:** none
- **Review:** owner

## Outcome

Every call to a model in the program has one way in: `Guarded::run`. It picks the route, checks that the adapter is available, asks `egress::check` whether the policy allows every label of the request to this endpoint, scans the final prompt for a marking whose label the request lacks, counts the budget, appends `ai.begin` before anything is sent, runs the adapter and retries only what can be retried, validates the reply against its schema with one repair, appends `ai.call`, keeps a call record and returns an answer with its provenance, or a Handoff ticket. A `Router` takes the first entry of `[model] order` whose effective allow set covers the request's labels. Nothing calls a model yet: the gate is proved with test doubles, and the first real adapter and verb arrive with `model-handoff-ask`.

## Why

- This is the one gate of the Ports paragraph in [The architecture in one page](../decisions/0001-foundation.md#the-architecture-in-one-page) and the Determinism bullet of [AD-01](../decisions/0001-foundation.md#ad-01-architecture). It is never cut ([Cut line and floor](../decisions/0001-foundation.md#cut-line-and-floor)). The controls are HG-09 (a label the policy does not allow to the endpoint), HG-10 (a marking in a prompt that the request's labels do not cover) and AL-04 (a call that left no trace) in [controls.md](../controls.md); the codes are FB0901 to FB0912, FB0914 to FB0916, FB0918, FB0919 and FB0925 in [09: model, decide, index, output, MCP and chat](../reference/corpus-format.md#09-model-decide-index-output-mcp-and-chat).
- The order of the eleven stages (G1 to G11, in step 4) is the design. Stages G3 to G6 run before any adapter code, so a bug in an adapter cannot send what the gate would have refused; a test adapter whose `attempt` panics proves it. A refusal for policy (route, label, marking, budget) never falls back to Handoff by itself, because falling back would route around the refusal; a failure of availability (a build without the `net` feature, the CPU, an unreachable endpoint after retries) does, because nothing was refused. The fallback is a new destination, so it is checked in its own right: a pack is built only if the `handoff` row allows every label of the request.
- The gate does not decide what may leave. `egress::check` of `core-policy` is the one pure function that decides, and the gate calls it and cannot send without the `Allowed` token it returns ([ADR 0004, section 5](../decisions/0004-company-boundary.md#5-egress) and [section 7](../decisions/0004-company-boundary.md#7-model-endpoints-and-the-ai-before-any-approval)). The failure this prevents: a second, hand-written comparison of labels in an adapter or in a verb that drifts from the policy, so that one path sends what another refuses.
- The audit comes first and last. If the journal cannot record `ai.begin`, nothing is sent (FB0903); if it cannot record `ai.call`, the reply is thrown away (FB0904). A begin with no call is an unfinished transaction that `audit verify` reports (FB0803, the same rule as an unfinished write). A Handoff round trip is the pair `ai.pack` and `ai.paste` instead, because nothing is sent.
- A model answer is not an input to a build. It is kept as a call record for review and for `--resume`, and a build reads only files that a person accepted (mechanism M6 of AD-01).
- Review is `owner` because this card adds `io/net.rs`, the one place a request is sent, and the [cards README](README.md#the-three-header-fields) makes anything under `crates/fieldbook/src/io/net*` owner-reviewed. The gate is also the control for HG-09, HG-10 and AL-04.
- No page, template or string shown in a browser is built here, so there is no Design bullet.

## Steps

1. `adapters/model.rs`, the types of the port: `Route { name, base_url, model, timeout_s, max_reply_bytes }` (`name` is an `EndpointName`; a route holds no approval, because approval is a row of the company's policy), `Finish { Stop, Length, ContentFilter }`, `RawReply`, `PackText`, `Attempt { Reply, Pack }`, `AttemptError { Transient(Connect | Timeout | RateLimited { retry_after_s } | Server(u16)), Permanent(Auth | Rejected(u16) | Tls | TooLarge | Truncated | Redirect | Unavailable(Reason)) }`, `trait ModelAdapter { fn id(&self) -> &'static str; fn caps(&self) -> Caps; fn attempt(&self, allowed: &Allowed, req: &ModelRequest, route: &Route) -> Result<Attempt, AttemptError>; }` (`attempt` takes the `Allowed` token as its first argument and hands it to the transport; an adapter is built with the `KeySource` it needs and reads its endpoint's `key_env` through it inside `attempt`, and it is never handed the journal or the clock), `trait ModelPort { fn plan(&self, via: Option<&str>, base: &LabelSet) -> Result<Plan, ModelError>; fn run(&self, req: &ModelRequest, via: Option<&str>, stop: &dyn Fn() -> bool) -> Result<ModelOutcome, ModelError>; fn resume(&self, ticket: &str, pasted: &str, label: Option<&str>) -> Result<ModelAnswer, ModelError>; fn describe(&self) -> Vec<RouteInfo>; fn preview(&self, req: &ModelRequest, via: Option<&str>) -> SendPreview; }`, where `plan` returns the `Plan { name, dest }` of the first candidate whose effective allow set covers the labels `base` (a caller that must cut its context first asks this, so that the context is cut for the route that will be used), and `run` takes `stop`: the retry loop checks it before each retry and before each pause, and a `true` ends the loop with the last error and `outcome = cancelled`; `ask` and every other caller pass `&|| false`, `ModelOutcome { Answer, Deferred }`, `ModelAnswer` and `Provenance` (private fields, built only in `gate.rs`; the answer has read-only `request_labels()` and `input_refs()` accessors for the request facts saved by the gate), `RouteInfo` and `ModelError`. A `ModelError` holds the code, a kind (`Policy`, `Availability` or `Invalid`), a help line from the catalogue and an optional `HandoffTicket` for the fallback; its text never includes a byte of an endpoint's reply. The traits `AiJournal` (`begin(event) -> Tx`, `finish(tx, event)`), `Pace` (`sleep_ms`) and `CallStore` (`put_call`, `put_pack`, `get_ticket`, `mark_used`) are declared here, with `Deps { journal, keys, pace, policy_provider, keep, budget }`, where budget is the shared RunBudget count and policy_provider supplies a fresh PolicySnapshot before every attempt; marking rules, actor, clock and shipped age come from that snapshot, never from a captured run date; `KeySource` is the one from `ai-config-and-keys`. Add `prepare(&self, req: &ModelRequest, route: &Route, context: &PreparationContext) -> Result<PreparedAttempt, AttemptError>` to ModelAdapter; `PreparationContext { policy_hash: Sha256, banners: BTreeMap<LabelId, String> }` is an immutable data projection of the same fresh PolicySnapshot used for final authorization; adapters perform no policy read or clock access. `PreparedAttempt { target, bytes, content_type }` owns the exact serialized outbound body (or Handoff text). `attempt` takes this prepared value instead of reserializing req, and verifies Allowed against its actual endpoint and body. Credentials are attached inside attempt and never included in payload logs.
2. `fieldbook_core::schema_json`: `to_json_schema(&Schema) -> JsonValue` (closed objects with `additionalProperties: false`, keys in field order) and `validate(&Schema, &JsonValue) -> Result<(), Vec<SchemaError>>`, where an unknown key, a missing required key, a wrong type, a string over `max_len` or outside `one_of`, an integer outside `min..max` and an array over `max` are each an error with a path. Goldens in `tests/fixtures/ports/model/schema/` hold the emitted JSON of three schemas (a pick, a list of ids, a nested object). The binary `adapters/schema_json.rs` only re-exports the shared functions and owns `extract_json(&str) -> Result<&str, ExtractError>`, the one place in the program that finds the JSON in a reply; `decide-port` and `pipeline-model-adapters` call the gate and do not strip a fence themselves. It accepts bare JSON (surrounding whitespace allowed) or JSON inside exactly one code fence (three backticks, optionally followed by the word `json`, and three backticks to close it), with only whitespace outside it. The slice it returns must parse as exactly one JSON value. Anything else is an `ExtractError` that names the shape: `empty`, `prose_before` (the first non-blank character is not `{`, `[` or a fence), `text_after` (one value parses and more follows), `two_fences`, `fence_not_closed` or `not_json`. The table test `extract_json_reads_these_shapes` has one row for each of: bare, fenced as `json`, fenced plain, leading prose, two fences, trailing text, empty, fence not closed; the fenced rows read the fixture `tests/fixtures/ports/model/reply-fenced.json` (a reply in one `json` fence), which is the one fenced fixture of the workspace.
3. `io/net.rs`, the part that holds nothing socket-capable. `HttpPost::post` takes `&Allowed` as its first argument, so a transport cannot send what the gate did not clear. It holds: `HttpPost`, `HttpRequest`, `Header { Plain, Secret }` (a secret header holds a `Key` and is shown as its name only), `HttpReply`, `HttpError { Connect, Timeout, Tls, TooLarge, Other }` (it never carries a header value or a query), `ScriptedHttp` (a queue of canned replies, a record of requests, a send counter) and `PanicHttp` (any send fails the test), `Avail { net_built, bridge_built, cpu_ok }` with `Avail::real()`, which reads `cfg!(feature = "net")`, `cfg!(feature = "bridge")` and `cpu_ok() -> bool` (a function that returns `true` here), so that a test can pass the values it needs. `crates/fieldbook/Cargo.toml` adds `net = []`, a feature with no crate behind it yet, and `bridge = ["net"]`, which compiles the chat listener of `chat-bridge` and adds no crate, to the `[features]` table that `policy-load` made (it holds `test-hooks = []`; write no second table), so that `cfg!` compiles without an unexpected-cfg warning. `net-stack-spike` adds `UreqHttp` to this file, puts its crates behind the feature and gives `cpu_ok` its body. `io/ai_journal.rs` implements `AiJournal` over the writer of `audit-journal`: `begin` appends `ai.begin` and returns its sequence number as the `tx`; `finish` appends `ai.call` with that `tx`; an append that fails returns the code (FB0903 before a send, FB0904 after). Each of the two opens the journal, appends one event and drops the handle, so the journal lock is held for one append and never across a model call, which can last minutes; the lock wait of `audit-journal` applies to each open, and the chain stays whole because the next open reads the last hash. `io/pace.rs` has `RealPace` over `std::thread::sleep`. `io/call_store.rs` writes `ai/calls/C-<seq>.json` and the Handoff files `handoff/H-nnnn.txt` (the pack) and `handoff/H-nnnn.toml` (the ticket: `ticket_version = 1`, exact `response_schema: Option<Schema>` encoded by the shared strict schema serializer (absent only for an unconstrained request), `pack_seq: u64` returned by the successful ai.pack append, the template, whether it is used, the complete request `labels`, sorted `context_ids` and `inputs = req.input_refs()` as `{ store, id }` tables) through the atomic helper; the call record holds the adapter, endpoint, model, template, purpose, the request's `labels` and `inputs`, the `policy` hash, both hashes, the system text, the prompt, the reply, the tokens, the attempts and the outcome. When the effective `keep_days` (the smaller of the owner's number and the row's `keep_calls_days_max`) has passed, the next write removes older records and appends one `purge` event (`what = calls`, `count`). A write that fails is a warning, never a failure of the call. A record is written only if the `state` store holds every label of the request (`labels::admit`) and the effective `keep_calls` is true (the owner's switch, and the row's `keep_calls_days_max` above zero); otherwise nothing is written and the warning names the reason and no label's title. Register `call_record` in binary `SURFACES`: drive the gate and real `put_call` writer, then inspect the stored bytes under permitted and refused label cases. The pure-core matrix continues to test view selection; it calls no binary serializer, store or journal.
4. `adapters/gate.rs`, `Guarded<A>::run`, in the stages G1 to G11 below and in no other order. G1 is the `Router`'s choice of the route (step 6), so every attempt starts again at G2 with a fresh PolicySnapshot. G2 Availability: FB0912 when the adapter needs the network and `avail.net_built` is false (`avail.bridge_built` is not read here; `chat` reads it before it opens the settings), FB0911 when `avail.cpu_ok` is false, FB0914 when the endpoint names a `key_env` that `deps.keys` reports as unset or empty (the adapter holds the same `KeySource` and reads the key inside `attempt`). G3 Egress: `egress::check(&snapshot.policy, &dest, Some(&req.labels()), None, snapshot.now, snapshot.shipped)`, where `dest` is `Dest::Model { name, base_url }` for a network route and `Dest::Handoff` for the Handoff route. This is the policy half of the decision: a Closed policy, an `unlabelled`, `marked` or undefined label (FB0901), no row, an expired row or a `base_url` that differs from the row's `url` (FB0918), a label outside the row's allow set narrowed by the owner's list (FB0901), and, for a `Model` route whose request carries a non-public label while the policy's `[audit] require_fresh_export` is on (the default), a journal that was not exported within `[audit] max_unshipped_hours` or never (FB0925). The gate does not read `[audit] require_fresh_export` itself: `egress::check` does, and with it off the same call goes on to stage G4. A denial is its code, a `refuse` event with `dest`, the request's `labels` and the closed `reason`, and the end of the run. The `Allowed` token of this step is dropped, because it was made without seeing the text. G4 Mismatch: `labels::markings_in` over `req.system()` and `req.prompt()` with the policy's `MarkingRules`, prepare the exact body with adapter.prepare, then `egress::check` again with Some(&delivery) binding the prepared bytes, target and marking result. A marking that maps to a label the request lacks is FB0902 and a `refuse` event with the reason `mismatch`. The `Allowed` token of this step is the only one that goes on: stages G6, G7 and G9 read its `dest`, `labels` and policy hash, and the adapter receives it. G5 Budget: the calls of this run below `max_calls_per_run` (FB0915), and the prompt within `caps().max_prompt_chars` (FB0907). G6 Audit: for an adapter whose `caps().network` is true, append `ai.begin` (`tx`, purpose, `dest`, `labels` and `policy` read from the token, adapter, endpoint, model, template, `prompt_sha256`, `context_ids` from req.context_refs() as store-qualified `RecordRef` values); for the Handoff adapter append `ai.pack` (`dest`, `labels` and `policy` read from the token, `prompt_sha256`, `context_ids` from req.context_refs() as store-qualified `RecordRef` values) instead, because nothing leaves the machine and no transaction waits for a reply. A failure is FB0903 and exit 3 and nothing has been sent. G7 Attempt: call the adapter with the token; an `Attempt::Pack` skips stages G8 and G9 and goes to stage G11; finish the current audit pair on every failed attempt; retry only `Transient`, at most `retries` times, after 1 s then 4 s or the `Retry-After` value up to 30 s, with no jitter, through `Pace`, and never when `stop()` is true (the loop then ends with the last error and `outcome = cancelled`); the last failure is FB0908 and the error carries a fallback offer. A `Permanent` error maps to its code and is never retried: `Auth` FB0905, `Rejected(413)` FB0907 (the endpoint says the request is too large) and every other `Rejected` and `Redirect` FB0906, `Tls` FB0910, `Truncated` FB0909 with outcome `truncated`, `TooLarge` FB0919 (a reply over the cap). G8 Validate: with a schema, find the JSON with `extract_json` (step 2 of this card), parse it and `validate` it; on failure, finish the current attempt through G9 with its `invalid` outcome and its own completed `ai.begin`/`ai.call` pair before starting a repair, and if that `ai.call` append fails, retain FB0904 and send no repair; the one permitted repair attempt then re-enters G2 through G7 with a fresh preparation, a fresh budget draw and a fresh policy snapshot, and completes its own G8 to G11. Append at most 8 fixed schema diagnostic codes and numeric schema-node indices, at most 512 Unicode scalars, never model-controlled paths or values; the full repaired request must fit the same limit, else FB0907; a second invalid result is FB0909 with outcome `invalid`. G9 Audit: append `ai.call` for a network adapter (`outcome` of `ok`, `failed`, `invalid`, `truncated` or `cancelled`, the code, `attempts`, `output_sha256`, the token counts); if that fails the output is dropped and the error is FB0904. G10 Keep: `CallStore::put_call` if the effective `keep_calls` is true and `state` holds every label of the request (step 3 of this card gives the rule); otherwise a warning, and the call goes on. G11 Return the `Answer`, or write the pack and ticket and return `Deferred`.
5. `Guarded::resume(ticket, pasted)`: the ticket must exist and be unused, and the pasted text must not be empty, else FB0916; a reply over `max_reply_bytes` is FB0919. It appends `ai.paste` with the pack's sequence number, the `labels` of the ticket and `output_sha256` (a Handoff round trip is `ai.pack` then `ai.paste`; it writes no `ai.begin` and no `ai.call`, so FB0803 never sees a pack that was not used), validates exactly as stage G8 does against the response_schema retained in that ticket (never today’s template), marks the ticket used, and returns an `Answer` whose provenance records the adapter and the model as `unrecorded` unless the caller passes a short label. A reply is checked, never trusted. `Guarded::preview(req)` builds a `SendPreview` (route, adapter, `labels`, the `egress::check` verdict (allowed, or the code and reason, and which side cut each label), characters, items, `Scan`, key state, budget left, `audited` (true when the journal can take the record this route writes before any byte leaves: `ai.begin` for a model route, `ai.pack` for Handoff)) without a network call and without a journal event.
6. `adapters/router.rs`, `Router`: `from_settings(settings, rows, factories, deps, avail)` builds one `Guarded<Box<dyn ModelAdapter>>` per configured endpoint name and for `handoff`, using the `FACTORIES` table of `adapters/mod.rs` (a factory gets `&Deps` for construction, but operation-specific banners come only through PreparationContext; the table is empty now; an endpoint whose adapter has no factory is FB0900 at build time). `run` takes the same `stop`, chooses the route by coverage, because labels have no order. The candidates are the one name after `--via` if it is given, and otherwise the entries of `[model] order` (with no `order`, `handoff` alone); the route is the first candidate whose effective allow set covers every label of the request, using the shared egress decision, so the Router has no comparison of its own. Preserve FB0413 and FB0925 before reducing that decision to a coverage boolean; an otherwise covering model route whose required export is missing or stale terminates plan/run with FB0925, no adapter attempt and no Handoff pack. Ordinary label noncoverage may still skip a candidate. If no candidate covers the request, the error is FB0901 with a `refuse` event carrying FB0901, the known request labels and reason `label`, with no invented destination; candidate names appear only in the command diagnostic; with `--via`, the error is the code that `egress::check` gives for that one candidate (FB0901, FB0918 or FB0413). `Router::plan(via, &base)` applies the same test to a set of labels without a request and returns the `Plan { name, dest }`, and `run` calls the same function, so the two cannot disagree. It passes `stop` through to `Guarded::run`. After a failure of availability, and only then, it asks the `handoff` route for a pack of the same request if `handoff` is in `order` and its row covers the request's labels; it adds the ticket to the error and exits with the endpoint's code. Leaving `handoff` out of `order` turns the fallback off, and a request that the Handoff row does not cover gets the endpoint's error alone and no pack. Once a candidate is chosen, a policy refusal (FB0901, FB0902, FB0907, FB0915, FB0918 or FB0925) ends the request: it never moves to the next candidate and never falls back. `describe` returns one `RouteInfo` per endpoint name and for `handoff`, with the key state, the state of the policy row (found, expired or missing), the effective allow set, which side cut each label (`EffectivePolicy::explain`) and no secret.
7. `audit.rs`: `audit verify` reports an `ai.begin` with no `ai.call` of the same `tx` as FB0803 (a warning, like the unfinished write); a `cancelled` call counts as finished. Add the fixture `state-ai-gate/` (a journal with one finished pair and one lone begin, written by the real writer under a fixed clock, and a `settings.toml` with an `order` and an endpoint that names a scripted adapter. The policy for it is `tests/fixtures/policy/gate.toml`, with the `model` row for that endpoint; it sits outside the state folder, because FB0414 refuses a policy inside one); the test `audit_reports_a_begin_with_no_call` is in `tests/audit.rs` beside the existing cases.
8. `adapters/doubles.rs`, compiled into the library and used only by tests: `ScriptedModel` (a queue of `Result<Attempt, AttemptError>`, a record of the requests it received and a count of attempts), `PanicModel` (its `attempt` panics), `ScriptedPace` (records the sleeps and does not sleep), `MemJournal`, `FaultyJournal` (fails the Nth append, begin or finish) and `MemCalls`. The drift check of `ai-kernel` skips this file. It also holds `test_policy(text, owner) -> EffectivePolicy`, which parses an inline policy text with `Policy::parse` and applies the given `OwnerSettings`; a test gets an `Allowed` only by calling `egress::check` over such a policy, because nothing else builds one.
9. `tests/model_contract.rs`: suite M as a function `suite_m(make: &dyn Fn() -> Box<dyn ModelAdapter>)` that each adapter card calls from its own `contract_model_<id>` test. It requires that the same request gives the same prompt hash and, for a deterministic adapter, the same reply; that random replies never panic the gate and always end in a reply or a coded error (the check inside `suite_m` is named `random_and_mutated_bytes_never_panic`: 200 byte strings from `Rng::new(1)` of `tests/support/rng.rs`, included in `tests/model_contract.rs` with `#[path = "../../../tests/support/rng.rs"] mod rng;` and written nowhere else (`one_rng_exists`), and the valid reply of `requests.toml` with each of its bytes once flipped and once deleted, each given to the gate as the adapter's reply); that a refusal names the adapter's id; and that an adapter is never handed the journal or the clock (it receives a `KeySource` when it is built and reads only its endpoint's `key_env`); the only things it gets from the gate besides the request are the `Allowed` token and its `Route`. The suite runs here on `ScriptedModel`. The scripted requests and the expected `ai.begin` and `ai.call` field values are in `tests/fixtures/ports/model/` (`requests.toml`, `records.toml`).
