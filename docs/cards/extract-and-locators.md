# extract-and-locators

- **Runs where:** home, CI Linux
- **Schema impact:** none
- **Review:** auto

## Outcome

`cargo xtask extract <version-id>` writes `corpus/sources/text/<version-id>/` with one text file per page and an `extraction.toml` that holds the page hashes, the pages with little or no text and the `[locators]` it recognises. `fieldbook check` raises FB0212 when an extraction no longer matches its original, and the warning FB0223 when a consequential claim rests on a version that is metadata-only or has such pages.

## Why

- Methods, file names, the keys of `extraction.toml`, `[locators]`, the section-anchor rule and the FB0212 cases are [Extraction](../reference/corpus-format.md#extraction). FB0212 and FB0223 are in [02: registers and sources](../reference/corpus-format.md#02-registers-and-sources). A file that exists is not evidence that the text was read: an image-only page extracts to an empty file whose hash passes, so `thin_pages` names it. For the public Corpus, extraction runs at home only and its output is committed; CI checks hashes and never re-extracts. For a company item the output is a file of the company store beside its original and carries the original's labels (the union rule of [ADR 0004](../decisions/0004-company-boundary.md#2-labels)); an approved extractor runs inside `fieldbook` on the company device, never through `xtask` and never in a repository (`r2-org-intake`).
- `xtask` is the only crate that starts processes ([AD-05](../decisions/0001-foundation.md#ad-05-crate-layout-and-enforcement)). The known-bad rules are in the `check-known-bad` card's harness (`tests/known-bad/`).
- Control ED-03 (an extraction holds the original's hash and per-page hashes) is in the [control register](../controls.md).
- The poppler pin (`[poppler] version = "26.10.0"` in `.config/tools.toml`) and its row in [dependencies.md](../reference/dependencies.md) already exist; this card reads the pin through `xtask/src/tools.rs` and does not change either file. A change of the pinned version is a separate dependency change.
- Design: the [MAP.md](../design/MAP.md#routes-and-components) row "Source drawer", for the `[locators]` data that LocatorView lists. [HANDOFF.md](../design/HANDOFF.md) [§5 Components](../design/HANDOFF.md#5-components) (LocatorView). No template or style change: the `s/` page shows the text and anchors in `quote-match-and-anchors`. No token group.

- Docs to update: `AGENTS.md` (Commands: `cargo xtask extract`, at home, needs `pdftotext` for PDFs). `errors.md` is unchanged: FB0212 and FB0223 are already catalogued.

## Steps

1. `fieldbook-core/src/extraction.rs`: the typed `ExtractionToml`, read with error positions by `ExtractionToml::parse(text)`, and `section_anchor(label)`, the anchor rule of the reference. Also the append-only const `METHODS` in `extraction/methods.rs` ([Adding an extraction method](README.md#adding-an-extraction-method)), `Method { name, types, locator, keys, extractor, fixture }`, with the rows `pdftotext-layout`, `html-strip`, `plain` and `supplied`; `ExtractionMethod` is the name type that reads from it. The `fixture` of `plain` is the original of step 4, of `html-strip` the new `tests/fixtures/extract/html-strip/` (a small synthetic HTML file and its expected output), and of `pdftotext-layout` `xtask/tests/fixtures/synthetic-two-pages.pdf`. `csv-rows` is a later row, appended by `extract-csv-rows`. `supplied` is produced by the home fallback in step 12; the laptop adapter later reuses it. FB0223 carries its evidence rule. Also the `Extractor` trait, `trait Extractor { fn id(&self) -> &'static str; fn extract(&self, bytes: &[u8]) -> Result<Extraction, ExtractError>; }`, with `enum ExtractError { NotText, TooLarge { bytes: u64 }, ToolMissing(String), ToolFailed { status: i32 } }`, `struct Extraction { method: &'static str, pages: Vec<PageText> }` and `struct PageText { number: u32, text: String }`, and the two extractors that start no process, `Plain` and `HtmlStrip`. `NotText` is a byte string that is not valid UTF-8 (or an HTML file with no text at all is not an error: it is one thin page), and `TooLarge` is an original over `MAX_ORIGINAL_BYTES`, a const of `extraction.rs` with the value `33_554_432` (32 MiB; an original of exactly that size is read). `extraction.rs` also holds `pub const SELECT_TYPES: &[&str]`, the extensions that `extraction::select` looks up: `txt`, `md`, `markdown`, `html`, `htm`, `xhtml` and `svg`.
2. `check/extraction.rs`: a pass that, for each version with a folder under `sources/text/`, compares the files, hashes, `page_count`, `original_sha256` and `thin_pages` (it must equal the list computed from the page files) with the tree and the row, and checks that no two labels share an anchor. Every failure is one FB0212 diagnostic at the file it concerns. Independently iterate every consequential claim for FB0223, a warning at its `version` cell: a consequential claim whose version row has a `location` that starts `metadata-only: `, or whose extraction lists a thin page or uses `supplied`. Only a version without an extraction that is not metadata-only raises nothing here; missing folders do not bypass the metadata-only warning. Register the pass in `check/mod.rs`.
3. `extract.rs`: `extraction::select(ext, head)` returns a core extractor for plain text and HTML-like files (the extensions of `SELECT_TYPES`, and no other); `extract.rs` adds `PdftotextLayout`, the only `Extractor` that starts a process. The method string is `Extractor::id()`'s method, never a literal in `extract.rs`. PDF runs `pdftotext -layout` per page and records the dotted version in the output of `pdftotext -v` (found with `Version::find_in` of `tools.rs`) as `tool_version`; a missing `pdftotext` is `ExtractError::ToolMissing(name)` and `extract` exits 3 with its name; `NotText`, `TooLarge` and `ToolFailed { status }` make `extract` print one line that names the original and the cause, write no folder for that original, go on with the next one and exit 1 at the end. The size is checked first: an original over `MAX_ORIGINAL_BYTES` is `TooLarge` before any extractor runs or any process starts, so nothing is written for it. `PdftotextLayout::with_program(name)` builds the extractor with another program name, so that a test needs no poppler to reach `ToolMissing` or `ToolFailed`. A `tool_version` that differs from the pin in `.config/tools.toml` is a warning and not a stop: `extract` prints one line on standard error that names both versions, extracts anyway, and records the version used as `tool_version` in the extraction record, so the difference stays visible, and `check` still fails when a quote no longer matches its page text (the pin is `[poppler] version` in `.config/tools.toml`, read with `Pins::get("poppler", "version")`; this card changes neither the pin nor its row in `dependencies.md`, and has `cargo xtask doctor` report a missing or older `pdftotext` as a warning on a local run, never in CI). HTML, XHTML and SVG use `HtmlStrip` from core, and plain text uses `Plain`; `extract.rs` holds no tag stripper. Write `thin_pages` unconditionally, as the ascending integer numbers of the pages the reference calls thin, and as `[]` when there are none, and write `[locators]` for the labels it recognises and keep every label already present.
4. Fixture: add a synthetic plain-text original under `sources/public/` for one existing version row, long enough that no page is thin, set that row's `sha256` and `location`, and commit the output of `cargo xtask extract` for it. The fixture stays strict clean.
5. Known-bad: move FB0212 from `pending.toml` to a `cases.toml` case that changes one byte in the fixture's `p0001.txt`. Move FB0223 as well, with a case that lists `thin_pages = [1]` in the fixture's `extraction.toml` and `also = ["FB0212"]`. If a consequential fixture claim rests on a metadata-only version, change the fixture, not the rule.
6. Tests, in `mod tests` of `xtask/src/extract.rs` (`xtask` is a binary crate, so a test of one of its functions is in the module it tests; each calls the function behind `cargo xtask extract` on a temporary folder): `plain_text_is_copied` (and its `extraction.toml` holds `thin_pages = []` for text that is long enough, so the empty list is always written and pinned), `html_is_stripped`, `rerun_keeps_hand_locators`, `same_input_same_output`, `not_text_is_refused` (bytes that are not valid UTF-8 in a `.txt` original: `ExtractError::NotText`, no folder written, exit 1), `too_large_is_refused` (a `.txt` original of `33_554_433` bytes: `ExtractError::TooLarge`, no folder written, exit 1; one of exactly `33_554_432` bytes is read), `a_missing_tool_is_exit_3` and `a_failing_tool_names_the_status` (`PdftotextLayout::with_program` with a program that does not exist gives `ToolMissing`, and with one that exits 1 gives `ToolFailed { status: 1 }`), and `html_with_no_text_is_thin` (an HTML original with no text, written by the test: one thin page; it runs without `pdftotext`) and `image_only_page_is_listed` (a PDF whose second page holds no text, `synthetic-blank-page.pdf`; it needs `pdftotext` and is `#[ignore]` like `pdf_gives_one_file_per_page`); `pdf_gives_one_file_per_page` (`#[ignore]`, needs `pdftotext`): extract a temporary copy of `synthetic-two-pages.pdf` as a stored original; the version folder must hold `p0001.txt` and `p0002.txt`, and its `extraction.toml` must have `tool` `pdftotext`, `method` `pdftotext-layout` and a `tool_version` equal to the dotted version in the output of `pdftotext -v`; the shared `extractor_contract` from repository-root `tests/support/extractor_suite.rs`, run through local wrappers over `Plain`, `HtmlStrip` and `PdftotextLayout`, which the registry test of `ai-kernel` runs over every extractor in `ADAPTERS`: the same input gives the same output; adapter-specific cases declare input and expected outcome: Plain/HtmlStrip give one thin page for empty input and NotText for invalid UTF-8; empty or malformed PDF bytes give ToolFailed, exit 1 and no output folder, while the valid blank-page PDF gives a thin page; no panic on 1 MB of bytes from `Rng::new(1)` (the PDF variant is `#[ignore]` like the other poppler tests; `extract.rs` declares the generator at file level with `#[cfg(test)]` on the line above `#[path = "../../tests/support/rng.rs"] mod rng;`, so that the normal build does not compile it, and `mod tests` uses it as `super::rng`); in `xtask`, `tools::the_poppler_pin_is_readable`, `tools::a_differing_version_is_a_warning` (the pin check returns a warning that names both versions and never an error) and `pdf_extracts_when_the_version_differs` (`#[ignore]` like the other poppler tests: with the pin set to `0.0.0` in a temporary `tools.toml`, `extract` exits 0, prints the warning on standard error and records the installed version); in `fieldbook-core`, `methods_only_grow` (each line of `tests/golden/extract/methods.txt` is a row of `METHODS`, unchanged), `extraction::` tests for the anchor rule, for each FB0212 case, for a stale `thin_pages`, and for FB0223 (a thin page, a metadata-only version, a non-consequential claim that raises nothing, and a version with no extraction that is not metadata-only and raises nothing). Name the tests `metadata_only_without_extraction_warns` and `ordinary_version_without_extraction_does_not_warn`.
7. Two test files in `fieldbook-core`. `tests/extract_types.rs` has `text_types_equal_the_extractor_list`: `add::TEXT_TYPES` and `extraction::SELECT_TYPES` hold the same entries; `extract-csv-rows` and `extract-xlsx-sheets` append to both lists in their own pull requests. `tests/extraction_no_panic.rs` has `parser_never_panics_on_200_seeded_inputs`: it includes the generator with `#[path = "../../../tests/support/rng.rs"] mod rng;`, builds 200 byte strings of length 0 to 128 from `Rng::new(1)`, and takes a valid `extraction.toml` (every key of the reference, `thin_pages` and `[locators]` included) with each of its bytes once flipped and once deleted. Each goes through `String::from_utf8_lossy` into `ExtractionToml::parse`; the result is a value or a typed error with a position, and nothing panics. In the same file, `html_strip_never_panics_on_seeded_inputs` feeds HtmlStrip 200 seeded byte strings plus single-byte flips/deletions of valid HTML with quoted attributes and multibyte text; extraction returns a value or ExtractError without a panic.

8. `thin_pages_uses_page_numbers` checks ascending integers and `[]`; `thin_page_stems_are_refused` rejects strings such as `p0001`. The known-bad integer case must produce both FB0223 and FB0212. `too_large_is_refused` independently asserts `MAX_ORIGINAL_BYTES == 33_554_432` and builds valid text originals of exactly 33,554,432 and 33,554,433 bytes. The former extracts; the latter returns `TooLarge`, exit 1 and no output folder. Raising the constant by one must fail.

9. Use the single reusable `extractor_contract` in repository-root `tests/support/extractor_suite.rs`, included with `#[path]` from each target. Adapter constructors and wrappers stay in their own target; `PdftotextLayout` and its ignored process wrapper stay in `xtask`. Keep no copy in a binary test module. Any changes to the suite signature or empty-input cases change this shared file and all wrappers together. Run both the `xtask` wrapper and binary integration wrapper to prove reuse without an `xtask` dependency.

10. Method growth is additive without a format amendment: old row meanings are immutable, and method-specific keys use the registered key schema. The common parser preserves unsupported method metadata as unavailable; known methods still reject unknown keys. Tests append a synthetic method and locator, reject mutation of an old row, round-trip unsupported metadata and ensure no unavailable locator verifies a claim. Reserved structured-path and email-part rows stay Later until their resolver card supplies these tests.

11. Reserve optional `[method_data]` in the common extraction envelope for future method-specific keys; keep every existing root key unchanged. `ExtractionToml` dispatches validation to the registered method schema. Unsupported methods retain their metadata for round trip but yield unavailable facts; no resolver can certify them. The shared suite accepts the method validator as an argument and declares its RNG include relative to `tests/support`, rather than relying on a caller’s private test module.

12. Provide the home fallback `cargo xtask extract --source VERSION --text FILE` for any stored original type. It reads explicitly supplied UTF-8 text, applies the existing size and text rules, keeps the original byte-exact, and writes method `supplied` with original/text hashes and the normal thin-page facts. It performs no source admission, starts no converter and never marks a claim verified. Tests cover xls, XML, JSON, YAML, text/scanned PDF, eml/msg body and attachments, doc/docx, txt/md using synthetic original bytes; each retains its original hash and raises the supplied-evidence warning where applicable. A changed-original plant must fail. Laptop `Supplied` later reuses this format and validation.

13. The shared pure helper `extraction::supplied_text(bytes: &[u8]) -> Result<Extraction, ExtractError>` drops a leading UTF-8 BOM, refuses non-UTF-8, normalizes CRLF/CR to LF and splits only on lines equal to `[page break]`, preserving empty pages. It uses Plain’s size, page construction and thin-page rules with method/tool `supplied` and tool version `1`. The home fallback scans supplied text under the existing public Corpus scan rules before writing; a marking or other nonpublic input refuses without output. Test normalization, empty parts and seeded/mutated bytes here. The later `Supplied` adapter delegates to this helper rather than duplicating it.

14. The shared suite takes named empty/malformed vectors and expected typed outcomes per adapter, keeping determinism and no-panic checks common. `extractor_refusals_match_adapter_contract` runs the text cases; the PDF wrapper is ignored in CI and checks its real subprocess result at home. Later staged, CSV and workbook wrappers supply Missing("staging folder"), Missing("header row") and NotWorkbook respectively instead of inheriting a text-only assertion.

## Acceptance

```sh
cargo nextest run --locked -p xtask extract:: tools::
cargo nextest run --locked -p fieldbook-core extraction::
cargo nextest run --locked -p fieldbook-core --test extract_types --test extraction_no_panic
cargo nextest run --locked -p fieldbook --test known_bad
(cd tests/fixtures/corpus-mini && cargo run -q --locked -p fieldbook -- check --strict --today "$(cat TODAY)"); echo "exit $?"
cargo nextest run --locked -p xtask extract:: --run-ignored only
just check
```

Expected: the tests pass; `check` on the fixture prints `clean` and `exit 0`, so it holds no FB0223 warning; the ignored PDF test passes at home, where `pdftotext` is installed (it is not run in CI, and no weekly job runs it); `just check` exits 0.

## Negative control

Copy the fixture to a temporary folder, append one byte to its `corpus/sources/text/*/p0001.txt`, and run `check --strict` there. It must exit 1 with an FB0212 line naming that file. Remove the copy. Then, in a second copy, replace `p0001.txt` with a few characters and update its hash in `extraction.toml` and its `thin_pages`: `check` must print a `warning[FB0223]` line for a consequential claim on that version and no FB0212. Remove the copy. Then rename one method in `METHODS`: `methods_only_grow` must fail. Restore it. Then make a differing poppler version a failure (exit 3) in place of a warning: `tools::a_differing_version_is_a_warning` must fail. Restore it. Then add `csv` to `SELECT_TYPES` alone: `text_types_equal_the_extractor_list` must fail. Restore it. Then raise `MAX_ORIGINAL_BYTES` by one: `too_large_is_refused` must fail. Restore it. Then, at home, make `PdftotextLayout` record `tool_version = "0.0.0"`: `cargo nextest run --locked -p xtask extract:: --run-ignored only` must fail in `pdf_gives_one_file_per_page`. Restore it.

Run FB0223 only inside the extraction-folder loop: `metadata_only_without_extraction_warns` must fail. Restore it.

Make HtmlStrip assume a closing tag delimiter exists: `html_strip_never_panics_on_seeded_inputs` must fail. Restore it.

Treat an invalid PDF as a successful thin page, or a text UTF-8 refusal as ToolFailed: the matching shared extractor case must fail. Restore each.

## Rollback

Revert the merge commit. Extractions already committed stay as files that nothing checks; FB0212 returns to `pending.toml`.

## BLOCKED

`pdftotext` is not installed at home and cannot be installed: set the item to Blocked with a `BLOCKED:` comment that says so, and stop. Also stop if the fixture cannot stay strict clean with an extraction (for example a check that does not yet know the `sources/text/` folder).
