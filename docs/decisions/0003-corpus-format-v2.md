# ADR 0003 Corpus format v2

Status: Proposed. The owner accepts it at the format gate. Until then nothing in this record is in force, and no reference document is edited to match it.

## Context

[ADR 0002](0002-corpus-format-v1.md) froze version 1 with nine page types and said that `note` "joins at Day 30 and makes the version 2" (AD-09). Its reopen trigger fires: content needs something the format cannot say, a saved assistant answer ("a saved answer is a note", [HANDOFF.md](../design/HANDOFF.md) line 108). The reference already describes part of the type ([Object types beyond v1](../reference/corpus-format.md#object-types-beyond-v1), `origin` and the FB0708 and FB0709 rows), the controls HG-02 and HG-06 and the card `handoff-new-note` rely on it, and the texts disagree in places (see Reconciled). This record decides the type and the version in one place, so that the card builds what the owner accepted.

**What it changes.** AD-09 of ADR 0002 (a tenth page type and the version 2); the Day-30 `new note` row of AD-17 and the company-store rows of ADR 0001 that put `new note` into the company store (Reconciled); and the retirement table and the FB0105, FB0108, FB0708 and FB0709 rows of the reference. AD-10 is not changed: no id form is tightened (see Id and place). Nothing else in ADR 0001, 0002 or 0004 is decided here.

## Decision

**A note is the saved text of an assistant answer, kept in the repository Corpus as an unreviewed draft. It is never a source and never evidence.** Everything below follows from that sentence.

| Topic | Decision |
|---|---|
| What it is | One page with `type = "note"` whose body is an AI-drafted answer, with the question it answered, the ids of the context it was given and a fingerprint of that context. Provenance is `origin = "ai_drafted"`, the only value in version 2. A note written by hand is an ordinary page, not a note; a later `origin` value is an additive vocabulary change. |
| What it is not | Not a source, a claim, a conflict, an answer in a register or a curriculum page. It has no parts and no `Sources` part, and no stage or reading path. `stage = 8` and `readiness = "PUBLIC-NOW"` are inert fixed values that keep the page schema one shape; any other value is FB0709. A reader leaves notes out of every stage and prerequisite list. Its computed `review_by` and FB0117 do not apply: a note carries `reviewed` instead. |
| Never supports a claim | A claim row whose `source_id` is a note id is FB0204. A page body that cites `[@<area>-note-<nnn>]` is FB0300 (the form is answer-only, [corpus-format.md](../reference/corpus-format.md#syntax-at-a-glance)). No page names a note in `prereq`, `links`, `supersedes` or `superseded_by` (FB0710). Nothing a note says raises a status, fills a cell or puts a figure on a page. Reviewing it changes none of this. |
| Cited in an answer | Only in the tolerant, answer-only form. `cite-check` gives a note `weak` whenever it is visible, reviewed or not, and keeps its normal precedence: absent is `broken`, outside a supplied context `outside_context`. The form names a note only: if the id belongs to a page of another type, it reads as absent. |
| Id and place | A note's id is `<area>-note-<nnn>`, three digits from 001 to 999, the next number after the highest ever used in that area's note series, withdrawn notes included (the allocation rule of Identifiers). A note with another id form is FB0105. The file is `corpus/pages/<area-slug>/<subarea>/<id>.md` in the repository Corpus only. The form is not reserved: `cmp-note-001` is a valid version 1 id for a page of any type, and keeping it so leaves AD-10 and "nothing valid in version 1 changes meaning" true. The allocator skips a number a page already holds. A company store holds no note page; see Reconciled for what `new note` does there. |
| Front matter | The page fields `id`, `title`, `area`, `subarea`, `type`, `stage`, `readiness`, `status`, `as_of` and `handling`, then `origin`, `reviewed`, `question`, `context_fingerprint` and `inputs = [{ store, id }]`. All five note fields are required and belong to no other type (FB0102 elsewhere). `terms`, `prereq`, `questions`, `conflicts`, `links`, `volatility`, `supersedes` and `superseded_by` are not allowed on a note. `handling` is `["public"]` (FB0410). `inputs` is sorted by store and id, may be empty only for a confirmed public answer with no context, and in the repository Corpus every `store` is `corpus` (another value is FB0709). A nonpublic or unresolved input is refused at the verb with FB0410 and never relabelled. A missing or malformed note field, a forbidden field, or a `status` outside the two values below is FB0709. |
| Body | Free text after the front matter, with no required parts: FB0134 and the part check of FB0130 skip it, but a `#` heading and a heading deeper than `###` are still FB0130. Every other body rule holds: scans FB0400 to FB0403, no raw HTML, no outside link, canonical citations of claims and source versions, each citation resolving. `as_of` is not later than the oldest claim cited (FB0118, strict). |
| Status and review | `status` is `draft` or `withdrawn` (below). The page words `reviewed` and `stable` are refused: they would say what `reviewed` says, or claim an acceptance a note cannot have. `reviewed` is `false` when written. The label is "AI-drafted · unreviewed" while false and "AI-drafted · reviewed" after (`ai_note_label`, already in `strings` under the other fixed wording). A person, the owner or the lead, sets `reviewed = true`; the verb, an agent and `queue accept` never do. `guard-statuses` fails a raise under an agent commit, as for `verification`, and fails an edit of the body, question, `inputs` or fingerprint of a reviewed note that does not set `reviewed = false` in the same commit, as it does for claim evidence (GS-02). `guard-statuses` also fails an agent commit that moves a note's `status` from `withdrawn` to `draft`, so a person's review cannot be restored by an agent. |
| Withdrawal | A note is never deleted once it is on `main`, and its number is never issued again. A wrong or obsolete note is withdrawn: its `status` becomes `withdrawn` and the file stays, as for a source version (`lifecycle`) or a question (`status`). A withdrawn note is shown with the word, `cite-check` gives it `weak` like any visible note, stays in the allocator's count, and is never put in a context pack, named or not. It has no replacement link: `supersedes` and `superseded_by` stay refused, and a replacement is a new note. Any commit may withdraw; the reverse is a new note. A note that is not yet on `main` may be deleted by hand, as "Never reused, never renamed" in Identifiers allows before an edition contains an id (ADR 0002 implies the same window); once it is on `main` the hosted site may have shown it, so it is withdrawn instead. |
| `schema_version = 2` | Version 2 is version 1 plus the `note` page type, its five fields, the `withdrawn` note status, FB0710 and the reading of `type = "note"`. It is an additive change ([Scope and versioning](../reference/corpus-format.md#scope-and-versioning)): nothing valid in version 1 changes meaning, and no existing byte is rewritten except the one stamp. A Corpus needs no note to be at version 2. |
| Reading and migrating | A tool built for version 2 reads version 1 and version 2 (`SCHEMA_VERSION_MAX = 2`). The first tool for version 2 is the one released as `v0.2.0` with the Day-30 release (README release table); the `0.2.0` row of `version.rs` is that tool. Every v1 page, register, original and citation stays valid unchanged, and a v1 Corpus needs no migration to be read, searched, built or checked. The Corpus moves to 2 only by the one-off stamp, `cargo xtask migrate-1-to-2`, which changes `schema_version` in `corpus/corpus.toml` and nothing else, and runs once at home before the first note is saved; the shipped `fieldbook migrate` from R2 inherits the step. A company store is stamped and migrated on its own; its stamp never has to equal the Corpus's. A tool built only for version 1 refuses a version 2 Corpus (FB0100). |
| `check` on mixed or older input | The version is one stamp per Corpus; no file carries its own. A `note` page under `schema_version = 1` is FB0108, and `new note` there writes nothing and tells the person to run `cargo xtask migrate-1-to-2`, never to edit the stamp by hand. A version 2 Corpus with no notes is clean. A stamp of `0` or above the tool's maximum is FB0100 as today. |
| Codes | **FB0710** (error, reserved) has two cases: a `note` page in a company store tree, and a note named in `prereq`, `links`, `supersedes` or `superseded_by` of another page. This record changes four existing codes and no other: FB0105 gains the case of a note whose id is not `<area>-note-<nnn>` (today's page-id pattern accepts such an id); FB0108 is gated by the stamp (today it fires for any unknown `type`); FB0709 is widened to the five note fields, the forbidden fields, `stage`, `readiness`, `status` and the `store` of an input; FB0708 is narrowed to the repository Corpus. `withdrawn` on a page of any other type stays FB0104. |
| Search | The index and its ranking are unchanged: a note is a page unit with section units (`search.md` already indexes every type), its `status` shown is `draft` or `withdrawn`, and notes count toward the edition index budget of ADR 0006. The result chip for a note is a reader change that the interface lane and the card `handoff-new-note` (the render, step 7) own. |
| Edition | A note ships as a page, with its label, question and body, and in no stage list. `schema_version` is copied from the Corpus and `min_tool_version` from `version.rs`. |
| Context packs | HG-02 stands: a note is left out unless the question names its id or `--include notes` is given. When included it is marked as an AI-drafted note, and it brings no closure of its own, so the claims it cites do not enter the pack through it. |
| Cite-check | A note is a `weak` fact of kind `note` (HG-05, FB0704 "the cited text is a note"). A note's own citations are checked as in any page and count for no claim's use. |
| Labels, boundary | A Corpus note is public: confirmed public at the verb or at `queue accept`, with every input public. No label table, policy or egress rule changes ([ADR 0004](0004-company-boundary.md): a note does not become public by citing public claims). |
| Left out | A hand-written note; a note page in a company store; a note as a source, a claim or a status input; threads (still session-only); a replacement link between notes; any `origin` other than `ai_drafted`; a ranking, filter or query form for notes; the `inputs` field on other types. |

## Consequences

**What this gives.** The saved answer has one defined home, one id family and one set of refusals, and `handoff-new-note`, `review-queue`, `handoff-cite-check` and `assistant-page` can each be built against the same text.

**What it costs.** It follows "Adding a page type" in [docs/cards/README.md](../cards/README.md#adding-a-page-type): a row in the page types table, `PageType::Note` (the enum and its count go from 9 to 10) with its `template()` arm, the template and its fixture copy, and a render with a golden; the part rules are skipped, so FB0134 gains no rule. Beyond the recipe: `SCHEMA_VERSION_MAX` and the `0.2.0` row in `version.rs` (its test asserts 1), the schema-gated FB0108, the note check pass (FB0709, FB0710), the `guard-statuses` rules, the one-off `migrate-1-to-2` with a fixture tree, and the context class. Migration cost is one stamp line; no rewrite and no re-verification. Rollback: before a note exists, revert the stamp. Once a note file exists on `main` the stamp stays, because a note page under schema 1 is FB0108; withdraw the notes. A withdrawn note keeps its file and its number.

**Documents and cards that change when this is accepted.**
- Reference: [corpus-format.md](../reference/corpus-format.md) (Scope and versioning; Page types and front matter with `inputs`; Layout templates; Identifiers: the note id, the allocation rule and the retirement table, which gains the row "Note: `status` becomes `withdrawn`; the file stays"; "Reports never enter the Corpus" at line 534, which names a note; the page `status` vocabulary; FB0105, FB0108, FB0708, FB0709 and FB0710; Object types beyond v1; the Verb map); [errors.md](../reference/errors.md) and [cli.md](../reference/cli.md) by `cargo xtask docs`; [search.md](../reference/search.md) (the line "arrives at Day 30"). `citation-check.md` does not state the weak predicate and is not changed.

- Design: [HANDOFF.md](../design/HANDOFF.md) (the laptop note lines 1250 and 1251) and [MAP.md](../design/MAP.md) (the `note` render and stage lists).
- Cards: `handoff-new-note` (the fields and `inputs`, FB0710, the `draft`/`withdrawn` status rule, the guard, the company-store refusal, the context marking and the no-closure rule of step 9, `cargo xtask migrate-1-to-2` in the schema-1 message of step 1, the allocator over withdrawn notes), `handoff-context` ("Company notes in a pack" and the `Include` struct, which gains `notes`), `review-queue` (the `note` row), `handoff-cite-check`, `assistant-page`, `model-handoff-ask`, `transfer-and-windows-drill`, `r2-migrate` and `r2-records` (the company record that holds a saved answer). ## Reconciled

| Where | Says | Against | Decision |
|---|---|---|---|
| `corpus-format.md` 1437 (FB0708) | In a company store a note takes the store's default labels | `handoff-new-note.md` 31 (a company-store note is a record, never reaches the Corpus); [HANDOFF.md](../design/HANDOFF.md) 1250 ("Laptop notes are ORG", an old label word) | No note page in a company store; FB0708 is for the repository Corpus; the record uses ADR 0004 labels. |
| `0001-foundation.md` 115, 235, 464, 465; `HANDOFF.md` 1251; `handoff-context.md` 30 | `new note` writes the owner's company notes into the company store from R2 | This record: no `note` page in a company store (FB0710) | On a company-store machine `new note` saves a record of the store's note type once `r2-records` allows it, is refused until then, and never writes a `note` page. "Company notes" in those texts means such records. |
| `corpus-format.md` 387 (the `type` row), 401 to 404 (note fields) and 1438 | Four note fields | `corpus-format.md` 1639 and `handoff-new-note.md` 57 (`inputs` required); `handoff-new-note.md` 43 and 45 (`NoteMeta` and FB0709 without `inputs`) | Five fields; FB0709 covers all. |
| `0001-foundation.md` 481 (and 167, where the verb has no flags at all) | `new note --ai-drafted --area <a> --from <file>` | `corpus-format.md` 207 and `handoff-new-note.md` 9 (`--confirm-public` required) | `--confirm-public` is required; ADR 0001 is corrected at acceptance. |
| `handoff-new-note.md` 42 | `check` refuses a note under schema 1 with FB0108 | `check/pages.rs` 81 (FB0108 for any unknown `type` regardless of schema) | FB0108 is gated by the stamp. |
| `corpus-format.md` 390 (page `status`: `draft`, `reviewed`, `stable`) | A page's maturity | `handoff-new-note.md` 43 (`status = "draft"` and a `reviewed` boolean) | Two words for one fact are refused: a note's `status` is `draft` or `withdrawn`. |
| `corpus-format.md` 516 to 532 (ids never reused, rows never deleted) | Retirement by `superseded_by` or a Change note | This record's no `supersedes`, no Change note and a rollback that deleted notes | Withdrawal by `status`; no deletion once the note is on `main` (Withdrawal). |

Chosen without a settled source in the repository (the owner confirms these by accepting this record):
- Notes carry no optional page fields, no `review_by` and no FB0117, no stage or reading-path role; fixed `stage` and `readiness` checked by FB0709.
- FB0710 and its two cases; the 999-per-area limit; the id form not reserved.
- `status` of `draft` or `withdrawn`, the withdrawal rule, `reviewed` reset on edit and the `guard-statuses` rules.
- A version 2 Corpus may hold no note, and a company store's stamp is independent.
- A note brings no closure into a pack, a withdrawn note never enters one, and a note's citations count for no claim's use.
- `--confirm-public` on `new note` is a person's typed public act, as for home `add` and `new`; an agent never runs it, and `reviewed` stays a person's.
- `guard-statuses` fails an agent commit that moves a note's `status` from `withdrawn` to `draft`.

## Alternatives rejected

| Alternative | Why not |
|---|---|
| Keep notes outside the Corpus (state folder or a register) | They would be unsearchable and not in the edition; the owner needs to read, review and cite an answer's question and context in one place, and the state folder is never committed. |
| A note as a register (`notes.csv`) | A new register is a breaking column set for long text, loses Markdown and the scans' file model, and Excel round trips damage it. |
| Hold the type back until R2 and the migrate verb | The saved answer is the Day-30 Handoff outcome; a one-line stamp is cheaper than a second release path. |
| Bump to 2 now and require every Corpus to move | Forces a stamp on a Corpus that holds no note; the tool reads both and the stamp can wait for the first note. |
| Let a reviewed note be citable or become `stable` | Review of an answer is not verification of its claims; GS-02 and HG-06 keep a person's certification on claims, not on text from a model. |
| A hand-written note (`origin = "owner"`) | It is a page; a second origin adds a vocabulary value with no trigger. |
| Reserve the id form `<area>-note-<nnn>` against other page types | It tightens an id form that version 1 allows and AD-10 freezes, which makes the change breaking and needs a refusing migration, for no gain: the allocator skips a held number. |
| Delete a wrong note once it is on `main`, and allow its number to be issued again | It breaks "never reused" and the allocator's count; a withdrawn file costs a few bytes. |
| Retire a note with `superseded_by` and a Change note | It gives a note page-graph fields and parts that assume reviewed content. |
| A note in a company store as a page | Labels and ids there are the record store's; ADR 0004 gives it records. |
| Let a note carry optional page fields | They open a path into prerequisite graphs, volatility and supersession, all of which assume reviewed content. |

## Reopen trigger

A change to this format is a new ADR that amends or supersedes this one and raises `schema_version`. Any of these fires it: a second note `origin` is needed, the same workaround for notes appears in three content pull requests, a company store needs a note page rather than a record, or a dependency change leaves the format unreadable.
